# 水下后处理实现计划书

> 状态：**计划 / 待评审**
>
> 目标：为 GE 引擎加入「相机入水后的全屏水下视效」——水雾 / 深度吸收 / 色彩渐变、水下场景焦散、以及水面上下观察的一致化。它区别于 `水面渲染计划书.md` 里的「水面材质本身」：本方案处理的是**相机浸入水介质后，整个画面**的着色。
>
> 前置：
> - `水面渲染计划书.md`：水面已在透明段渲染，HDR 变体输出到 `Scene_HDR`；折射 / 深度吸收 / 岸线泡沫已落地（阶段 2）
> - `HDR中间缓冲实现计划书.md`：`Scene_HDR`（RGBA16F，alpha 为天空/几何哨兵）、`Scene_HDR_Base`、`SceneDepth`（R32 不透明场景深度快照）已可用
> - 现有片元侧判定：`water_hdr.frag` 用 `gl_FrontFacing` 区分水上/水下看面（相机在水面下方时水面片元为背面）
> - 现有视空间重建工具链：`water_hdr.frag` 已实现 `invProj × SceneDepth → 场景视空间/世界位置` 的完整链路，可直接复用
>
> 关联：`水面渲染计划书.md`、`HDR中间缓冲实现计划书.md`、`延迟渲染实现计划书.md`、`透明物体渲染计划书.md`

## 1. 目标与范围

### 1.1 本方案要达成的能力

| 能力 | v1（本计划主体） | v2（可选增强） |
|---|---|---|
| 入水判定 | CPU 每帧：相机视点 vs 水体范围 + Gerstner 波面高度，输出**连续淹没量 0~1** | 多水体嵌套取深者（v1 即 max） |
| 水下介质 | 全屏水雾 + 深度吸收（向该水体 DeepColor 渐变）+ 轻度去饱和/暗角 | 光密度随深度非线性曲线、体积散射 |
| 焦散 | 两段式：水面 shader 内（水上俯视）+ UnderwaterFX 全屏投影（水下仰视场景） | 真焦散 / 光柱（god rays） |
| 一致性 | 现有「从水下往上看水面半透明看穿 / 不实心」保持不变，与全屏雾正确叠加 | 水上水下 FOV/畸变差异 |
| 编辑 | 参数并入 WaterComponent + Inspector + 序列化；渲染器总开关 | 场景级全局水下设置块 |
| 音频 | 不接管（本方案只出淹没量，音频消费见 §7 预留） | 水声低通/混响切换 |

### 1.2 明确不做

- **不做真光线追踪焦散**：引擎目前无 compute pass、无曲面细分，焦散走「水面微法线调制（折射路径）+ 程序化滚动贴图投影（全屏路径）」，不引入新渲染后端。
- **不新增反射路径**：水下向上看天空仍走现有 `water_hdr.frag` 的 Snell 窗口透射天空（全内反射区由片元 alpha 自然淡化），本方案只负责"水面之上"剩余画面的介质着色。
- **不改变透明段语义 / 不引入 OIT**：UnderwaterFX 是一个读 `Scene_HDR`、写独立中间纹理的全屏后处理 pass，叠加在现有 Blend 链之上，不动水面网格与排序。

## 2. 现状盘点：为什么现在水下观感不足

| 层 | 现状 | 缺口 |
|---|---|---|
| **水面材质** | `water_hdr.frag` 已按 `gl_FrontFacing` 区分水面上下两侧：水上取镜面反射，水下取 Snell 窗口透射天空 + 低 alpha"水膜"（`water_hdr.frag:101-104, 259-264`） | 这只是"水面这张膜"的表现；**水膜之外**的水下空间（地板、物体、远处的几何）没有任何介质着色 |
| **相机状态** | 渲染器 `BeginScene` 存有 `m_ViewPos`（真正渲染相机的世界位置，Renderer3D.cpp:53），`m_WaterTime` 每帧刷新（Renderer3D.cpp:63）；水批次 `m_WaterBatches` 含波形/尺寸/色参（WaterBatch，Renderer3D.h:673） | **没有"相机是否入水 / 淹了多深"的全局量**。片元级 `!gl_FrontFacing` 只在有水面片元的地方成立，不能驱动全屏效果 |
| **中间资源** | 不透明场景颜色快照 `Scene_HDR_Base`、深度快照 `SceneDepth`（R32）已为水面折射存在（SceneLayer.cpp:392-422），Transparent 读这两张传给水面（SceneLayer.cpp:431-434） | 这两张是可复用的现成输入，但当前没有**读 `Scene_HDR` 做整屏后处理**的 pass 插槽 |
| **pass 拓扑** | 延迟链 `Transparent → Bloom（可选）→ Tonemap`；Bloom 开启时已经用"独立合成缓冲 + 重定向 `hHDRFinal`"规避自读自写（SceneLayer.cpp:459-497） | 没有 UnderwaterFX 插槽；但 Bloom 的"插入独立缓冲 + 重定向下游"正是本方案要复用的模式 |
| **编辑器** | WaterComponent Inspector 已可调全部水面参数（`SceneHierarchyPanel_Components.cpp:390`） | 无水下相关参数（雾密度、焦散开关/强度） |

**结论**：水面材质已经把"水面这张界面"画对了，但**相机进入水体后，眼睛与画面之间还有一整个水介质**——全屏雾、深度吸收、以及本该洒在场景表面上的焦散都缺失。底层资源（`Scene_HDR` + `SceneDepth` + 波面参数 + 渲染相机位置）全部就绪，只差一个**全屏后处理 pass + 一个 CPU 入水判定**把它们接起来。

## 3. 核心决策

### 3.1 决策一：入水判定输出「连续淹没量 0~1」，不做 bool

- 波面动态起伏，布尔会在浪里/切换瞬间忽闪。判定结果是一个 `submersion ∈ [0,1]`：>0 才累计水下效果，且数值驱动雾/焦散的强度渐变。
- 判定主体（§4.1）逐帧对每个 `WaterBatch` 求相机相对波面的淹深，取 `max`（相机被最深水体包围效果最重）。
- CPU 每帧先算目标值，再对上一帧值做指数平滑（`amount = lerp(amount, target, 1-exp(-k·dt))`），出水/入水不弹跳。

### 3.2 决策二：波面高度判定与顶点着色器同式、在世界 XZ 上算

- `water.vert` 的 Gerstner 累加在 `p = model*pos` 之后进行，`dot(D, p.xz)` 用的是**世界坐标**（water.vert:46,66）。所以 CPU 复刻时**不要先把相机转进水面本地系**，直接用世界 `viewPos.xz` 与同式波参求面高，才能与可见波峰/波谷对齐。
- 只累加 `p.y -= amplitude·sin(2π/λ·dot(D,xz) − 2π/λ·speed·t)`（water.vert:72），其余 x/z 位移分量与高度无关可跳过。
- 前提约束：水面按水平放置建模（`Height` 即世界 Y 平移）。若允许旋转水面，波域定义本身不自洽——v1 维持水平。

### 3.3 决策三：两个入口——「水面片元」与「全屏介质」职责分离

| 观察位 | 谁负责 | 内容 |
|---|---|---|
| 相机在水上、俯视水底 | 水面 shader（折射分支） | 折射采样已见水底 → 叠加**段 A 焦散调制**（§5.2） |
| 相机在水下 | UnderwaterFX 全屏 pass | 全屏水雾 + 深度吸收 + **段 B 焦散投影**（§5.3） |

水面片元（`water_hdr.frag`）只处理"界面"；UnderwaterFX 只处理"介质"。两者用 §4 的淹没量衔接，不互相改写。

### 3.4 决策四：UnderwaterFX 插在 Transparent 后、Bloom 前，写独立缓冲并重定向下游

- 读 `Scene_HDR`（此时已含不透明 + 透明 + 水面，线性 HDR）与 `SceneDepth`（R32），写一张新的 `Underwater_HDR`；Bloom/Tonemap 的读取源改指向它。**完全复用 Bloom 开启时的"独立缓冲 + 重定向 `hHDRFinal`"模式**（SceneLayer.cpp:459-497），不引入任何自读自写。
- 必须**原样透传 alpha**（`Scene_HDR.a` 是天空/几何哨兵，Bloom 按它排除天空、Tonemap 按它直出天空，水面透明段已按 `eOneMinusSrcAlpha` 自适应收敛）：UnderwaterFX 只改 rgb，`out.a = in.a`。
- 插入后（带水面场景）：

```
ShadowMap_C* → GBuffer → Lighting → SceneColorCopy → SceneDepthCopy
    → Transparent(含水面) → UnderwaterFX → Bloom → Tonemap → Scene2D
```

- 无水面 / 淹没量为 0 / 总开关关时：**不声明该 pass**，Bloom/Tonemap 直接读 `Scene_HDR`（现状零变化）。与 Bloom 的"存在时才插入"策略一致。

### 3.5 决策五：焦散分层——折射侧用「水微法线 + 滚动贴图」，全屏侧用「程序化滚动投影」

- **段 A（水上俯视）**：透射水底的光受水面微法线聚焦——在 `water_hdr.frag` 折射分支里，透射色乘 `(1 + 焦散系数)`。焦散系数由已算好的水面法线与阳光方向的解析近似 + 一层滚动细网纹理叠加，消除静止感。成本≈0（水面本就逐片元）。
- **段 B（水下看场景）**：水面不在视线路径上，段 A 失效。全屏 pass 用**程序化双层滚动焦散**，按光照方向投影到场景表面：重建世界坐标 → `worldPos.y < 波面` 的几何像素 → 加性叠加亮纹（模拟光线聚焦，不是乘法透射，见 §5.3）。无需额外贴图资产（默认正弦叠加即可看），可选艺术向法线→焦散查找纹理（v2）。

## 4. 判定层：相机淹没量（核心）

### 4.1 CPU 判定函数（新增）

```cpp
// Scene 侧新增（也可放 Renderer3D 内部，见 §4.2）：对每个水面求相机淹深，返回最大淹没量
// 输入与 DrawWater 相同的 wave 数据 + 水面世界 Y + 相机世界位置
float ComputeCameraSubmersion(glm::vec3 viewPos,
                              glm::vec3 planeY,              // 水面世界 Y（Height）
                              glm::vec2 sizeXZ,              // 有界范围（XZ 半宽）
                              const std::array<WaterGerstnerWave, 4> &waves,
                              float time, float timeScale) {
    // ① 有界平面范围（防止湖边低于水位的地面误判入水）
    glm::vec2 local = viewPos.xz - planeXZ;                 // planeXZ = 水面实体世界平移.xz
    if (abs(local.x) > sizeXZ.x * 0.5f || abs(local.y) > sizeXZ.y * 0.5f)
        return 0.0f;
    // ② 相机处波面高度（与 water.vert 同式，世界 XZ，phase 用世界时间）
    float surfaceY = planeY;
    for (int i = 0; i < 4; ++i) {
        const auto &w = waves[i];
        if (w.wavelength <= 0.0f) continue;
        float k = 2.0f * PI / w.wavelength;
        float f = k * dot(normalize(w.direction), viewPos.xz) - k * w.speed * (time * timeScale);
        surfaceY -= w.amplitude * sin(f);
    }
    // ③ 深度 = 面高 − 相机高 → 连续淹没量
    float depth = surfaceY - viewPos.y;                     // >0 才入水
    return clamp(depth / kSubmersionBand, 0.0f, 1.0f);      // kSubmersionBand ≈ 0.5m 过渡带
}
```

- 波参直接复用 `WaterBatch`（Renderer3D.h:673）——渲染器已持有（`Scene::RenderMeshes3D` 的 waterView 已把组件拷贝进批次，Scene.cpp:1410-1418）。判定的波参集合与绘制用的是同一份，天然一致。
- **若不想在 v1 复刻 Gerstner**：`surfaceY` 先用 `planeY`（纯平面）。入水瞬间比波面最多早/晚半个波幅，视觉无感；把步骤 ② 整体换成上面的累加即升级，调用点不动（§7 阶段 0 → 阶段 1）。

### 4.2 状态存放与每帧流水

- Renderer3D 新增按帧状态（对照 `m_WaterTime` 的做法，Renderer3D.h:1149）：
  ```cpp
  float m_WaterSubmersion = 0.0f;   // 平滑后淹没量 0..1
  float m_WaterPlaneY = 0.0f;       // 被淹没水体波面 Y（UnderwaterFX 段 B 用它判水下几何）
  float m_WaterAbsorption = 2.0f;   // 被淹没水体吸收深度（可让雾色弱化）
  // 从产生 max 淹没量的那个 WaterBatch 摘 DeepColor 作雾色，跨水体色彩只取最深者
  glm::vec3 m_WaterDeepColor{0.012f, 0.055f, 0.09f};
  ```
- **每帧更新点**：`FlushTransparent` 的 `DrawWaterBatches` 末尾（Renderer3D_Record.cpp:469）——此时 `m_WaterBatches`、`m_ViewPos`、`m_WaterTime` 都已就位，算完存下，UnderwaterFX 的 execute 直接读。`EndScene` 不清，跨帧指数平滑依赖旧值。
- **音频消费**（预留，不接）：把同一 `m_WaterSubmersion` 暴露只读接口，AudioWorld 按需读取做水声切换。

### 4.3 无水面 / 编辑器相机的降级

- 无水面批次：淹没量恒 0 → UnderwaterFX 不声明（§3.4），全链零变化。
- Edit 态 EditorCamera 与 Play 态主玩法相机都从同一 `viewPos`（`Scene::RenderMeshes3D` 的形参）流入判定，编辑器里把相机压低进湖一样能看到水下视效——无需额外分支。

## 5. 渲染层

### 5.1 UnderwaterFX pass 声明（SceneLayer，紧跟 Transparent）

### 5.2 UnderwaterUBO（std140，新增，仿 WaterUBO 布局）

```cpp
struct UnderwaterUBO {
    glm::mat4 invProj;        ///< SceneDepth → 视空间重建
    glm::vec4 params;         ///< x=submersion(0..1), y=fogDensity(每米), z=desaturate, w=暗角
    glm::vec4 deepColor;      ///< 水雾色（取自被淹没水体 DeepColor）
    glm::vec4 caustics;       ///< x=causticsStrength, y=causticsScale(UV 平铺), z=enable, w=时光滑
    glm::vec4 sunDir;         ///< 段 B 焦散投影方向(世界)xyz
    glm::vec4 waterPlane;     ///< x=planeY(判水下几何), yzw=留空
    glm::vec4 timeParams;     ///< x=time(滚动), y=dt
    glm::vec4 viewPos;        ///< 相机世界位置（可选，或从 FrameUBO 取）
};
static_assert(sizeof(UnderwaterUBO) % 16 == 0, "UnderwaterUBO 必须 16 字节对齐");
```

- `FlushUnderwaterFX`：填 UBO（读 §4.2 状态），绑定 `Scene_HDR`→b1、`SceneDepth`→b2（最近邻）、（可选焦散贴图）→b3，画 3 顶点全屏三角形。淹没量 ≈ 0 时 shader 直接 return，成本仅一次采样。

### 5.3 `underwater.frag` 伪代码

```glsl
void main() {
    float sm = waterFx.params.x;              // 淹没量
    if (sm <= 0.001) { outFrag = vec4(texColor.rgb, texColor.a); return; }

    vec3 sceneCol = texture(samplerSceneColor, uv).rgb;
    float sceneRaw = texture(samplerSceneDepth, uv).r;    // 最近邻采样
    vec4 ndc = vec4(uv*2.0 - 1.0, sceneRaw, 1.0);
    vec4 viewP = waterFx.invProj * ndc;
    vec3 viewPos3 = viewP.xyz / max(abs(viewP.w), 1e-6);
    float dist = -viewPos3.z;                             // 场景距离（米）

    // —— 介质：深度水雾 + 向 DeepColor 吸收 ——（几何哨兵 gating 见 §5.4）
    float fog = 1.0 - exp(-waterFx.params.y * dist);       // 距离衰减
    vec3 col = mix(sceneCol, waterFx.deepColor.rgb, fog * sm);

    // 轻度去饱和 / 暗角（sm 越深越重）
    float lum = dot(col, vec3(0.299, 0.587, 0.114));
    col = mix(col, vec3(lum), waterFx.params.z * sm);
    col *= 1.0 - waterFx.params.w * sm * smoothstep(0.1, 0.9, length(uv - 0.5));

    // —— 段 B 焦散（加性，只对水下几何生效）——
    // 几何哨兵：alpha≥0.5（Scene_HDR 元数据）才是真实几何；天空不叠焦散
    if (waterFx.caustics.z > 0.5 && sceneIsGeometry) {
        vec3 worldPos = /* SceneDepth 重建世界坐标（复用 water_hdr.frag:215 链路） */;
        if (worldPos.y < waterFx.waterPlane.x - 0.05) {    // 只加在波面以下
            vec2 cUv = worldPos.xz * waterFx.caustics.y;   // 按光方向投影（v1 简化取 xz）
            cUv -= waterFx.sunDir.xz * waterFx.timeParams.x * 0.3;  // 顺光漂移
            float c = ProceduralCaustics(cUv, waterFx.timeParams.x); // 双层滚动正弦网
            col += c * waterFx.deepColor.rgb * waterFx.caustics.x * sm;
        }
    }

    outFrag = vec4(col, srcAlpha);    // alpha 原样透传（天空/几何哨兵不变）
}
```

> 程序化焦散（默认，无需资产）：两套不同频率/速度的正弦场叠加再取 `pow(smoothstep(...), N)` 锐化成"光斑"，是经典便宜方案；替换成采样滚动焦散贴图（v2）只改一个采样函数。
>
> **加法而非乘法**：相机在水下时水面不在视线路径，场景表面是直接被照亮、被水雾吸收的（§3.3），焦散是"额外光"，用加性叠加近似光照；乘法则错误地近似"透射率"。

### 5.4 哨兵语义与 sky 保护

- `Scene_HDR.a`：天空=0、几何/透明合成=1（HDR 计划书 §5.3）。UnderwaterFX **必须保留 alpha** 直传，否则 Bloom 把天空当几何放大、Tonemap 不再直出天空。
- **水下向上看的天空**：该区像素经水面片元混合后 alpha 接近 0（水面低 alpha 膜 + `eOneMinusSrcAlpha` 自适应，water_hdr.frag:259-267）→ 视为"天空/介质"：**只做介质雾，不叠焦散**（天空没有可投影的几何表面）。
- 判断几何：`srcAlpha >= 0.5` 用几何雾+焦散；`< 0.5` 用介质雾但不叠焦散。阈值需要按实际 alpha 收敛微调，作为 §8 风险列出。

### 5.5 段 A 焦散（水上俯视，改水面 shader）

在 `water_hdr.frag` 折射分支（water_hdr.frag:191-235）里，对透射色加调制：

```glsl
// 透射光被水面微法线聚焦 → 水底更亮；N 已是波+细节合成法线
float caustic = 1.0 + kCausticStrength * smoothstep(0.0, 1.0, dot(N, L_阳光) );
// + 一层滚动细网纹乘(1..2)消除静止感；只对真正水下内容(underwaterContent)生效
transmitted *= caustic;            // 或 transmitted += causticGlow * waterBody * underwaterContent
```

- 复用已算好的 `N`（water_hdr.frag:93）与方向光 `L`，不新增采样；法线细节经滚动 UV 时天然带动光斑运动。成本≈0。
- 效果边界：段 A 只增强"水底透射画面"，不产生场景表面投影（那是段 B）。水下相机时段 A 失效（该分支 `!underwater` 才走）。

## 6. 与水面 / 透明链的合成语义

| 场景 | 行为 |
|---|---|
| 水上俯视水底 | 水面 shader 折射分支正常（现有）；段 A 焦散调制透射色 |
| 相机刚入水（浅，sm<0.3） | UnderwaterFX 全屏轻雾叠加；焦散弱；水面膜保持看穿——两特效用 sm 渐变衔接，无硬切 |
| 相机深潜 | 全屏雾向 DeepColor 收束 + 去饱和 + 暗角；段 B 焦散在场景表面亮起 |
| 相机出水的瞬间 | 平滑后 sm 回落，效果淡出；水面片元切回水上分支（gl_FrontFacing） |
| 无水面 / 关闭开关 | UnderwaterFX 不声明，`Scene_HDR` 直通 Bloom/Tonemap，视觉零变化 |

- **顺序确定性**：UnderwaterFX 读到的 `Scene_HDR` 已经含水面（Transparent 先画）。因此"水面那张膜"与其后方的"介质雾"是两次独立合成——膜本身不会被雾二次吃掉 alpha，但会被雾染色（rgb 被 mix）。这与"透过水下看远处水面更浑浊"的直觉一致。

## 8. 风险与难点

| 风险 | 影响 | 缓解 |
|---|---|---|
| alpha 哨兵在 UnderwaterFX 里被改写 | Bloom/Tonemap 把水下天空当几何 / 不再直出天空 | 直传 `out.a = in.a`；几何/天空 gating 用 §5.4 阈值，按实际混合收敛微调（含水面低 alpha 膜的叠加结果） |
| 入水判定与可见波面不同步 | 浪尖判定过早、波谷过晚 | §4.2 CPU 同式波累加；v1 先平面高度验收，观感不符再升级 |
| 无水面时 pass 成本 | 白跑一个全屏 pass | 条件声明：无水面/开关关不插入（§3.4） |
| 深水 + 全屏采样带宽 | 移动/低配掉帧 | UnderwaterFX 半分辨率渲染 + 双线性上采样；段 A 零成本不占预算 |
| 焦散投影在陡立表面（河岸/礁石侧面）方向错误 | 光斑沿墙拉伸 | v1 投影简化为 XZ 平面（限制使用场景）；光照方向倾斜投影列 v2 |
| 多水体重叠 | 雾色/波面归属混乱 | 取 max 淹没量的水体整组参数；跨水体颜色混合 v1 不做（§4.2） |

## 9. 验收标准

1. 相机从水上压入水下，画面经 **sm 渐变**过渡到水雾+去饱和+暗角，反向出水平滑淡出，无硬切/闪帧。
2. 水下看湖底/岸礁，段 B 焦散光斑在波面以下的几何上滚动、方向随光顺流；水上俯视水底段 A 焦散增强透射画面。
3. 现有「从水下往上看水面半透明、透出天空/场景」的表现不回归（提交 1409b142 / 2b8094c9 语义保持）。
4. `Scene_HDR.a` 哨兵经 UnderwaterFX 原样直传：Bloom 仍只放大几何、Tonemap 仍直出天空，无不泛光/漂白回归。
5. 场景无水面时画面与关闭后完全一致（零新增 pass）；总开关在编辑器即时生效。
6. 水下参数（FogDensity / Caustics*）入序列化，老 `.scene` 无该字段时按默认值加载。
7. 性能：UnderwaterFX 全屏单 pass 目标 < 0.5 ms（半分辨率 < 0.3 ms）；段 A 水面侧成本可忽略。

## 10. 未来预留（本方案 v1 不做）

- **God rays / 体积光柱**：UnderwaterFX 加性焦散槽位可扩展成阳光光柱（沿 sunDir 的屏幕空间光线步进），读现有 SceneDepth 即可。
- **艺术向焦散资产**：程序化正弦网可整体替换成法线→焦散查找纹理 / 滚动贴图序列，只动一个采样函数。
- **音频联动**：暴露 `m_WaterSubmersion` 只读，AudioWorld 用它切换水声低通/混响；`AudioWorld::SyncListener` 已以主相机实体为 listener 兜底（AudioWorld.cpp:237），可直接取同一淹深来源。
- **水上水下差异观感**：水下 FOV 放大 / 表面扰动全屏化，可作为 UnderwaterFX 的附加 uniform。
- **体积散射 / 悬浮粒子**：需要 compute 或额外贴图，超出 raster-only 范围，独立立项。

## 11. 锁定的衔接点

- `水面渲染计划书.md`：本方案不修改水面网格/材质/排序；只新增一个读 `Scene_HDR` 的全屏 pass，水面 `water_hdr.frag` 仅折射分支加段 A 调制。
- `HDR中间缓冲实现计划书.md` / alpha 哨兵：UnderwaterFX 与 Bloom 同策略插入、透传 alpha，下游语义不变。
- `延迟渲染实现计划书.md`：pass 拓扑沿用 `SceneLayer::RecordScenePasses` 延迟链；Forward 单 pass 路径（`IsDeferred()==false`）不做水下后处理（无 HDR 中间链）。
- `透明物体渲染计划书.md`：水面在透明段末尾绘制不变；UnderwaterFX 在其后合成，不影响透明段混合顺序。
