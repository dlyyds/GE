## 1. 设计理念

### 1.1 核心原则

| 原则 | 说明 |
|------|------|
| **自包含** | 每个 Module 有自己的 Init/Shutdown，生命周期自管 |
| **显式依赖** | Module 通过 ModuleContext 按类型安全地获取其他 Module，不依赖全局单例 |
| **组合优于继承** | 应用入口通过 Register 组合 Module，而不是继承 Application 写死初始化 |
| **事件驱动解耦** | Module 之间不直接调用，通过 EventBus 通信 |
| **对称生命周期** | Init 顺序 = Register 顺序，Shutdown 自动逆序，不会漏资源 |

### 1.2 解决的问题

| 问题 | 方案 |
|------|------|
| Application 承担过多职责 | Application 退化为 Module 容器，不关心任何子系统的细节 |
| 全局单例无处不在 | 每个 Module 的实例由 Application 持有，通过 ModuleContext 类型安全访问 |
| 业务代码集中在"上帝类" | 业务逻辑拆为独立的业务 Module |
| 依赖关系隐式不可控 | ModuleContext::Get\<T\>() 在编译期检查类型，运行时断言存在性 |
| 事件只对特定类开放 | EventBus 允许任何对象订阅事件，用优先级控制顺序 |
| 关停顺序脆弱 | 自动逆序 Shutdown，每步独立，单步失败不影响其他 Module |

## 3. 核心接口

### 3.1 IModule——所有 Module 的基类

```cpp
class ModuleContext;

class IModule {
public:
    virtual ~IModule() = default;

    /// 模块名称（调试 / 日志用）
    virtual const char *GetName() const = 0;

    /// 初始化。在此通过 ctx.Get<T>() 获取依赖的其他 Module。
    /// 保证：所有比本模块先注册的 Module 都已初始化完毕。
    virtual void Init(ModuleContext &ctx) = 0;

    /// 每帧更新。按注册顺序调用。
    virtual void Update(Timestep ts) {}

    /// 关闭。逆序调用。
    /// 保证：所有比本模块后注册的 Module 已经关闭。
    virtual void Shutdown() = 0;
};
```

**设计要点**：
- 只有 4 个虚函数（Init/Update/Shutdown/GetName），最小接口
- 没有 OnEvent——事件通过 EventBus 订阅，任何对象都能收
- 没有 OnImGui——ImGui 面板通过向 ImGuiModule 注册回调实现

### 3.2 ModuleContext——Module 的通信渠道

```cpp
class ModuleContext {
public:
    /// 按类型获取 Module。如果 T 未注册，触发断言。
    template<typename T>
    T &Get();

    /// 检查 Module 是否已注册（用于可选依赖）
    template<typename T>
    bool Has() const;

    /// 获取事件总线
    EventBus &GetEventBus();

private:
    std::unordered_map<std::type_index, IModule*> m_Modules;
    EventBus m_EventBus;

    friend class Application;  // 只有 Application 能注册 Module
};
```

**设计要点**：
- 按 `type_index` 索引，类型安全——`ctx.Get<RenderModule>()` 编译期检查
- 不是 `Get("string_name")`——字符串 key 运行时才知道错了
- `Has<T>()` 用于可选依赖（如"如果启用了 ImGui 则注册面板"）

### 3.3 Application——Module 容器

```cpp
class Application {
public:
    /// 注册一个 Module——按注册顺序 Init，逆序 Shutdown
    template<typename T, typename... Args>
    T &Register(Args &&... args) {
        auto module = std::make_unique<T>(std::forward<Args>(args)...);
        auto *ptr = module.get();

        m_Context.m_Modules[typeid(T)] = ptr;
        ptr->Init(m_Context);
        m_Modules.push_back(std::move(module));

        return *ptr;
    }

    void Run();
    void Close();

    ModuleContext &GetContext();
    template<typename T> T &GetModule();
    template<typename T> bool HasModule();

private:
    std::vector<std::unique_ptr<IModule>> m_Modules;
    ModuleContext m_Context;
    bool m_Running = true;
    float m_LastFrameTime = 0.0f;
};
```

**设计要点**：
- Register 做了三件事：创建 → 注册到 Context → Init（顺序安全）
- Application 不知道任何子系统的细节，只做"注册"和"运行"
- 销毁时逆序 Shutdown，不会漏资源

## 4. 主循环

### 4.1 框架

```cpp
void Application::Run() {
    while (m_Running) {
        Timestep ts = CalcDeltaTime();

        // 所有 Module 按注册顺序执行 Update
        for (auto &m : m_Modules) {
            m->Update(ts);
        }

        // 帧结束（如 Vulkan Present）
        EndFrame();
    }
}
```

### 4.2 典型帧时序

```
Frame N:
  │
  ├─ Module::Update 按注册顺序执行
  │     │
  │     ├─ WindowModule::Update    ← 事件轮询（glfwPollEvents）
  │     │     │                       → EventBus::Emit → handler
  │     │     ├─ ImGui handler     (priority 100)
  │     │     ├─ Engine handler    (priority 10)
  │     │     └─ Game handler      (priority -100)
  │     │
  │     ├─ VulkanModule::Update   ← BeginFrame（acquire image）
  │     │
  │     ├─ GameModule::Update     ← 游戏逻辑 + 渲染
  │     │     └─ RenderScene()
  │     │         ├─ BeginScene(...)
  │     │         ├─ Draw(...)
  │     │         └─ EndScene()
  │     │
  │     └─ ImGuiModule::Update    ← ImGui 渲染
  │           ├─ BeginFrame()     ← ImGui_NewFrame
  │           ├─ 遍历所有面板回调  ← 各 Module 注册的面板
  │           └─ EndFrame(sw,cmd) ← ImGui::Render + 提交
  │
  └─ EndFrame (Vulkan Present)
```

**引入新 Module 时只需要关注两件事**：
1. 它的 `Init` 中需要哪些其他 Module（通过 `ctx.Get<T>()`）
2. 它的 `Update` 在这个时序中应该在哪个阶段执行（通过注册顺序保证）

## 5. EventBus 事件系统

### 5.1 设计

```
 事件源                       EventBus                       消费者
─────────                    ────────                       ────────
WindowModule::               m_Handlers                    GameModule::Init()
  KeyCallback()               ├── KeyPressed: [ ]            ctx.GetEventBus()
    └── Emit<KeyPressed>      │   ├─ {cb, prio=100}           .Subscribe<KeyPressed>(
                               │   ├─ {cb, prio=0}              [this](auto &e) {
                               │   └─ {cb, prio=-100}              ...
                               │                              }, priority = 0
                               ├── MouseMoved: [ ]            );
                               └── Resize: [ ]
```

### 5.2 接口

```cpp
class EventBus {
public:
    /// 订阅事件 T。handler 返回 true = 消费事件（停止传播）
    /// priority 越高越先执行
    template<typename T>
    void Subscribe(std::function<bool(T &)> handler, int priority = 0);

    template<typename T>
    void Unsubscribe();

    /// 阻塞发布——立即执行所有 handler
    template<typename T>
    void Publish(T &event);

    /// 构造并发布
    template<typename T, typename... Args>
    void Emit(Args &&... args);

    /// 入队（延迟处理模式）
    template<typename T>
    void Queue(T event);

    /// 处理队列中所有事件
    void Flush();

    void Clear();

private:
    struct Entry {
        std::function<bool(Event &)> callback;
        int priority;
    };
    std::map<std::type_index, std::vector<Entry>> m_Handlers;
    std::vector<std::shared_ptr<Event>> m_Queue;
};
```

### 5.3 优先级约定

| 优先级 | 用途 | 示例 |
|--------|------|------|
| 100 | ImGui 事件拦截 | ImGui::WantCaptureMouse |
| 10 | 引擎基础设施 | Swapchain Resize |
| 0 | 默认 | 普通逻辑 |
| -10 ~ -100 | 业务逻辑 | 游戏输入响应 |

### 5.4 阻塞 vs 延迟

```
阻塞模式（默认）：
  GLFW callback → EventBus::Emit → 立即执行 handler
  优点：延迟最低
  缺点：在回调中执行用户代码

延迟模式（可选）：
  GLFW callback → EventBus::Queue → 缓冲
  Flush() 阶段 → 统一处理
  优点：处理时机可控，适合物理/输入同步
```

### 5.5 使用示例

```cpp
// 订阅事件
ctx.GetEventBus().Subscribe<MouseMovedEvent>(
    [this](MouseMovedEvent &e) -> bool {
        m_Camera.Rotate(e.dx, e.dy);
        return false;  // 不消费，继续传播
    },
    priority = 0
);

// 发布事件
bus.Emit<WindowResizeEvent>(1920, 1080);
```

## 6. ImGui 系统

### 6.1 设计

ImGuiModule 统一管理 ImGui 的生命周期，其他 Module 不直接接触 ImGui 的 Begin/End。

```
         其他 Module                    ImGuiModule
        ────────────                  ──────────────
GameModule::Init()                   Update(ts)
  ctx.Get<ImGuiModule>()               ├─ BeginFrame()
    .RegisterPanel(                     │   ├─ ImGui_NewFrame()
      [this]() {                        │   └─ ... platform backends
        ImGui::Begin("面板");           │
        ...                              ├─ for (auto &panel : m_Panels)
        ImGui::End();                    │   └─ panel.callback()
      },                                │       → GameModule 的面板
      "GamePanel",                      │       → Engine 的面板
      priority = 0                      │       → ...
    );                                  │
                                       └─ EndFrame(swapchain, cmd)
                                           ├─ ImGui::Render()
                                           └─ ImGui_ImplVulkan_RenderDrawData()
```

### 6.2 接口

```cpp
class ImGuiModule : public IModule {
public:
    /// 注册一个面板回调。EndFrame 时按 priority 顺序调用。
    void RegisterPanel(std::function<void()> callback,
                       const std::string &name,
                       int priority = 0);

    void UnregisterPanel(const std::string &name);

    void Init(ModuleContext &ctx) override;
    void Update(Timestep ts) override;
    void Shutdown() override;

private:
    struct PanelEntry {
        std::function<void()> callback;
        std::string name;
        int priority;
    };
    std::vector<PanelEntry> m_Panels;
};
```

### 6.3 其他 Module 如何添加面板

```cpp
void GameModule::Init(ModuleContext &ctx) {
    // ... 初始化游戏逻辑 ...

    // 注册 ImGui 面板
    ctx.Get<ImGuiModule>().RegisterPanel(
        [this]() {
            ImGui::Begin("Debug Panel");
            ImGui::Text("FPS: %.1f", GetFPS());
            ImGui::SliderFloat("Value", &m_Value, 0, 100);
            ImGui::End();
        },
        "DebugPanel",
        priority = 0
    );
}
```

**不需要**：
- 实现 `OnImGui()` 虚函数
- 手动调用 `BeginFrame/EndFrame`
- 保存 ImGuiModule 的引用

### 6.4 事件拦截

ImGuiModule 在 Init 中注册高优先级事件 handler，自动拦截 ImGui 想消费的输入：

```
EventBus 分发顺序：
  1. ImGuiModule handler (priority=100)   ← 如果 ImGui 想捕获，return true
  2. Engine handler (priority=10)
  3. Game handler (priority=-100)         ← 只有 ImGui 没消费时才会收到
```

## 7. 应用入口

### 7.1 引擎核心

一组稳定的基础设施 Module，多个应用入口共用：

| Module | 职责 | 依赖 |
|--------|------|------|
| LogModule | 日志系统初始化 | 无 |
| WindowModule | 窗口创建 + 输入事件 → EventBus | LogModule |
| GraphicsModule | 图形 API 上下文（设备/交换链） | WindowModule |
| ResourceModule | 纹理/模型缓存 | GraphicsModule |
| RenderModule | 渲染器封装 | GraphicsModule |
| ImGuiModule | ImGui 生命周期 + 面板管理 | GraphicsModule, WindowModule |

### 7.2 入口写法

```cpp
// main.cpp
int main() {
    Application app;

    // 引擎基础设施
    app.Register<LogModule>();
    app.Register<WindowModule>();
    app.Register<GraphicsModule>();
    app.Register<ResourceModule>();
    app.Register<RenderModule>();
    app.Register<ImGuiModule>();

    // 业务层（应用特有）
    app.Register<GameModule>();

    app.Run();
}
```

**注册顺序 = 依赖顺序**：
- 基础模块先注册（Log → Window → Graphics）
- 依赖基础模块的后注册（Render → ImGui → Game）
- Shutdown 自动逆序（Game → ImGui → Render → ... → Log）

## 8. 附录

### 8.1 新 Module 开发检查清单

1. 继承 `IModule`，实现 `GetName / Init / Shutdown`
2. 在 `Init` 中通过 `ctx.Get<T>()` 获取依赖
3. 需要每帧逻辑则实现 `Update`
4. 需要 ImGui 面板则在 `Init` 中 `RegisterPanel`
5. 需要收事件则在 `Init` 中 `Subscribe`
6. 在 `main.cpp` 中 `Register`

### 8.2 常见问题

**Q：Module 之间如何通信？**  
A：通过 `ctx.Get<T>()` 获取对方实例后调用公开方法，或通过 EventBus 发布事件。

**Q：一个 Module 的 Init 中能访问其他 Module 吗？**  
A：能。`Register` 保证所有比它先注册的 Module 已经 Init 完成。

**Q：Update 的执行顺序怎么控制？**  
A：注册顺序就是 Update 的执行顺序。基础 Module 先注册先执行。

**Q：如何做一个可选 Module？**  
A：在 Init 中用 `ctx.Has<T>()` 检查是否存在，不要用 `Get<T>()`。
