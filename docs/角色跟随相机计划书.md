# 角色跟随相机（第三人称 FollowCamera）计划书

> 状态：**计划中（未开工）**。前置已完成：编辑器/运行时物理分离（`编辑运行时物理分离计划书.md` 阶段 A/B）已落地——Play/Stop 双态、StepPhysics 门控、Transform 快照回滚；角色控制器 CharacterVirtual 已落地（`角色控制器CharacterVirtual计划书.md`）——`character.*` 脚本 API、`CharacterControllerComponent`（含面朝逻辑 FacingYaw/BaseRotation）；Orbit 相机已具备"瞄准点 + 球坐标 + lookAt"的天然第三人称几何。
> 目标：给角色一整套"跟随"相机——Play 时镜头钉在角色身上走、鼠标环绕视角/滚轮距离、（按需）背后朝向镜头；并且把这份能力与编辑器现有导航相机之间的**所有冲突**逐条摆清楚、给出收敛方案。这是 `编辑运行时物理分离计划书.md` 路线图里"运行时与编辑器相机分离"一格的承接落地。
> 定位：只加一枚 `CameraFollowComponent` + Scene 一处每帧驱动 +（可选）`Camera::Mode::ThirdPerson`；不改渲染 / 不动 `CameraComponent.Primary` 语义 / 不影响编辑态导航。

---

## 0. 一句话架构

```
Scene::UpdateCameraFollow()（每渲染帧，UpdateWorldTransforms 之后调用）
  ├─ 解析跟随目标：CameraFollowComponent.TargetUUID → 实体（加载后稳定解析）
  ├─ 读目标世界位置 → CameraInstance.SetTarget(pos + up × HeightOffset)
  │      └─ Orbit 相机自动变成"跟随相机"：位置 = Target + 球坐标，lookAt(Target)
  └─ 可选 FollowYaw：背后镜头（需要 Camera::Mode::ThirdPerson 的"基准朝向 + 鼠标偏移"模型）

输入：沿用现链路 悬停视口 → SetProcessCameraInput(true) → DispatchInputEventToCamera
      → CameraInstance.OnEvent（左键环绕 / 滚轮距离；跟随态禁用右键 pan）
```

**关键约束**：不改渲染、不改 `Scene::OnUpdate3D` 的既有步骤顺序之外的东西、不新增第二台"只属于玩家"的相机实体（v1 复用主相机）。冲突收敛（§2）是主线任务，功能其次。

## 1. 现状盘点：现有相机系统到底是如何工作的

| 环节 | 现状（代码依据） | 对跟随相机的意义 |
|---|---|---|
| Orbit 视图几何 | `Camera::GetView()`（Camera.cpp:49-62）：相机位置 = `m_Target + 球坐标(m_Theta, m_Phi, m_Distance)`，`lookAt(m_Target)` | **已经是第三人称几何**：加跟随 = 每帧把 Target 钉在角色上，位置自动跟随 |
| 鼠标输入 | `Camera::OnMouseMove`（Camera.cpp:122-149）：左键拖 = 改 theta/phi（环绕），右键拖 = 平移 Target（pan） | 左键环绕、滚轮距离可直接复用；右键 pan 在跟随态会与逐帧 SetTarget 打架（§2.3） |
| 滚轮 | `Camera::OnScroll`（Camera.cpp:151-158）：改 `m_Distance`，clamp [MinDistance, MaxDistance] | 直接复用，即"跟拍距离" |
| 输入路由 | `SceneLayer::OnEvent`：悬停视口且非拖 gizmo → `SetProcessCameraInput(true)`；`Scene::OnEvent` → `DispatchInputEventToCamera` → 主相机 `CameraInstance.OnEvent`（Scene.cpp） | Play 时 gizmo 已隐藏，悬停视口即喂鼠标给相机 → **鼠标环绕免费获得** |
| 相机实体 | `SceneLayer::OnUpdate` 用 `m_Context->CameraEntity`（加载后 = `GetPrimaryCameraEntity()`，即第一个 `Primary==true` 的相机） | v1 复用主相机实体，`m_Context->CameraEntity` 无需改 |
| 角色位置 | `PhysicsWorld::SyncCharacterTransformsToComponents` 每子步把 CharacterVirtual 位姿写回 `TransformComponent`；`UpdateWorldTransforms` 每帧重算 world | 读目标的**世界矩阵平移列**即可，需在 `UpdateWorldTransforms` 之后读（§2.5） |
| 面朝 | `CharacterControllerComponent.FacingYaw`（弧度，Components.h:627）+ `BaseRotation`（含转正倾斜）+ `FaceMovement/TurnSpeed/FrontAxis` | 背后镜头要"角色朝哪、镜头就在背后"，朝向来源见 §2.4 |

**结论**：Orbit 相机 = 一个"瞄准点 + 环绕 + 缩放"的现成第三人称相机。加"挂在角色身上"本质只有一行：每帧 `SetTarget(角色世界位置 + 增高)`。真正的复杂度全部在"和编辑器相机的冲突"上。

## 2. 与现有相机的冲突清单（主线，逐条收敛）

### 2.1 相机角色冲突：同一个实体既是"编辑器导航相机"又是"玩家跟随相机"

- **现状**：编辑器里主相机 = Orbit 导航相机（自由绕场景转、pan、缩放），`Edit/Play 分离计划书` 决策"Play 沿用编辑器相机路径"。
- **冲突**：若不加区分地让相机跟随角色，编辑态就没法用相机逛场景；若完全不跟随，Play 就没有"游戏视角"。
- **收敛**：`CameraFollowComponent` 挂在相机实体上，且行为按 `Scene::IsPlaying()` 门控——**Edit 态完全不做任何事，相机保持编辑器导航语义；Play 态接管 Target**。另留 `EnableInEdit` 逃生阀（想编辑时预览跟随效果可用）。
- **层面**：这与物理门控同哲学（Edit 静止、Play 模拟），对用户心智一致。

### 2.2 Target 归属冲突：`m_Target` 被双写

- **现状**：`Camera::m_Target` 是相机的内部状态，编辑器相机的平移/环绕都直接改它。
- **冲突**：跟随组件每帧 `SetTarget(角色位)`，而右键 pan 或脚本也会改 `m_Target`（§2.3），两写手打架，结果依帧序漂移。
- **收敛**：明确"谁在 Play 拥有 Target"——**Play 态下 Target 的唯一写手是 `UpdateCameraFollow`**；编辑态才是用户/编辑器拥有。数据流单向：`角色世界位 → SetTarget`，不再反向读它当依据。

### 2.3 右键 pan 冲突：跟随态平移 Target 无意义且反直觉

- **现状**：Orbit 右键拖 = 平移 Target（Camera.cpp OnMouseMove else 分支）。
- **冲突**：Play 态下用户右键平移的 Target，下一帧就被 `UpdateCameraFollow` 覆盖回角色身上——操作无效还造成"相机抖一下/不受控"的困惑（和"动态体上拖 gizmo"是同类问题，编辑运行时计划已在 gizmo 上处理过）。
- **收敛**：跟随态（FollowCamera 生效）下**禁用右键 pan**。做法取舍：
  - v1（推荐）：`CameraFollowComponent` 生效时在 SceneLayer/Scene 事件路由处把右键拖的 pan 语义短路（最省事，但把"了解相机内部"泄漏到上层）；
  - v2（干净）：`Camera` 增加 `SetPanEnabled(bool)`，OnMouseMove 的 else 分支据它短路（相机自管自己的交互，推荐长期）。

### 2.4 朝向冲突：`m_Theta` 是绝对制，直接覆盖会吞掉鼠标视角

- **现状**：Orbit 的 `m_Theta` 是绝对角度；鼠标左键拖直接改它。
- **冲突**：若"背后镜头"每帧 `SetOrbit(角色朝向, ...)`，则用户鼠标刚绕出来的视角偏移被立即覆盖回角色背后——"镜头跟着角色转"与"鼠标自由环绕"互相冲突。
- **收敛（拆成两种模式，按需选）**：
  - **自由环绕（v1，零冲突）**：只 `SetTarget`，不动 theta/phi/distance。角色走，镜头围绕点跟着走；鼠标照常自由环绕。这是"挂在角色身上"最直接的形态。
  - **背后镜头（v2，需偏移模型）**：把 theta 拆成 `基准朝向（角色面朝的世界偏航） + 鼠标偏移量`。两种实现：
    - 务实版：`UpdateCameraFollow` 每帧在 OnEvent 之后读 `Camera.GetTheta()` 与上一帧记录的 theta 求差（= 本帧鼠标贡献），累进偏移量，再 `SetOrbit(角色偏航 + 偏移, phi, distance)`；不新增模式，但依赖"鼠标事件先于更新帧"的时序，稍脏；
    - 干净版：`Camera` 新增 `Mode::ThirdPerson`——持有 `m_BaseYaw`（由跟随组件设）+ `m_YawOffset`（鼠标累加），`GetView` 用 `球坐标(baseYaw+offset, pitch, distance)`。推荐后者，约 60 行，交互自聚合，后续碰撞拉近也好挂。

### 2.5 朝向来源冲突：角色"面朝"没有单一真相

- **现状**：`FacingYaw` 是**弧度**（PhysicsWorld.cpp 里 `DegreesToRadians(TurnSpeed)*dt` 步进），且只在 `FaceMovement==true` 且**有水平输入**时才驱动；`BaseRotation` 含"转正倾斜"（模型自身可能歪）。相机 theta 是**度**。
- **冲突**：直接读 `FacingYaw` 当相机偏航，会 (a) 单位不一致、(b) 角色静止转向时拿不到、（c）被倾斜姿态污染。
- **收敛**：**背后来源一律读目标实体的世界旋转，取水平前向的偏航角**：`yaw = atan2(-fwd.x, -fwd.z)`，其中 `fwd` = `目标世界矩阵旋转`作用于 `FrontAxis` 后的水平投影。这依赖的是"角色现在实际朝哪"，与 `FaceMovement` 开关、FacingYaw 内部状态无关——脚本直接 `SetRotation` 转向也能跟上。`UpdateCameraFollow` 在 `UpdateWorldTransforms` 之后调用，恰好拿得到最新世界旋转。

### 2.6 相机实体冲突：单独建"玩家相机" vs 复用主相机

- **现状**：`GetPrimaryCameraEntity()`（Scene.cpp）返回第一个 `Primary==true` 的相机；`SceneLayer` 加载后把 `m_Context->CameraEntity` 绑定到它，渲染始终用它。
- **冲突**：若新增第二台"玩家相机"实体并在 Play 切换，需要 Play/Stop 重新指向 `GetPrimaryCameraEntity` + 刷新 `m_Context->CameraEntity`，还牵扯相机参数在切换时的 preserve——改动面大、易出"编辑相机 view 没同步 aspect"类问题。
- **收敛**：**v1 复用主相机实体**，把 `CameraFollowComponent` 挂上去，行为由 Play 态门控。这样 `m_Context->CameraEntity`、aspect 同步、渲染主相机选择全部零改动。等将来需要"开场 CG 相机 / 多视角切换"再引入多相机实体与切换层。

### 2.7 序列化冲突：跟随目标不能存实体句柄

- **现状**：`entt::entity` 是注册表内句柄，加载/重建场景后**不保真**（`ClearAllEntities` + 重新 `CreateEntity` 会复用句柄值）。
- **冲突**：若 `CameraFollowComponent` 直接存 `entt::entity Target` 进 `.scene`，加载后指向错实体或废句柄。
- **收敛**：组件存 **`TargetUUID`（string，IDComponent.UUID）**，序列化友好；运行时先经 `Scene::FindEntityByID` 解析为实体句柄缓存，缓存失效（实体被销毁）时每帧重查兜底。这与其他组件引实体（如 MeshSource UUID）风格一致。

### 2.8 更新时序冲突：读角色世界位必须在正确阶段

- **现状**：`Scene::OnUpdate3D` 步骤序：`UpdateScripts → StepPhysics → UpdateAnimations → UpdateWorldTransforms → UpdateSkins → UpdateLightParams → UpdateEnvironment → RenderMeshes3D`。
- **冲突**：角色 `TransformComponent` 是本帧物理写回的**局部 TRS**；世界位要在 `UpdateWorldTransforms` 重算后才生效。若在它之前读，拿到的 world 是上一帧的（慢一帧的滞后感）。
- **收敛**：`UpdateCameraFollow()` 插在 `UpdateWorldTransforms()` 之后、`UpdateSkins()`/渲染之前（两行间已有自然空位），保证读的是本帧最新 world 旋转/平移。

### 2.9 Play/Stop 相机参数回滚（可选，同 Transform 快照哲学）

- **冲突**：跟随态会把 `Orbit` 的 target/distance 改到角色身上；Stop 后编辑相机可能停在角色位置，而非用户 Play 前逛的场景位置。
- **收敛**：沿用 `编辑运行时物理分离计划书` 的"Transform 快照回滚"哲学——Play() 时把相机 `(Target, Theta, Phi, Distance)` 存一份，Stop() 写回。改动极小、与既有心智一致；**初版可不做**（很多情况下"Stop 后相机留在角色旁"反而是想要的），列为可选项。

### 2.10 输入快照/相机消费冲突（低风险，说明即可）

- **现状**：`Scene::OnEvent` 对所有输入事件先记入 `m_InputState`（供脚本 `input.*` 查询），再非阻塞地把同一事件转发给相机。
- **冲突**：Play 态鼠标同时被"脚本 input.*（能读到拖拽）"与"相机 OnEvent（环绕视角）"消费——目前角色移动用 WASD、相机用鼠标，无按键冲突。只是提醒：将来若做"鼠标点击/拖动即玩家指令"需注意二者共享同一份原始输入；且 Play 中相机输入依赖"悬停视口"，真正的游戏需要**光标捕获**（见 §8 风险）。

### 2.11 多角色/多相机冲突（未来格子）

- v1 只支持"一台相机跟随一个目标"。多相机切换、跟随目标热切换、分屏，留到"多相机实体 + 切换层"出现时再设计；接口上保证 `UpdateCameraFollow` 是独立函数、组件内聚，不被早期实现堵死。

## 3. 总体设计

### 3.1 组件（`GE/include/GE/Scene/Components.h`）

```cpp
/// 跟随相机：Play 时把主相机的瞄准点钉在目标实体上（Orbit 几何即第三人称）。
/// 挂在带 CameraComponent 的实体上；一个场景允许一台（v1）。
struct CameraFollowComponent {
    // 目标（参与序列化）：存 UUID，加载后解析为实体句柄
    std::string TargetUUID;

    float HeightOffset = 1.6f; ///< 瞄准点上抬（角色眼睛/胸口）；世界 up 方向
    float Distance     = 3.5f; ///< 初距（用户滚轮可覆盖，受 Min/Max clamp）
    float Pitch        = 25.0f; ///< 初始俯角（度）
    bool  FollowYaw    = false; ///< 背后镜头（v2，需 Camera::Mode::ThirdPerson）；false = 自由环绕
    bool  EnableInEdit = false; ///< Edit 态是否也跟随（默认否：编辑态用编辑器导航）

    // 运行时（不序列化）
    entt::entity Target = entt::null; ///< 解析后的目标实体（FindEntityByID 结果）
};
```

挂载约定：实体 = `TransformComponent + CameraComponent + CameraFollowComponent`。不新增第二相机实体（决策 5.1）。

### 3.2 Scene 驱动（`GE/include/GE/Scene/Scene.h` + `Scene.cpp`）

```cpp
// Scene.h private：新子步骤声明
void UpdateCameraFollow();

// Scene.cpp 在 OnUpdate3D 中，UpdateWorldTransforms() 之后、UpdateSkins() 之前调用
void Scene::UpdateCameraFollow() {
    // 门控：Edit 态默认不接管（编辑导航）；EnableInEdit 可强制预览
    if (!m_PhysicsWorld) return;
    if (!IsPlaying() && !...EnableInEdit) return;

    auto ccView = m_Registry.view<CameraComponent, CameraFollowComponent>();
    for (auto entity : ccView) {
        auto &cfc = ccView.get<CameraFollowComponent>(entity);
        if (!m_Registry.valid(cfc.Target))
            cfc.Target = FindEntityByID(cfc.TargetUUID); // 缓存失效兜底重查
        if (!m_Registry.valid(cfc.Target)) continue;
        auto *ttc = m_Registry.try_get<TransformComponent>(cfc.Target);
        if (!ttc) continue;

        // 瞄准点 = 目标世界位 + 增高（world 由本帧 UpdateWorldTransforms 刚算好）
        const glm::vec3 aim = glm::vec3(ttc->GetWorldMatrix()[3])
                            + glm::vec3(0.0f, cfc.HeightOffset, 0.0f);
        ccView.get<CameraComponent>(entity).CameraInstance.SetTarget(aim);

        if (cfc.FollowYaw) {
            // 背后镜头：基准偏航 = 目标世界旋转的水平前向角；偏移量由相机自身鼠标模型维护
            // v2：cam.SetBaseYaw(facingYawDeg);（配合 Camera::Mode::ThirdPerson，见 3.4）
        }
    }
}
```

要点：
- **读 `GetWorldMatrix()[3]` 而非 `Translation`**——目标挂在层级下也能取到真实世界位。
- 只写 `SetTarget`（自由环绕）时，`theta/phi/distance` 保持用户当前值（鼠标照常环绕角色）；初距 `Distance/Pitch` 首次生效可用"进入 Play 且用户未动过时 SetOrbit 一次"。
- Target 解析：组件添加时（`OnComponentAdded<CameraFollowComponent>` 特化）与读取前双保险；实体销毁后 `valid==false` → 跳过并置空。

### 3.3 输入侧改动（冲突收敛）

- **v1（推荐起点）**：在 `SceneLayer::OnEvent` 或 `Scene::OnEvent` 处的相机路由前，若该场景 `IsPlaying()` 且主相机带 `CameraFollowComponent` → 把"右键拖的 pan 语义"短路成不动作（配套设置 `SetProcessCameraInput` 逻辑不变）。最简单：新增 `Camera::SetPanEnabled(bool)`，`OnMouseMove` 的 else（pan）分支据它返回。
- **不动**：左键环绕、滚轮距离、键盘 WASD（FPS 模式下才用，跟随走 Orbit 不用）。

### 3.4 背后镜头（v2，可选，按需开工）

`Camera` 新增 `Mode::ThirdPerson`（`Camera.cpp`）：

```cpp
// Camera.h 新增私有字段
float m_BaseYaw   = 0.0f;  ///< 基准偏航（度，由跟随组件每帧 = 角色世界偏航）
float m_YawOffset = 0.0f;  ///< 鼠标水平偏移累加（度）
// GetView() ThirdPerson 分支：位置 = Target + 球坐标(baseYaw + yawOffset, pitch, distance)
// OnMouseMove ThirdPerson 分支：m_YawOffset -= dx*sens; m_Pitch += dy*sens;（无右键 pan）
// 公开：SetBaseYaw(deg) / GetYawOffset()
```

- `CameraFollowComponent.FollowYaw=true` 时，`UpdateCameraFollow` 每帧 `cam.SetBaseYaw(目标世界偏航)`，其余交给相机自己的偏移模型——鼠标环绕与角色转向**并存不互相覆盖**（解决 §2.4）。`ThirdPerson` 模式天然禁右键 pan（没有 pan 分支）。
- 碰撞拉近（角色↔相机间射线、撞墙把距离拉近）：依赖物理查询接口（`物理系统增强计划书` 阶段 A 的 RayCast）落地后追加，v2 内可选。

### 3.5 序列化（`GE/src/Scene/SceneSerializer.cpp`）

- 序列：`CameraFollowComponent` 段落写 `TargetUUID / HeightOffset / Distance / Pitch / FollowYaw / EnableInEdit`（跳过运行时 `Target`）。
- 反序列：`AddComponent` 后填字段；`Target` 留空，首个渲染帧由 `UpdateCameraFollow` 自解析。
- 旧 `.scene` 无此段落 → 不添加组件，行为不变（向后兼容）。

### 3.6 Play/Stop 集成

- v1：不特别处理（Stop 后相机留在角色旁，作为"跟拍点位"，可接受）。
- 可选快照（决策 5.6）：`Scene::Play()` 存 `(Target, Theta, Phi, Distance)`，`Stop()` 写回——与 `编辑运行时物理分离` 的 Transform 快照同一套哲学，改动约 10 行。

## 4. 阶段实施

### 阶段 A：自由环绕跟随（最小闭环）

- A1. `Components.h`：+`CameraFollowComponent`（v1 字段 + `Target` 运行时句柄）。
- A2. `Scene.h/.cpp`：+`UpdateCameraFollow()`，在 `OnUpdate3D` 的 `UpdateWorldTransforms()` 与 `UpdateSkins()` 之间调用；`OnComponentAdded<CameraFollowComponent>` 特化（首次解析 TargetUUID）。
- A3. `SceneSerializer.cpp`：序列/反序列段落。
- A4. `SceneHierarchyPanel.cpp`：`TryAddComponent` 加一行 + `DrawComponent` 面板（TargetUUID 输入框 + 数值字段 + FollowYaw/EnableInEdit 复选）。

### 阶段 B：健壮性 + 冲突收敛

- B1. Target 生命周期：目标实体销毁/组件移除 → `valid==false` 时降级为"相机原地不动"，不崩不跳。

## 5. 决策记录（编码前拍板）

**5.1 复用主相机实体，不新增"玩家相机"实体 —— ✅ 已定（v1）**
- `m_Context->CameraEntity`、aspect 同步、渲染主相机选择全部零改动；切换相机的 preserve 问题不复存在。多相机等"开场 CG/切换视角"需求出现时再引入实体级切换。

**5.2 自由环绕优先，背后镜头放缓 —— ✅ 已定（阶段 A 先做自由环绕）**
- 自由环绕 = 只 `SetTarget`，复现"镜头挂在角色身上"零冲突；背后镜头牵动 theta 绝对制与鼠标视角的模型改造（§2.4），v2 再上。两者组件字段天然兼容（`FollowYaw` 开关）。

**5.3 朝向读世界旋转水平偏航，不读 FacingYaw 内部 —— ✅ 已定**
- `FacingYaw` 是弧度、仅 FaceMovement 生效时驱动、且 BaseRotation 含倾斜；世界旋转水平 yaw 是"角色实际朝哪"的唯一可靠来源，且天然在 `UpdateWorldTransforms` 之后可用。

**5.4 跟随态禁用右键 pan —— ✅ 已定**
- pan 语义=平移 Target（`Camera.cpp:OnMouseMove` else 分支），与逐帧 `SetTarget` 直接打架；禁用是收敛唯一解。实现走 `Camera::SetPanEnabled`，相机自管交互，不把 pan 语义泄漏到上层。

**5.5 跟随目标存 UUID 解析，不存实体句柄 —— ✅ 已定**
- `entt::entity` 不跨加载保真（ClearAllEntities + 重建会复用句柄值）；UUID（IDComponent）与现有 MeshSource 引资源同风格。运行时缓存句柄，失效兜底重查。

**5.6 Play/Stop 相机快照 —— 待定（初版不做，阶段 B3 可选）**
- "Stop 后相机留在角色旁"很多时候是期望行为；需要"回编辑器逛场景位置"再加 10 行快照，与 Transform 快照同一哲学。

## 8. 风险与开放问题

1. **鼠标滞后一帧/时序**：自由环绕版在 `OnUpdate3D` 改 Target，输入在 `OnEvent` 先消费，天然"先拉视角、后跟位"，无明显滞后。背后镜头（v2 偏移模型）若走 `GetTheta()` 差值 hack，依赖帧序，务必在阶段 C 用干净模式实现。
2. **光标捕获**：编辑器模型靠"悬停视口才喂鼠标给相机"；真正的"像玩游戏"需要按鼠标时**捕获并隐藏光标**（GLFW CURSOR_DISABLED），否则拖拽会飞出窗口。这是输入层的能力，列为阶段 C 前置或独立小单。
3. **相机跟随多个角色 / 切换目标**：v1 单目标；组件已留 `TargetUUID`，未来可做成"按 Tag/相机专用组件选目标"，改动面小。
4. **碰撞拉近**：防"镜头穿墙/穿角色"需角色→相机射线 + 平滑回弹，依赖物理查询接口（阶段 A）先落地；否则 v1/v2 都不会自动避障。
5. **与 Edit/Play 门控耦合**：`UpdateCameraFollow` 的"是否接管"由 `IsPlaying()` 决定；若未来有"非角色也有跟随需求"（航拍/序列镜头），把判断下沉成"组件 `Enabled` + 命令式 `SetFollowTarget`"，本组件接口目前不堵死这条路。
