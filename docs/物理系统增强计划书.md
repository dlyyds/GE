# 物理系统增强计划书

> 状态：**计划中（未开工）**
> 目标：把当前"只跑了 Jolt 基础刚体模拟"的物理层补成可用的游戏物理层——碰撞/触发事件、查询接口（射线/Overlap）、编辑器物理可视化、编辑器与运行时物理分离、碰撞层配置化、碰撞体类型扩展、若干物理正确性修复。
> 前置：现状——JoltPhysics 已集成并封装（`PhysicsWorld.cpp`，Fixed 60Hz 步进 + 时间累加器，`MAX_SUBSTEPS=5`），Box/Sphere 两枚碰撞体，Static/Kinematic/Dynamic 三态，碰撞层过滤（Default/Player/Enemy/Trigger），动态体↔Transform 双向同步。编辑器/运行时不做区分（`Scene::OnUpdate3D` 每帧无条件 `StepPhysics`，Scene.cpp:515）。
> 关联：`脚本输入系统计划书.md`（事件总线思想、ScriptComponent 回调签名风格）、`实体包围盒剔除计划书.md`（线框调试开关、子实体剔除）、`项目架构总览.md`

## 0. 一句话架构

```
Jolt Contact/TempListeners(物理 Update 内同步回调, 只写环形缓冲, 不碰 ECS)
        │
        ▼
PhysicsWorld::Step() 返回后, 主线程把缓冲 → CollisionEvent(正常碰撞 + 触发器)
        │
        ▼
Scene::StepPhysics() 尾部 → 按 entity 路由到 ScriptComponent::OnCollisionEnter/Stay/Exit
        │
        ▼
查询接口(射线/Overlap) = PhysicsWorld 薄封装 Jolt NarrowPhaseQuery, 命中返回 entt::entity
```

**关键约束**：Jolt 的 `PhysicsSystem::Update()` 是同步调用，contact 回调发生在物理步进线程内（此处即主线程）。但回调内**不得**改 ECS / 回调脚本——先落缓冲，Step 返回再分发。缓冲同时天然聚合 manifold 点、避免脚本副作用污染 solver。

## 3. 阶段 A：物理事件 + 查询接口

### 3.1 Body ↔ 实体映射（前置基础）

创建 body 时写入 userdata（`ProcessPendingBodies`，PhysicsWorld.cpp:424）：

```cpp
JPH::BodyCreationSettings bodySettings(...);
bodySettings.mUserData = static_cast<JPH::uint64>(static_cast<entt::id_type>(entity));
// 或创建后 bodyInterface.SetUserData(bodyID, ...)
```

`PhysicsWorld` 新增两个反向查询：

```cpp
entt::entity GetEntityFromBody(JPH::BodyID id) const;   // 读 userdata, 无效返回 entt::null
JPH::BodyID   GetBodyFromEntity(entt::entity e) const;  // 复用现有 RuntimeBodyID
```

**生命周期防线**：实体销毁路径已走 `DestroyRigidBody`（先 `RemoveBody` 再 `DestroyBody`，PhysicsWorld.cpp:265），userdata 随 body 一起消失；事件分发时仍对 `reg.valid(entity)` 兜底。

### 3.2 碰撞/触发事件生成（ContactListener）

在 `InitJolt` 注册 `JPH::ContactListener`：

```cpp
class EngineContactListener final : public JPH::ContactListener {
    void OnContactAdded(const JPH::Body &a, const JPH::Body &b,
                        const JPH::ContactManifold &mf, JPH::ContactSettings &ios) override;
    void OnContactPersisted(...) override;   // 同 Added
    void OnContactRemoved(const JPH::SubShapeIDPair &) override;
    // 缓冲栏: std::array<RawContactEvent, N> 环形写入 + spawn 计数
};
```

实现要点：

- 回调内**只写原始缓冲**（body pair、本次穿透法线/法向冲量近似），不碰 registry、不回调脚本。`Update()` 本身先 `ClearRawEvents()` 再步进。
- **Stay 是高频通道**：初版 `OnContactPersisted` 逐对只更新"最近帧仍在接触"标记，不单独排队（避免每帧几十万事件）。行为近似 Enter/Exit 两态，Stay 仅当脚本显式注册回调时才启用。
- **传感器区分**：`body.IsSensor()` 的底不产生 solver 约束，但仍会触发 Added/Removed。初版统一走同一 listener，事件携带 `bool IsTrigger`，脚本侧两种回调都收；**Jolt 5.x 对 sensor 的精确回调语义在实现时以单测验证**（一个动态球 vs 传感器球，打日志核对 Enter/Stay/Exit 序列）。

事件结构（放 `PhysicsTypes.h`，轻量、可跨线程拷贝）：

```cpp
struct CollisionEvent {
    entt::entity A = entt::null;          ///< 事件所属实体（回调挂在它身上）
    entt::entity B = entt::null;          ///< 对端实体
    enum class Type : uint8_t { Enter, Stay, Exit };
    Type type = Type::Enter;
    bool IsTrigger = false;               ///< 本事件是否来自传感器
    glm::vec3 ContactNormal = {0,0,0};    ///< Enter/Stay 时有效（第一个接触点的法线向 A）
    float Impulse = 0.0f;                 ///< 法向冲量近似（Enter/Stay）
};
```

### 3.3 路由到脚本

扩展 `ScriptComponent`（Components.h，与现有 `std::function` 回调同风格）：

```cpp
using CollisionCallback = std::function<void(Entity self, Entity other,
                                             float impulse, const glm::vec3 &normal)>;
CollisionCallback OnCollisionEnter;
CollisionCallback OnCollisionExit;
CollisionCallback OnTriggerEnter;         // IsTrigger 的 Enter
CollisionCallback OnTriggerExit;          // IsTrigger 的 Exit
```

`Scene::StepPhysics` 尾部消费缓冲，对事件里 `A`、`B` 两侧实体分别取 `ScriptComponent` 后调用——**两侧都要投递**（否则对端实体收不到自己视角的事件）。

```cpp
void Scene::DispatchCollisionEvents();
// 对 buffer 里每条: 若 A 实体有 OnCollisionEnter ⇒ 调(A, B, impulse, normal)
//                      若 B 实体有 OnCollisionEnter ⇒ 调(B, A, impulse, -normal)
```

### 3.4 查询接口

`PhysicsWorld` 薄封装 `NarrowPhaseQuery`：

```cpp
struct RayCastHit {
    entt::entity Entity = entt::null;
    float Distance = FLT_MAX;             ///< 命中距离(注意 sc 正 x 向)
    glm::vec3 Position, Normal;
};

bool RayCast(const glm::vec3 &origin, const glm::vec3 &unitDir,
             float maxDist, RayCastHit &out) const;                    // 最近命中
bool RayCastAll(const glm::vec3 &origin, const glm::vec3 &unitDir,
                float maxDist, std::vector<RayCastHit> &out) const;   // 全部命中(排序)
bool OverlapSphere(const glm::vec3 &center, float radius,
                   std::vector<entt::entity> &out) const;
bool OverlapBox(const glm::vec3 &center, const glm::vec3 &halfExtents,
                const glm::quat &rot, std::vector<entt::entity> &out) const;
```

- 命中集经 `GetEntityFromBody` 回映射到 entity，跳过无 `RigidBodyComponent` 的底。
- **Mask/过滤挂钩**：所有查询接口预留 `CollisionLayer filterMask` 参数（默认全层），复用阶段 D 的过滤；阶段 A 先用 `ObjectLayerFilterSingleObjectVsAll`，D 再做真过滤。

### 3.5 验收

- sandbox 脚本：注册 `OnCollisionEnter/OnTriggerEnter`，动态球砸传感器球，日志打 Enter/exit 序列正确、冲量非零。
- 射线：编辑器点任意碰撞体，`RayCast` 返回正确 `entity`；`OverlapSphere` 拾取通过。
- 回归：现有 2.scene 刚体摆放行为不变（事件为空缓冲时零开销）。

## 5. 阶段 C：编辑器/运行时物理分离（Edit/Play）

### 5.1 现状问题

`Scene::OnUpdate3D` 每帧无条件 `StepPhysics`（Scene.cpp:515），编辑器里给实体加 Dynamic 刚体立刻下落——没法摆放场景，也没有"预览 vs 实际运行"的区分。编辑器**现有任何运行态**（已 grep 确认无 Play/Simulate）。

### 5.2 设计

`Scene` 增加模拟状态：

```cpp
enum class SimulationState : uint8_t { Edit, Playing };

bool IsPlaying() const;
void Play();   // Edit → Playing：把所有"已标记但未建"的 RequestCreate 
               //             flush 到待创建列表，首帧 Step 即建立；从各刚体初始化位置落座
void Stop();   // 回 Edit：可选项——回滚到 play 前保存的 Transform 快照（初版做）
```

- `StepPhysics` gate：`if (m_SimulationState == Playing) m_PhysicsWorld->Step(ts);`。
- **Edit 态编辑语义**：Transform 可自由改（body 未建/未激活，无冲突）；缩放改变 → 仍天然作用于下次创建的 shape。
- **Play 进入**：把 `m_PendingBodies` 之外 "有 RigidBody + 碰撞体但未初始化"的实体全部补 `RequestCreateRigidBody`；首帧 `ProcessPendingBodies` 建立 + `Activate`，动态体开始模拟。**第二帧起** dynamic 的 Transform 由 Jolt 写回——第一帧 Start 快照要在 UI 线程 Play 按下时立刻同步一次 `SyncBodiesToTransforms`（防"按 Play 后画面抖一下"）。
- **Stop 回滚**（初版做，$性价比最高）：Play 前对每个动态实体存 `(Translation, Rotation)` 快照，Stop 时写回 + 所有 body 统一 `DestroyRigidBody` + 清 pending，回到干净的 Edit 态。
- 编辑器 UI：`SceneLayer` 顶部 ImGui 工具条加 **▶ Play / ⏹ Stop**（替代键盘 F5/F8 亦可）；Play 时视口标题显示"▶ 运行中"。

### 5.3 验收

- 编辑器摆悬空动态盒子，Edit 态静止悬停；点 Play 开始下落，点 Stop 回到原位且完全静止。
- Play 期间修改 Transform 无效/或显示警告（防止"手拖被物理拉回"的困惑）。

**涉及文件**：`GE/include/GE/Scene/Scene.h`、`GE/src/Scene/Scene.cpp`、`GE_Editor/src/SceneLayer.cpp`、`GE_Editor/src/SceneLayer.h`。

## 6. 阶段 D：碰撞层与碰撞矩阵配置化

### 6.1 现状问题

`CollisionLayer` 枚举 + `EngineObjectLayerPairFilter` 写死（PhysicsWorld.cpp:86）：Trigger 不与任何层碰、其余全碰。`Player/Enemy/Trigger` 都死在常量里，加自定义层要改映射表，编辑器没有任何入口。

### 6.2 设计

- **碰撞矩阵**：`PhysicsWorld` 持有 `std::array<std::array<bool, Count>, Count> m_CollisionMatrix`（初值 = 现有硬编码语义：Trigger 行/列全 false，其余 true）。`EngineObjectLayerPairFilter` 改为持有矩阵引用，`ShouldCollide` 直接查表；`ObjectVsBroadPhaseLayerFilter` 同理查 `m_CollisionMatrix[layer1][layer2BroadPhase→layer]`（矩阵是对称的，BroadPhaseLayer 与 ObjectLayer 初版一一对应，见注释）。
- **过滤项保留 Mirror**：查询接口（§3.4）的 `filterMask` 从矩阵读取，保证"场景里不碰的层也无法被射线/Overlap 选中"（可配置项，默认一致）。
- **编辑器 UI**：层次面板（`SceneHierarchyPanel`）或新建"物理设置"面板，用 ImGui 表渲染 N×N 勾选框矩阵：
  - 勾 = 两层可碰撞；未勾 = 不可。对角自动强制 true（自己与自己总是可查询）。
  - 修改后调 `PhysicsWorld::SetCollisionMatrix(...)` → filter 下次步进即生效（不需要重建 body，broad-phase 层过滤在 broadphase 查询/求解时查）。
- **序列化**：矩阵存进 `.scene`（`SceneSerializer`），不序列化时用默认矩阵（向后兼容旧场景）。

### 6.3 验收

- 勾选 Player×Enemy 关 → 两动态球穿身而过、无碰撞响应；重开恢复。
- 射线穿过被禁层内的物体，命中集正确排除（filterMask 生效）。
- 旧 .scene 加载后行为与现在完全一致（默认矩阵 = 现硬编码语义）。

**涉及文件**：`GE/src/Physics/PhysicsWorld.cpp`、`GE/include/GE/Physics/PhysicsWorld.h`、`GE_Editor/src/Panels/SceneHierarchyPanel.cpp`、`GE/src/Scene/SceneSerializer.cpp`。

## 7. 阶段 E：碰撞体类型扩展 + 物理正确性修复

### 7.1 碰撞体类型扩展

在 Box/Sphere 基础上补三枚（均在 `BuildShapeForEntity` 组合进复合形状，多碰撞体依旧 `StaticCompoundShape`）：

```cpp
struct CapsuleColliderComponent {
    float Radius = 0.5f;
    float HalfHeight = 1.0f;            ///< 不含端帽的柱身半高
    glm::vec3 Offset = {0,0,0};
    glm::quat OffsetRotation = {};      ///< 绕刚体中心的局部旋转(新增: 斜置碰撞体)
};
struct ConvexHullColliderComponent {
    GE::UUID MeshSource;                ///< 从已有的 Mesh 资源取顶点, Jolt ConvexHullShapeSettings 算凸包
    glm::vec3 Offset = {0,0,0};
    glm::quat OffsetRotation = {};
};
struct MeshColliderComponent {          ///< 静态 trimesh(地形/关卡), 仅 Static 刚体可用
    GE::UUID MeshSource;
    glm::vec3 Offset = {0,0,0};
};
```

- **ConvexHull / Mesh 的数据源**：复用现有 Mesh 资源加载（`MeshManager`），`MeshColliderComponent` 需要 TridimensionalMesh API（带索引）；两枚组件序列化 `MeshSource` UUID。初版限制：凸包/网格碰撞体只支持 Static，Dynamic 用凸包会抬升内存/稳定性成本，文档标注。
- **OffsetRotation** 同样给 Box/Sphere 补上（`RotatedTranslatedShapeSettings` 第二个参数现在是 `sIdentity()`，PhysicsWorld.cpp:469 直接接上）。

### 7.2 物理正确性修复（四处）

| # | 问题 | 位置 | 修复 |
|---|---|---|---|
| 1 | **质量改动不动惯量**：只 `SetInverseMass(1/Mass)` | `UpdateRigidBodyProperties`（PhysicsWorld.cpp:309） | 改用 shape 推导惯量：`body.GetShape()->GetMassProperties()` 缩放质量后用 `bodyInterface.SetMassProperties`，用户在面板改 Mass 时旋转手感正确 |
| 2 | **改类型是销毁重建**：`RebuildRigidBody` destroy→下一步重建，丢速度/激活态 | `RebuildRigidBody`（PhysicsWorld.cpp:315） | 新增 `SetRigidBodyType(entity, type)` 走 `bodyInterface.SetMotionType`（保留速度、不重建 shape）；仅**改碰撞形状**时才保留销毁重建 |
| 3 | **碰撞体 Offset 不能旋转** | `BuildShapeForEntity`（PhysicsWorld.cpp:469） | `RotatedTranslatedShapeSettings` 第二参数改接 `OffsetRotation` |
| 4 | **Scale 语义不干净**：盒半尺寸乘 `tc->Scale` 但 Offset 不乘；球半径 `max(Scale)` | `BuildShapeForEntity`（PhysicsWorld.cpp:458/483） | 统一：碰撞体尺寸 **和** Offset 都乘 `tc->Scale`（组件局部空间 ⇒ 世界语义自洽）；UI 提示非均匀缩放下建议 `Scale` 乘进尺寸而非改变 RealScale |

溢出的优先级：**#1 惯量、#3 Offset 旋转**影响手感/摆放最直接，先做；#2 提升运行时切换体验；#4 与编辑器缩放交互，体验权衡后做。

### 7.3 验收

- 面板把球 Mass 从 1→10 后，砸同样物体反弹/推动效果与"静止重物"直觉一致（不再出现"重但转得飞起"）。
- 运行时把 Dynamic 设成 Static：物体立刻焊死原位，速度归零语义正确；再设回 Dynamic 恢复。
- Capsule 斜置（OffsetRotation 45°）滚动方向正确；凸包碰撞体从 `.gemesh` 生成贴合模型。
- 2.scene 回归：旧 Box/Sphere 场景序列化读回形状、行为不变。

| 角色控制器 | `CharacterVirtual`（vs Character，无外加约束孔） | 封装 `CharacterControllerComponent` 挂在根实体，每帧 `PlayerInput` 驱动 | 有第一/第三人称角色 |
| 约束/Joint | 点位/铰链/球/固定 | Data-only 组件 + `PhysicsWorld` 建/拆 | 门、铰链、布娃娃 |
| 物理材质 | `PhysicsMaterial` + 摩擦/弹性合并规则 | `PhysicsMaterialAsset` + Collider 引用 | PBR 材质拓展后顺带 |
| 渲染插值 | 固定 tick | Step 输出与渲染帧间 α 插值 | 低帧率/高物理负荷场景 |

**阶段 F 不排期**，需要时按单开工；其接口设计**不要让早期阶段把路堵死**——阶段 A 的缓冲/分发、阶段 E 的组件挂载方式均为后续 Character/Joint 预留了扩展点。

## 9. 风险与开放问题

1. **传感器回调语义**：Jolt 5.x 对 `IsSensor` 底是否回调 `OnContactAdded/OnContactRemoved` 需在 A 阶段**先写最小单测验证**；若不回退，传感器事件改由 `NarrowPhaseQuery` 手动轮询（每帧 Overlap + 差分）兜底。
2. **Stay 通道量级**：`OnContactPersisted` 是高频，初版策略（不排队、仅标记）若在脚本侧衍生需求（连续接触力），追加按实体聚合、每实体每帧最多一条 Stay。
3. **body userdata 生命周期**：实体销毁后 userdata 随 body 销毁（路径已有），事件消费对 `reg.valid` 兜底即可；**禁止**在 ContactListener 回调内 `try_get` 实体——跨线程/破坏 ECS 迭代。
4. **Edit/Play 快照膨胀**：Stop 回滚需要每动态实体存 Transform，物体多时可接受（一组 `vector<tuple<entity,Transform>>`）；不做深度序列化快照。
5. **碰撞矩阵与 broad-phase 层**：初版矩阵是 `Count×Count` 全对对，broad-phase 层数与 ObjectLayer 一一对应；未来层数>几十时再引入层分组（`GroupFilter`）——当前 4 层不适用。
