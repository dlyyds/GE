# 骨骼动画实现计划书

> 状态：**计划中（未开工）**。前置已完成：骨骼蒙皮阶段 A~E（`骨骼蒙皮实现计划.md`）全部落地——顶点 80B 带蒙皮字段、`mesh_skinned` 蒙皮管线、关节 SSBO、SkinDef 共享去重、场景序列化。
> 目标：为 GE 引入 glTF 骨骼动画（animation），让带骨骼的角色（mint_swimsuit 等）经 `GLTFSceneImporter` 导入后能按动画键帧驱动骨架、蒙皮跟随变形。
> 定位：**只做骨骼动画（关节/节点 TRS 键帧）**，融入既有蒙皮链路；不做 morph target（权重）动画、不做复杂混合。动画是纯粹的「时间采样 → 写节点局部 TRS」的场景层特性，**渲染层零改动**——蒙皮管线已按「每帧读当前 worldMatrix」设计，动画写完 TRS、DFS 重算 world、`UpdateSkins` 自动跟上。

---

## 0. 一句话架构

```
AnimationClip(共享键帧资源) + AnimationComponent(绑定+播放状态)
        ↓ 每帧 UpdateAnimations（在 UpdateWorldTransforms 之前）
写目标节点实体的局部 TRS
        ↓ 已有 UpdateWorldTransforms DFS（无需改）
recompute 全部 worldMatrix
        ↓ 已有 UpdateSkins（无需改）
jointMatrix = world × IBM 上传 → mesh_skinned 变形
```

**关键观察（mint 实测）**：动画 channel 的目标节点（mint: 157~196 等）往往**不是皮肤 joints 本体（7~60），而是其上层的祖先/结构节点**。动画写任一节点的局部 TRS，经 DFS 传播到其子树内全部关节的世界矩阵，蒙皮自然跟随。因此**动画作用于「任意解析出的目标节点实体的局部 TRS」**，而非仅限皮肤关节。

## 1. 术语与 glTF 动画数据模型

glTF 的 animation 由三部分构成（`model.animations[i]`）：

```
animation {
  channels: [ { sampler: int, target: { node: int, path: "translation|rotation|scale|weights" } }, ... ]
  samplers: [ { input: accessorIdx(时间), output: accessorIdx(采样值), interpolation: "LINEAR|STEP|CUBICSPLINE" } ]
}
```

- **channel**：一条「动哪个节点」的「哪条路径(TRS/权重)」→ 指向一个 sampler。
- **sampler**：键帧数据。`input` 是 SCALAR 时间数组（秒，单调递增）；`output` 是按路径定类型的值数组（translation/scale=VEC3、rotation=VEC4[xyzw]、weights=SCALAR）；`interpolation` 决定取值方式。
- **时间轴**：clip 时长为所有 sampler `input` 末尾时间的最大值。
- **rotation**：glTF 存四元数 `[x,y,z,w]`，转引擎 `glm::quat` 需换序为 `(w,x,y,z)`（与导入器 `FillTransform` 同款处理）。

**插值规则**：
- LINEAR：相邻键帧线性插值；rotation 用 **slerp**。
- STEP：取前一个键帧值（保持）。
- CUBICSPLINE：每键帧 3 个值（入切线 + 出切线 + 值），需 Hermite 插值 —— **v1 不做**（mint 全 LINEAR，见 §8）。

**mint_swimsuit 实测**：1 条 animation，约 980 个 channel（translation/rotation ≈335 条、scale ≈310 条），全 LINEAR；时长约 24.1s；每 channel 键帧数 4~723 不等。键帧总量 ~50 万，展开为内存约 7MB，可接受。

## 2. 现状与差距分析

| 模块 | 现状 | 动画需要的改动 | 破坏性 |
|---|---|---|---|
| `GLTFLoader` | 只 `LoadModel` + `BuildMesh`（顶点/材质） | 新增 `BuildAnimations(model, out)`：解码 times/values/插值 → AnimationClip；不碰 mesh | 无 |
| `GLTFSceneImporter` | 建实体树 + 皮肤两遍回填（SkinDef） | 有动画时给角色实体挂 `AnimationComponent`：解析每 channel 的 node → 实体句柄（复用 `nodeEntities`），目标节点缺失则跳过 | 低 |
| `Components.h` | 无动画组件 | 新增 `AnimationClip` / `ClipInstance` / `AnimationComponent`（规则同 SkinDef 共享模式） | 低 |
| `Scene` | `OnUpdate3D`：脚本→物理→`UpdateWorldTransforms`→`UpdateSkins`→渲染 | 新增 `UpdateAnimations`，**插在 `UpdateWorldTransforms` 之前**（动画写局部 TRS，DFS 重算 world，蒙皮就地生效） | 低 |
| `UpdateSkins` / 蒙皮肤管线 | 每帧读当前 worldMatrix | **零改动**（这正是先前把 `UpdateSkins` 放 DFS 之后的原因） | 无 |
| `SceneSerializer` | 已序列化 Skin/Joint | 序列化 `AnimationComponent`：clip 源键 + 目标实体 UUID + 播放状态 | 低 |
| 编辑器面板 | 已展示 Skin/Joint | 动画控件（播放/暂停、速度、时间、循环、切 clip） | 无 |

**关键决策点（已在 §9 拍板）**：动画数据继承 SkinDef 的「**共享资源 + 按实例解析**」模式——**AnimationClip（原始键帧）是模型级共享资源**（按 `"path#N"` 去重缓存）；**channelTargets（目标实体句柄）按每次导入/加载实例解析**。两个角色实例共享同一份键帧、各有自己的目标实体表。

## 3. 总体架构设计

```
┌──────────────────── 加载期（GLTFSceneImporter::Import）────────────────────┐
│  载入 model →
│  若 model.animations 非空：
│    对每条 animation → 调 GLTF::BuildAnimations(model, i, clip)   ← 解码键帧
│    经 ClipCache 按 "path#N" 去重取 shared_ptr<AnimationClip>
│    给「带 SkinComponent 的实体」挂 AnimationComponent：
│      ClipInstance { clip, channelTargets }                        ← 逐 channel 解析
│      channelTargets[i] = nodeEntities[ch.nodeIndex]（缺失则 entt::null）
├──────────────────── 场景层（每帧）─────────────────────────────────────────┤
│  Scene::UpdateAnimations(ts)          ← 插在 UpdateWorldTransforms 之前
│    for 每个 AnimationComponent：
│      time += dt * speed；超时长按 loop 回绕或钳制
│      遍历当前 active clip 的 channels → 采样(Linear lerp / rot slerp)
│        → 写 channelTargets[i] 实体 TransformComponent 的局部 TRS
│  然后 UpdateWorldTransforms DFS 重算（含目标节点的子孙关节）
│  然后 UpdateSkins 读 world → 关节矩阵 → GPU
├──────────────────── 持久化（SceneSerializer）───────────────────────────────┤
│  Animation: { Clip: "path#N", Targets: [实体UUID...], Time/Speed/Playing/Loop }
└──────────────────────────────────────────────────────────────────────────────┘
```

**设计原则**：
1. **动画是「时间采样写局部 TRS」，不是渲染属性**。渲染端读到的永远是 DFS 之后的 world，动画只负责在局部 TRS 上游动。
2. **Clip 共享、Targets 独立**。键帧是模型级不变量（多实例共享）；目标实体是场景级（每实例解析）。与 SkinDef/SkinComponent 的分工完全同构。
3. **作用于任意节点，不限于皮肤关节**。channel.target.node 解析为实体即写；祖先节点动画经 DFS 传播到子孙关节（mint 就是这种形态）。

## 4. 分阶段实施

按「数据可打印 → 角色动起来 → 可持久化 + 编辑」节奏拆 3 个可独立交付的小阶段，每阶段结束可编译可运行可回退。

### 阶段 A：数据层 —— glTF 动画解析 + AnimationClip

**目标**：把 mint 的动画键帧读出来，channel / sampler / 插值 / duration 可打印验证。本阶段不渲染。

**A1. 数据结构**（`Components.h`，放物理组件之前、皮肤组件之后）
```cpp
/// 一条动画通道：动某个节点的某条路径（TRS）
struct AnimationChannel {
    enum class Interp : uint8_t { Linear = 0, Step = 1, CubicSpline = 2 };
    enum class Path : uint8_t { Translation = 0, Rotation = 1, Scale = 2 };

    int         nodeIndex = -1;    ///< glTF 目标节点索引（导入期解析成实体）
    Path        path = Path::Translation;
    Interp      interp = Interp::Linear;
    // 键帧（按路径类型分存，避免每帧类型转换；rotation 已转 glm::quat 内存序）
    std::vector<float>     times;           ///< 键帧时间（秒，单调递增）
    std::vector<glm::vec3> vecKeys;         ///< translation / scale 值（每键帧一个）
    std::vector<glm::quat> quatKeys;        ///< rotation 值（每键帧一个，wxyz 序）
};

/// 动画片段（模型级共享资源：与 SkinDef 同构，跨实体按 "path#N" 去重）
struct AnimationClip {
    std::string                     name;
    float                           duration = 0.0f;
    std::vector<AnimationChannel>   channels;
};

/// 绑定到场景的动画实例：clip（共享键帧）+ 本次解析的目标实体
struct ClipInstance {
    std::shared_ptr<AnimationClip> clip;
    std::vector<entt::entity>      channelTargets;  ///< 与 clip->channels 一一对应（未解析为 null）
};

/// 动画组件：挂在带骨架的角色实体上（与 SkinComponent 同实体）
struct AnimationComponent {
    std::vector<ClipInstance> clips;   ///< 模型全部动画（mint 1 条）
    size_t  active = 0;                 ///< 当前播放 clip 索引
    float   time = 0.0f;                ///< 播放时间（秒）
    float   speed = 1.0f;               ///< 播放倍速
    bool    playing = true;             ///< 是否在播
    bool    loop = true;                ///< 是否循环

    AnimationComponent() = default;
    AnimationComponent(const AnimationComponent &) = default;

    /// 便捷访问当前 clip（无动画返回 nullptr）
    [[nodiscard]] const AnimationClip *activeClip() const {
        return (active < clips.size()) ? clips[active].clip.get() : nullptr;
    }
};
```

**A2. glTF 读取**（`GLTFLoader.cpp` 新增 `BuildAnimations`）
```cpp
bool GLTF::BuildAnimations(const tinygltf::Model &model, size_t animIdx,
                           AnimationClip &out, std::string *err = nullptr);
```
- 遍历 `model.animations[animIdx].channels`，查对应 sampler。
- 用类似 `ReadFloatAttr` 的思路从 accessor 解出 `times`（SCALAR/FLOAT）与 `output`（按 path 类型），bufferView 越界/类型不符时容错跳过该 channel。
- rotation：`[x,y,z,w]` → `glm::quat(w,x,y,z)`。
- `interpolation` 字符串 → 枚举；CUBICSPLINE 记 `CubicSpline`，本阶段不展开（见 §4 阶段 D）。
- `name = model.animations[animIdx].name`；`duration = max(times.back())`。

**A3. 验证**：临时日志打印 mint：animation 数、每条 duration、channel 数、抽查某 channel 时间轴首尾与插值类型。**不必写单测**（项目无测试框架），日志验证即可。

**退出标准**：日志能读出 mint「1 条动画 / 约 980 channel / 时长 24.1s / 全 LINEAR」，且现有非动画模型加载渲染完全不受影响。

### 阶段 B：场景层 —— AnimationComponent + UpdateAnimations + 蒙皮跟随

**目标**：让 mint 导入后按动画键帧驱动骨架，网格随之变形。**这是动画"动起来"的关键里程碑**。

**B1. 导入器扩展**（`GLTFSceneImporter.cpp`）
当前两遍流程之后追加动画接入：
1. `model.animations` 非空时，对每条 animation 调 `GLTF::BuildAnimations` 得到 `AnimationClip`，经 clip 缓存（见 B3）取去重后的 `shared_ptr`。
2. 给「合法的」角色实体挂 `AnimationComponent`。选实体规则：优先取**带 SkinComponent 的实体**（动画驱动的骨架宿主）；若没有皮肤但有动画（纯对象动画，可选），退化为挂到动画目标节点的最近公共祖先实体——**v1 仅支持有皮肤的角色场景，无皮肤的对象动画列入阶段 D**。
3. 对每条 clip 解析 `channelTargets`：`nodeEntities[ch.nodeIndex]`，找不到则 `entt::null`（洞况跳过）。
4. 空洞校验：channel 目标节点未导入 / 目标实体无 Transform，容错跳过（该 channel 不驱动，画面退化为绑定姿态该部位）。

> 顺序约束：必须在**所有实体树建成 + SetParent 完成**后才解析 channelTargets（复用 `nodeEntities`，理由同皮肤两遍回填）。

**B2. Scene 每帧更新动画**（`Scene.cpp` 新增 `UpdateAnimations`）
在 `OnUpdate3D` 中插在 `StepPhysics` 与 `UpdateWorldTransforms` 之间：
```cpp
void Scene::UpdateAnimations(Timestep ts) {
    auto view = m_Registry.view<AnimationComponent>();
    for (auto entity : view) {
        auto &ac = view.get<AnimationComponent>(entity);
        if (!ac.playing || ac.clips.empty()) continue;
        const AnimationClip *clip = ac.activeClip();
        if (!clip || clip->channels.empty()) continue;

        // 推进时间轴（速率为负支持倒放）
        ac.time += ts.GetMilliseconds() / 1000.0f * ac.speed;
        if (clip->duration > 0.0f) {
            if (ac.loop) {
                ac.time = std::fmod(ac.time, clip->duration);
                if (ac.time < 0.0f) ac.time += clip->duration;
            } else {
                ac.time = std::clamp(ac.time, 0.0f, clip->duration);
            }
        }

        // 逐通道采样 → 写目标实体的局部 TRS（局部字段，DFS 随后重算 world）
        const auto &targets = ac.clips[ac.active].channelTargets;
        for (size_t ci = 0; ci < clip->channels.size(); ++ci) {
            const auto &ch = clip->channels[ci];
            if (ci >= targets.size() || targets[ci] == entt::null) continue;
            auto *tc = m_Registry.try_get<TransformComponent>(targets[ci]);
            if (!tc) continue;
            switch (ch.path) {
            case AnimationChannel::Path::Translation:
                tc->Translation = SampleVec3(ch, ac.time);
                break;
            case AnimationChannel::Path::Rotation:
                tc->Rotation = SampleQuat(ch, ac.time);
                break;
            case AnimationChannel::Path::Scale:
                tc->Scale = SampleVec3(ch, ac.time);
                break;
            }
        }
    }
}
```

采样辅助（`AnimationChannel` 内的静态方法或自由函数）：
```cpp
// 线性插值（vec3）：二分定位键帧区间 [k, k+1]，t01 = (t - times[k])/(times[k+1] - times[k])
static glm::vec3 SampleVec3(const AnimationChannel &ch, float t);
static glm::quat SampleQuat(const AnimationChannel &ch, float t); // slerp
// STEP：取 times 上界的前一个键值；CUBICSPLINE：v1 直接按 LINEAR 近似（记警告）或钳到 vecKeys 前向
```
v1 用 `std::lower_bound` 二分定位，980 channel × 每帧二分成本可忽略；后续优化可缓存上一帧的键帧索引（时间单调 → 常用优化）。

**时序约束**：`OnUpdate3D` 最终顺序变为
`脚本 → 物理 → UpdateAnimations → UpdateWorldTransforms(DFS) → UpdateSkins → 光源/环境 → 渲染`。
**动画写的是局部 TRS，DFS 在它之后重算 world，蒙皮即拿到最新关节矩阵**。若跳过 DFS（本帧未动），则仍用缓存 world，等价于绑定姿态。

**B3. Clip 共享缓存**（`MeshManager` 或小型 `AnimationClipManager`）
- 键：`"scene.gltf#0"`、`"scene.gltf#1"`…（与网格 `"path#N"` 同构，跨导入去重）。
- 接口建议：`std::shared_ptr<AnimationClip> LoadAnimationClip(path, animIdx)`，内部缓存 `unordered_map<string, weak_ptr<AnimationClip>>`，命中返回既有、未命中 `GLTF::BuildAnimations` 后存入。
- 生命周期：`weak_ptr` 仅在无任何实体引用时释放，再次导入到同路径时重建并回归缓存。
- **v1 也可简化为「导一次建一次」不做缓存**（mint 1 条 clip 建成 7MB 可接受），缓存列入 B3 的推荐实现项，两者都算完成退出标准。

**退出标准**：导入 mint 后，角色按动画键帧持续变形（关节随 157~196 等目标节点运动带动网格）。临时改 `AnimationComponent.time` 或停 `playing` 能直观看到动画暂停/续播。

### 阶段 C：序列化 + 编辑器

**目标**：动画状态可保存/加载，面板可播放控制。

**C1. SceneSerializer 扩展**
```yaml
Animation:
  Clip:   "assets/.../scene.gltf#0"     # 动画片段源键（加载期经 LoadAnimationClip 取共享 clip）
  Targets: [实体UUID, 实体UUID, ...]      # 与 clip.channels 一一对应（跨文件稳定引用）
  Time: 0.0
  Speed: 1.0
  Playing: true
  Loop: true
```
- 序列化：遍历 `AnimationComponent`，写 `Clip` 键 + `Targets`（channelTargets 每个目标实体取其 IDComponent.UUID）、播放状态。
- 反序列化：沿用「先全建 → 记 ID → 再回填」流程——pass1 建实体记待回填动画；pass2 解析动画：`LoadAnimationClip(clipKey)` 取共享 clip，`Targets` UUID → 实体句柄重建 channelTargets，挂 `AnimationComponent`。
- 兼容：`Clip` 键缺失（旧场景文件）→ 跳过该动画，所在骨架退化为绑定姿态，不崩溃。

**C2. 编辑器面板**（`SceneHierarchyPanel`）
`AnimationComponent` 控件：播放/暂停按钮、速度滑条、时间轴拖动（Scrubber，允许手动设 `time` 便于 D2 验证）、Loop 开关、clip 下拉切换（>`clips.size()` 时）。读取用 `activeClip()`。

**C3.（可选）模型级多 clip**：mint 仅 1 条；多 clip 只是 `clips` 多一项 + `active` 切换，无需额外基建。

**退出标准**：含 mint 动画角色的场景 保存 → 加载 后持续动画，播放状态/速度/循环保留；重载后仍动（Clip 经缓存去重，多角色实例共享同一键帧）。

## 6. 风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| 动画目标节点是大规模祖先节点（非皮肤关节），解析/驱动模型理解错 | 中 | 实测 mint 已确认该形态；方案明确「写任意目标实体局部 TRS + DFS 传播」，不依赖 skin.joints |
| CUBICSPLINE 误用 LINEAR 导致明显走样 | 低 | 显式按 interp 分支：非 LINEAR 时记一次警告并按 LINEAR 近似，D 阶段再完整支持 |
| 键帧量大（mint ~50 万键帧）内存/上传开销 | 低 | 只存 CPU 键帧（约 7MB），每帧仅采当前区间 2 个键值；采样索引缓存留 D |
| 动画与物理/脚本同时写同一关节 TRS 冲突 | 低 | 关节一般不是刚体；约定「谁能写」。先文档注明，编辑器加"动画接管"开关（Playing=false 即让出）|
| 序列化后目标实体 UUID 丢失导致不动 | 低 | Targets 按 UUID 二次回填（与 Skin/SkinDef 同法）；缺失容错退化为绑定姿态 |
| 多 clip 切换时 channelTargets 错位 | 低 | 每个 ClipInstance 自带 channelTargets，切换 active 即整套目标切走，不会交叉 |

## 9. 决策记录（编码前拍板）

**9.1 动画数据归属：Clip 共享 + Targets 按实例 —— ✅ 已定（与 SkinDef 同构）**
- 键帧（`AnimationClip`）是模型级不变量，跨导入/跨实例共享（`"path#N"` 缓存）。
- 目标实体（`channelTargets`）每实例解析，`ClipInstance` 打包「clip + targets」。
- 理由：两个角色实例骨骼拓扑相同但关节实体不同；键帧不必重复存储。

**9.2 动画作用于哪类节点 —— ✅ 已定：任意解析出的目标实体，不限于皮肤关节**
- mint 的动画目标是关节的外围/祖先节点（157~196），非 skin.joints（7~60）。
- 写任一目标节点局部 TRS，DFS 传播到子孙关节 → 蒙皮跟随。不依赖「目标在 joints 列表内」。

**9.3 AnimationComponent 挂载宿主 —— 已定：带 SkinComponent 的角色实体**
- v1 仅支持有皮肤的角色动画；无皮肤对象动画列阶段 D。

**9.4 插值范围 —— 已定：v1 支持 LINEAR + STEP，CUBICSPLINE 按 LINEAR 近似**
- mint 全 LINEAR，无实际资产依赖 CUBIC；完整 Hermite 支持列 D。

**9.5 序列化 Targets 方式 —— 已定：存目标实体 UUID（跨文件稳定），clip 存源键**
- 与 Skin 关节 UUID 持久化同法；反序列化二次回填（两遍流程），缺失容错。

## 10. 与既有蒙皮链路的关系（为什么几乎没有渲染改动）

前序蒙皮实现刻意把 `UpdateSkins` 放在 `UpdateWorldTransforms`（DFS）之后、每帧读**当前** worldMatrix。动画只需在其更上游写局部 TRS：

```
UpdateAnimations（写局部 TRS）
  → UpdateWorldTransforms（重算 world） 既有
  → UpdateSkins（jointMatrix = world × IBM） 既有，零改动
  → 蒙皮肤管线（mesh_skinned 变形） 既有，零改动
```

因此本计划是**纯场景层/时序特性**：新增 1 个组件 + 1 个每帧系统 + 1 处解析 + 持久化与面板，渲染层与着色器完全不动。这也是把动画做成「蒙皮基础设施之上的薄层」的回报——第 4 阶段动画落地成本被压到现在这一套计划的规模。
