# 动画系统增强计划书（采样缓存 · 动画事件 · clip 过渡）

> 状态：**计划中（未开工）**。前置已完成：骨骼动画阶段 A~C 全部落地——`AnimationChannel/Clip/ClipInstance/AnimationComponent`、glTF 动画解析（LINEAR/STEP + rotation slerp）、`.geanim` 烘焙、`AnimationClipManager` 共享缓存、`UpdateAnimations` 时序、场景序列化、编辑器播放面板、BoundingBox 动画扫帧。
> 目标：把当前「单 clip 硬切播放器」补齐成**可用的通用动画播放内核**——(1) 采样键帧索引缓存（性能）、(2) 动画事件（交互接入点）、(3) clip 过渡/混合（切动画不跳变）。
> 定位：延续既有「动画是时间采样写局部 TRS」的场景层特性，渲染层依旧**零改动**；三阶段各自独立可回退，每阶段结束可编译可运行。

---

## 0. 一句话架构

```
采样缓存：ClipInstance 持每 channel 键帧下界 hint，时间单调 → 免二分
动画事件：update 推进时间时做跨帧区间检测 → 命回调（loop 回绕补区间）
clip 过渡：active 指向目标、transitionFrom 指向源，双路 eval 到 pose buffer 按权重混合后写回
```

三个阶段都只改 `Scene.cpp` 的 `UpdateAnimations` 与相关数据结构，不动蒙皮/渲染/着色器。

## 2. 总体设计

### 2.1 采样键帧索引缓存（阶段 A）

**问题**：`FindActiveKey`（`Scene.cpp:52`）对 `times` 做二分定位键帧区间。`UpdateAnimations` 每帧对每个 channel 调用一次，mint 单角色即 ~980 次二分/帧；时间轴**单调推进**意味着每帧键帧下界要么不变、要么 +1~2，二分浪费绝大部分。

**设计**：缓存放在 `ClipInstance`（每实例每 channel，而非共享 `AnimationClip`）——共享 clip 是模型级不变量，缓存是播放状态，多实例各播各的时间轴。

```cpp
/// 绑定到场景的动画实例：clip（共享键帧）+ 本次解析的目标实体
struct ClipInstance {
    std::shared_ptr<AnimationClip> clip;
    std::vector<entt::entity>      channelTargets;  ///< 与 clip->channels 一一对应（未解析为 null）
    std::vector<uint32_t>          keyHints;        ///< 与 channels 一一对应：上次采样的键帧下界（运行时缓存，不序列化）
};
```

采样改造：新增带 hint 版本，保留原纯二分版本（编辑器一次性查询仍用）：

```cpp
// 从 hint 出发单调走：时间前进向右扫、后退向左扫；hint 失效（>=n）时回退全区间二分。
// 典型帧推进 O(1) + 仅跨越 1~2 个键帧；拖动/倒放大跨步时才退化为整段扫描（编辑器场景，可接受）
size_t FindActiveKey(const std::vector<float> &times, float t, uint32_t &hint);
```

`hint` 语义：指向「上一帧/本次已知的键帧下界 k0」。前进时 `while (times[k0+1] <= t) ++k0`；后退时 `while (times[k0] > t) --k0`；一旦 k0 越界视为未初始化回退二分。首帧装配 `ClipInstance` 时 `keyHints.assign(channelCount, 0)`；切换 clip 时整套 `keyHints` 随 `ClipInstance` 换走（与 `channelTargets` 同机制），无错位风险。

**过渡期（阶段 C）的复用**：from 与 to 是两个不同 `ClipInstance`，各持一套 `keyHints`，过渡双路 eval 天然各享其缓存——这正是缓存放 `ClipInstance` 而非组件的原因之一。

### 2.2 动画事件（阶段 B）

**问题**：现在动画只是"动"，无法把「播到第几秒」暴露给逻辑层。脚步、武器砍中帧、音效、粒子、对话口型都需要**按播放时间触发回调**。

**设计**：事件表挂 `ClipInstance`（场景/玩法级数据，与共享键帧分离）。`AnimationComponent` 加一个运行时回调句柄（不序列化）：

```cpp
struct AnimationEvent {
    float        time = 0.0f;   ///< 秒，相对 clip 起点
    std::string  name;          ///< 事件名（脚本/音频等按名订阅）
};

struct ClipInstance {
    // …… clip / channelTargets / keyHints（见 2.1）
    std::vector<AnimationEvent> events;   ///< 场景级事件表（编辑/序列化；共享键帧里没有事件）
};

struct AnimationComponent {
    // ……既有字段
    std::function<void(const std::string &eventName)> eventCallback; ///< 运行时句柄，不序列化
};
```

**触发检测（区间法，无需持久化 fired 状态）**：`UpdateAnimations` 对每个播放实体，在推进时间**之前**记 `prev = ac.time`，推进钳制后得 `cur = ac.time`；触发 `events` 中满足 `prev < e.time <= cur` 的事件。**loop 回绕**时（cur < prev）拆两段：`(prev, duration]` 与 `[0, cur]` 各触发一次。区间法天然免疫 scrubbing/clip 切换（它们直接改 `time`，下次推进的 `prev` 读取的是改后的值 → 不产生跨越区间 → 不误触发）。**负速/倒放不触发事件**（v1 决策，见 §9）。

**派发**：命中事件 → `GE_CORE_TRACE` 日志（可关）→ 若 `eventCallback` 非空则调用。脚本组件在 `OnCreate`/`OnUpdate` 里给 `eventCallback` 挂闭包即可按名分发。编辑器面板不做分发、只做**事件表编辑**（见 §3 阶段 B）。

### 2.3 clip 过渡 / 混合（阶段 C）

**问题**：`active` 是单索引。面板切 clip 直接 `time=0`，两 clip 关键姿势不同就跳变。主流引擎至少支持两 clip 之间的 crossfade。

**混合模型（entity,path 键合的 pose buffer）**：过渡期需要同时求值「目标 clip」与「源 clip」两套姿势，按权重混合后写回。由于不同 clip 的 channel **顺序与目标集都可能不同**，不能按下标配对——统一用 **键 = (目标实体, 路径)** 的临时 buffer 做并集。

```cpp
/// 过渡临时姿态槽（buffer 成员，避免每帧分配；flat vector 线性合并，channel 量级下足够）
struct BlendSlot { entt::entity e; AnimationChannel::Path p; float w; // 累计权重
                   glm::vec3 v; glm::quat q; };
```

**状态**：`active` 在切换瞬间即指向**目标** clip 并 `time=0`；源 clip 用独立字段续播：

```cpp
struct AnimationComponent {
    // ……既有字段
    size_t transitionFrom    = SIZE_MAX; ///< 源 clip 实例索引；SIZE_MAX = 无过渡
    size_t transitionFromKey = 0;        ///< 源 clip 在其 ClipInstance.keyHints 的记录槽（装配时定）
    float  transitionFromTime = 0.0f;    ///< 源 clip 播放时间（续播）
    float  transitionElapsed  = 0.0f;    ///< 过渡已进行墙钟时间
    float  transitionDuration = 0.0f;    ///< 过渡总时长（0 = 立即）

    /// 请求切换到 clip[idx]，用 blendSeconds 秒过渡（<=0 为硬切）
    void PlayClip(size_t idx, float blendSeconds);
};
```

**过渡流程**（`UpdateAnimations` 内，仅在 `transitionFrom != SIZE_MAX` 时期）：
1. 推进 `transitionFromTime`（复用既有回绕/钳制逻辑，抽小函数 `AdvanceClipTime(t, dur, loop)`）。
2. 推进 `transitionElapsed += dt`；α = `clamp(transitionElapsed / transitionDuration, 0, 1)`（线性；smoothstep 可选 `3α²-2α³`）。**α 按墙钟推进，不随 speed 缩放**。
3. 双路求值写 buffer：
   - 先采样目标 clip 全部 channel → 各自 (e,p) 槽记 `v/q`、`w=1`；
   - 再采样源 clip 全部 channel → 若 (e,p) 已在 buffer → `mix/v/slerp` 到 α → （目标值 × 已写权重）线性下降；若仅源拥有 → 直接写源值（见 §9.3 决策）。
4. 遍历 buffer 写回各实体 `TransformComponent`。
5. `transitionElapsed >= transitionDuration` → `transitionFrom = SIZE_MAX`，仅剩目标 clip 驱动。

**过渡期事件**：只触发**目标** clip 的事件（源 clip 事件不触发，v1 简化，见 §9）。

**序列化**：不序列化过渡进行中状态。保存时 `active` 已是目标 clip、`time` 已是目标时间轴 → 加载后直接落在目标 clip，干净。

## 3. 分阶段实施

### 阶段 A：采样键帧索引缓存

**目标**：运行时与 BoundingBox 扫帧的采样成本从「每帧二分」降到「均摊 O(1)」，行为逐位不变。

**A1. 数据结构**：`ClipInstance` 增 `keyHints`（见 2.1）。装配处（`GLTFSceneImporter` 解析后、反序列化回填后）`keyHints.assign(channelCount, 0)`。

**A2. Scene 采样**：新增带 hint 的 `FindActiveKey(times, t, hint)`（2.1 伪码）；`SampleVec3Channel`/`SampleQuatChannel` 增加带 hint 重载（或直接在 `UpdateAnimations` 用带 hint 版本）。保留旧签名供一次性查询。

**A3.（可选）编辑器扫帧**：`SceneHierarchyPanel.cpp` 的「播放一遍取关节极值」评估（1247 行起）是逐帧单向播放，收益最大——同步改带 hint 版本，跨 clip 时各自重置 hint。

**退出标准**：
- 改造前后采样值**逐位一致**（临时对比日志打印若干 channel × 时间点）。
- mint 运行时 `UpdateAnimations` 与扫帧不再出现每帧二分（可插桩统计 `FindActiveKey` 前进步长，绝大多数 ≤1）。
- 既有场景渲染/包围盒功能不回退。

---

### 阶段 B：动画事件

**目标**：动画播到指定时间触发回调（含 loop 回绕），可编辑、可序列化、脚本可订阅。

**B1. 数据结构**：`AnimationEvent` + `ClipInstance.events` + `AnimationComponent.eventCallback`（见 2.2）。

**B2. Scene 触发**（`UpdateAnimations` 单 clip 路径扩展）：
```cpp
const float prev = ac.time;                       // 推进前记录
ac.time += ts.GetSeconds() * ac.speed;
// …既有回绕/钳制（复用 AdvanceClipTime 抽函数）
FireEvents(ac, prev, ac.time, ac.loop && clip->duration > 0);
```
`FireEvents`：按区间法触发 `events`（含回绕两段）；负速 `prev > cur` 且非回绕 → 不触发（静默跳过）。

**B3. 派发**：命中 → TRACE 日志；`eventCallback` 非空则调用。

**B4. 编辑器**（`DrawAnimationComponent`）：事件表编辑器——每行「时间输入 + 名字输入 + 删除按钮」、底部「添加事件」按钮。事件时间支持拖动/输入。

**B5. 序列化**：`clipNode` 增 `Events: [ { Time, Name }, … ]`；反序列化缺省空事件（旧场景文件照常）。

**退出标准**：
- 在 mint 动画若干时间点放事件，播一遍日志/回调**次数与时间**精确；loop 回绕处不重不漏。
- Scrubber 拖动、clip 切换、`playing=false` 期间不触发。
- 负速播放不触发（v1 语义）。
- 保存→加载后事件表保留。

---

### 阶段 C：clip 过渡 / 混合

**目标**：切 clip 时 `<blendSeconds>` 秒内从源姿势平滑过渡到目标姿势，结束后由目标单独驱动。

**C1. 结构**：`PlayClip(idx, blendSeconds)` + 过渡字段（见 2.3）。

**C2. `UpdateAnimations` 双路流程**：抽 `AdvanceClipTime`；过渡判定/推进/α 计算/双路 eval→buffer→写回/结束判定（见 2.3）。非过渡路径保持现状单 clip 采样。

**C3. 编辑器**：下拉切 clip 从「硬切」改为「填过渡时长输入框（默认 0.25s）+ 切换」；另加「立即切换」按钮（`PlayClip(i, 0)`）。展示当前过渡进度（α%）便于验证。

**C4. 序列化**：无新字段（过渡不落盘，见 2.3 与 §9.6）。

**退出标准**：
- 两 clip（含多 clip 资产）0.25s 过渡：播放中切换视图平滑连续，无瞬时跳变；非循环源 clip 到末尾后以尾姿势参与混合不崩。
- 过渡中再次切换 → 从新目标起新过渡，旧过渡丢弃（§9.4）。
- 暂停/续播、loop 开合在过渡前后行为正确；`transitionFrom=SIZE_MAX` 后仅目标驱动。
- 保存→加载后落点在目标 clip，无残留过渡状态。
- 回归：既有单 clip 场景（mint/buster_drone）渲染与播放与改造前一致。

## 9. 决策记录（编码前拍板）

**9.1 采样缓存归属 —— ✅ 已定：`ClipInstance`（每实例每 channel），不落共享 clip**
- 共享 `AnimationClip` 是模型级不变量；缓存是**播放状态**（多实例各播其轴）。放 `ClipInstance` 让过渡期 from/to 各享一套，切换 `active` 整套换走，无错位。

**9.2 事件归属 —— ✅ 已定：`ClipInstance.events`（场景级）+ 运行时 `eventCallback`（不序列化）**
- 事件是玩法/场景数据（哪个音频、哪帧受击），不是模型几何不变量；glTF 也不携带事件，编辑进来。回调是代码句柄，序列化无意义。

**9.3 过渡混合模型 —— ✅ 已定：entity,path 键合 pose buffer 并集驱动；「仅源拥有」目标写入源值**
- 不同 clip 的 channel 顺序/目标集可能不同，禁止下标配对。同骨架多 clip（主流）目标集一致 → 全部落到目标槽平滑混合；目标集不一致（罕见）→ 仅源节点按源值驱动，过渡结束该节点回退，接受末端可能微小 snap 并写文档。

**9.4 过渡中再次切换 —— ✅ 已定：从新目标起新过渡、丢弃未完成的旧过渡**
- 不做「捕捉当前混合姿势为 from」的复杂度。重置过渡字段即达语义。

**9.5 过渡权重曲线 —— ✅ 已定：linear 默认；smoothstep 留作开关**
- v1 求正确性；曲线替换是单行改动，需要时再开。

**9.6 过渡不序列化 —— ✅ 已定**
- 切换瞬间 `active` 已是目标、`time` 已是目标时间轴；加载后自然落在目标 clip。

**9.7 过渡 α 按墙钟推进 —— ✅ 已定：不随 speed 缩放**
- 避免变速下过渡权重「跳帧」；若将来要「变速过渡」，α 改按采样时间即可（记录在案）。

**9.8 过渡期事件 —— ✅ 已定：只触发目标 clip 事件，源 clip 不触发**
- 简化跨帧检测；双 clip 事件同时触发会重复语义。

**9.9 负速/倒放 —— ✅ 已定：`speed < 0` 时 `PlayClip` 不产生过渡（硬切）；事件不触发**
- 避免 from/to 时间轴方向相反导致的混合歧义；倒放过渡列 D 不在本次范围。

## 10. 与既有链路的关系（改动面收敛）

三个阶段都只是 `UpdateAnimations` 与其数据结构的演进：

```
UpdateAnimations（写局部 TRS）
  ├─ 阶段 A：采样从二分 → 缓存 hint（数值不变）
  ├─ 阶段 B：推进时间时顺带做事件区间检测（多一条副作用路径）
  ├─ 阶段 C：过渡期改双路 eval + buffer 混合写回（结束后退化为单路）
  → UpdateWorldTransforms（DFS） 既有，零改动
  → UpdateSkins 既有，零改动
  → 蒙皮肤管线 / 着色器 既有，零改动
```

`OnUpdate3D` 时序不变；`.geanim` 二进制格式**不动**（`AnimationEvent` 是场景数据，不进烘焙格式；`keyHints` 是运行时态也不进）。因此本计划是纯场景层/播放内核增强，与骨骼动画计划「动画是蒙皮之上的薄层」定位一致，渲染层始终透明。
