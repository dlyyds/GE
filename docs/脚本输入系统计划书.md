# 脚本输入系统计划书（输入快照 · 脚本查询 · 输入锁）

> 状态：**计划中（未开工）**。前置：现有输入链路全部落地——`Application::OnEvent`（GLFW 回调入口）→ `SceneLayer::OnEvent`（视口悬停门控，SceneLayer.cpp:200）→ `Scene::OnEvent`（Scene.cpp:845）→ `DispatchInputEventToScripts`（Scene.cpp:876，逐脚本回调）；平台层已有 `Input::IsKeyPressed/GetMousePosition` 实时轮询（`Core/GEInput.h`）。
> 目标：把「输入如何到达脚本」从**事件回调被动敲门**补成**脚本每帧主动查询输入状态**——(1) 输入快照 + 查询 API（玩法输入），(2) 删除六个从未被赋值的输入回调、`ScriptComponent` 收敛为 `OnUpdate`，(3) 输入锁/焦点（UI 与玩法输入抢占）。动画事件/物理事件是**边沿通知**、走独立事件总线（见动画系统增强计划书 §2.2/§9.2，非本文范围）；**输入是状态，不进总线**。
> 定位：引擎侧输入基础设施，老（C++ std::function）新（将来 Lua）脚本共用一套；不碰渲染/物理/动画链路。

---

## 0. 一句话架构

```
GLFW → Application::OnEvent → SceneLayer 门控（悬停/不是 gizmo） → Scene::OnEvent
   │                                                                │
   │                               输入事件 → Scene 侧 InputState 快照（held/边沿/鼠标增量）
   │                                                                │
   '── 相机保持事件驱动（引擎侧即时消耗，m_ProcessCameraInput）     ↓
                                                    UpdateScripts 顶部 BeginFrameInput 结算
                                                                   ↓
                                          脚本 OnUpdate 内 Input 查询（IsHeld/JustPressed/…）
ScriptComponent 收敛为 OnUpdate + Enabled —— 六个输入回调删除（全仓无代码消费，见 §2.3）
UI 抢占（gizmo/模态/暂停菜单） → 显式 InputBlock 栈，取代「逐键 return true 短路」
```

## 2. 总体设计

### 2.1 InputState 快照（核心）

输入本质是**状态**，不是一次性通知。系统每帧把键盘/鼠标的当前状态记录下来，脚本在 `OnUpdate` 里按需查询。数据归 `Scene`（每场景一份，非全局单例，多视口解耦）：

```cpp
/// 脚本输入快照 —— 每帧结算一次，脚本在 OnUpdate 内查询。
/// 位集上限按 KeyCodes.h / MouseCodes.h 枚举范围取（GLFW 键约 350，取 512 宽松平铺）。
struct InputState {
    std::bitset<512> held;          ///< 当前按住（跨帧状态）
    std::bitset<512> justPressed;   ///< 本帧刚按下（repeatCount==0 才置位）
    std::bitset<512> justReleased;  ///< 本帧刚释放
    std::bitset<16>  mouseHeld;     ///< 鼠标按住

    glm::vec2 mousePos    = {0, 0};   ///< 鼠标最新位置
    glm::vec2 mousePosPrev = {0, 0};  ///< 上一帧位置（结算差值用）
    glm::vec2 mouseDelta  = {0, 0};   ///< 本帧鼠标增量
    float     scrollDelta = 0.0f;     ///< 本帧滚轮累计

    /// 帧首调用（UpdateScripts 之前）：把本轮事件累积结算成「本帧」语义，
    /// 算好 mouseDelta，清空边沿/滚轮以待下一轮事件。held 跨帧保留。
    void BeginFrameInput();

    /// 焦点/视口离开：清空 held（防粘键，见 §6），同时清零边沿。
    void FlushAll();

    // ---- 脚本查询 API ----
    bool IsHeld(KeyCode key) const;
    bool JustPressed(KeyCode key) const;
    bool JustReleased(KeyCode key) const;
    bool IsMouseHeld(MouseCode btn) const;
    bool JustMousePressed(MouseCode btn) const;
    glm::vec2 GetMouseDelta() const;
    float     GetScrollDelta() const;
};
```

**生命周期**（与 App 循环节奏配套，Hazel 式：先 `OnEvent` 轮询再 `OnUpdate`）：
1. **事件轮询期**：`Scene::OnEvent` 收到输入事件 → **只写快照**——`KeyPressed`(`repeat==0`)→`justPressed`+`held`；`KeyReleased`→`justReleased`+清`held`；`MouseMoved`→`mousePos`；`MouseScrolled`→`scrollDelta+=`。
2. **帧结算**：`OnUpdate3D` 顶部、`UpdateScripts`（Scene.cpp:512）之前调 `BeginFrameInput()`。上一轮事件即刻成为本帧可见的 `justPressed/justReleased`；`mouseDelta = mousePos - mousePosPrev`。
3. **脚本读取**：`UpdateScripts` 里脚本 `OnUpdate` 内任意位置查询，**不受回调注册顺序影响**（意图驱动而非注册顺序驱动）。
4. **跨帧**：`held` 持续到 release 或 flush，天然支持「按住跑步」。

> 事件在轮询期记录、在帧首结算，同一 App 循环迭代内 `OnEvent` 先于 `OnUpdate`，因此脚本本帧一定读到的是**本帧之前那批事件** —— 与现在的「回调立即触发」等价且更可预期。

### 2.2 脚本查询接入口

查询对象是场景级快照，脚本经 `Entity`（其持 `Scene*`）访问。在 `Scene` 加：

```cpp
const InputState &GetInputState() const { return m_InputState; }
```

脚本在 `OnUpdate(ts, entity)` 里这样写：

```cpp
script.OnUpdate = [](Timestep ts, Entity e) {
    const auto &in = e.Scene()->GetInputState();
    if (in.IsHeld(KeyCode::W))  moveForward();
    if (in.JustPressed(KeyCode::Space)) jump();
    if (in.JustMousePressed(MouseCode::Button0)) fire();
    turnCamera(in.GetMouseDelta());          // 帧率无关：增量不再是"每回调一次"
};
```

（接入口落 `Entity` 还是直接 `ScriptComponent` 字段，按 Entity 是否已暴露 Scene 定；备选：在 `ScriptComponent` 存 `Scene*`。§5 文件清单按 `Scene::GetInputState()` + Entity 转发写。）

### 2.3 六个输入回调直接删除

全仓 grep（排除 third_party）确认：`OnKeyPressed/OnKeyReleased/OnMouseButtonPressed/OnMouseButtonReleased/OnMouseMoved/OnMouseScrolled`（Components.h:229）**只被 `DispatchInputEventToScripts`（Scene.cpp:876）分发、从未被任何代码赋值**——是定义即死的空壳。既然没有「老脚本要兼容」，便捷层没有存在理由。删除六个回调与类型别名，`ScriptComponent` 收敛为：

```cpp
struct ScriptComponent {
    UpdateCallback OnUpdate;             ///< 每帧更新回调
    bool           Enabled = true;       ///< 是否启用（false 时跳过 OnUpdate）
};
```

查询 API（§2.2）在 `OnUpdate` 内**全覆盖**原六个回调语义，无需回退出口：

| 原回调 | 查询式替代 |
|---|---|
| `OnKeyPressed` | `JustPressed(k)`（repeat>0 不入边沿） |
| `OnKeyReleased` | `JustReleased(k)` |
| `OnMouseButtonPressed/Released` | `JustMousePressed` / `IsMouseHeld` |
| `OnMouseMoved` | `GetMouseDelta()` / `mousePos` |
| `OnMouseScrolled` | `GetScrollDelta()` |
| 消费短路（return true） | `InputBlock`（§2.4） |

**相机**：保持事件路径不变（`DispatchInputEventToCamera`，Scene.cpp:857），它是引擎侧即时消耗 + 需要消费短路（拖 gizmo 不转相机），不属于玩法输入。

### 2.4 输入锁 / 焦点（UI 与玩法输入抢占）

旧语义「脚本回调 `return true` 挡住后续脚本」无法表达"UI 挡住整个场景输入"。改为显式锁：

```cpp
void PushInputBlock();           ///< 占用期间：Scene::OnEvent 输入事件不入快照（等价被消费）
void PopInputBlock();
bool IsInputBlocked() const;     ///< 引用计数式；0 = 未阻塞
```

- **主动占用**：gizmo 拖拽、模态 UI、暂停菜单、对话中 → `PushInputBlock()`，松开后 `PopInputBlock()`。`SceneLayer` 现有的 gizmo 门控（`m_Gizmo && ImGuizmo::IsOver()`，SceneLayer.cpp:206）可复接到这一处。
- **被动失焦**：鼠标离开视口 / 窗口失焦 → 事件不再到达（编辑器门控已有），但快照 `held` 会**粘键**（按下后没收到 release）。新增给 Scene 的 `OnInputFocusLost()` → `InputState::FlushAll()`，由 SceneLayer 在「离开视口」与 `WindowFocus`(lost) 时调用——这正是 SceneLayer 注释里相机曾踩过的坑（SceneLayer.cpp:210），本次给脚本侧一并解决。

## 3. 分阶段实施

### 阶段 A：InputState + 查询 API + 删除旧回调

**目标**：脚本输入收敛到唯一真相（快照查询），旧回调一并清除。

**A1. 新增 `InputState`**（2.1 结构），`Scene` 加成员 `m_InputState` 与 `GetInputState()`（2.2）。位集大小按 KeyCodes/MouseCodes 枚举范围定。

**A2. `Scene::OnEvent` 改为只写快照**：输入事件分支（Scene.cpp:849）记录进 `m_InputState`；同时**整个删除** `DispatchInputEventToScripts`（Scene.cpp:876~974）的逐脚本分发。

**A3. 帧结算**：`OnUpdate3D` 顶部、`UpdateScripts` 之前插 `m_InputState.BeginFrameInput()`。

**A4. `ScriptComponent` 收敛**：删除六个输入回调字段与类型别名（见 §2.3），保留 `OnUpdate` + `Enabled`。顺带检查 `Components.h` 里为这些回调引入的 `KeyCode/MouseCode` include 是否还有其它消费，无则清理。

**A5.（可选）示例脚本**：临时脚本用 `JustPressed(Space)` 打印一次日志，验证边沿单帧一次。

**退出标准**：编译通过、全局无死代码（旧回调引用清零）；查询式脚本能拿到 held/边沿/鼠标增量；多脚本无重复触发；既有渲染/物理/动画不回退。

---

### 阶段 B：输入锁 / 焦点

**目标**：模态场景（菜单/对话框/受击硬直）能整体挡住场景输入，脚本无需逐键判断。

**B1.** `PushInputBlock/PopInputBlock`（引用计数）接入 `Scene::OnEvent` 输入分支：阻塞时事件不写快照。gizmo 拖拽先接上（`SceneLayer` 现有门控 `m_Gizmo && ImGuizmo::IsOver()`，SceneLayer.cpp:206），UI 未有则留口。

**B2.** 视口离开 / 窗口失焦 → `OnInputFocusLost()` → `FlushAll()` 清 held（防粘键，见 §6）。

**退出标准**：模态期间所有脚本读到的输入全为空（held 亦清）；gizmo 拖拽仍挡相机与脚本；结束后恢复；推/弹引用计数无泄漏（配对断言）。

## 9. 决策记录（编码前拍板）

**9.1 输入走快照查询，不进动画/物理事件总线 —— ✅ 已定**
- 输入是**状态**（按住/增量/边沿），需要消费短路、焦点丢失清空；事件总线是**边沿广播**。硬塞会变成"脚本挨个订阅 KeyPressed"的乱序与双抓问题。两条正交：input = 快照查询；动画/物理事件 = 事件总线（见 §10）。

**9.2 消费语义 —— ✅ 已定：由「逐回调 return true 短路」改为「显式 InputBlock 锁」**
- 快照下所有脚本同帧读同一输入，无先后 / 无概率短路，「UI 挡游戏输入」是显式的锁而非逐键返回。行为变化（无顺序）写进文档，避免老脚本作者困惑。

**9.3 六个输入回调 —— ✅ 已定：直接删除，不保留便捷层**
- 全仓 grep（排除 third_party）确认六个回调从未被代码赋值、仅 `DispatchInputEventToScripts` 有分发无消费，是死代码；「老脚本零改动」的保留理由不成立。
- 查询 API 全覆盖原语义（§2.3 对照表）。将来若出现"即时抢占"输入（菜单/快捷键）→ 走 `InputBlock` + 既有事件链，不复活回调。Lua 接入只需暴露查询 C API。

**9.4 键重复 —— ✅ 已定：`repeat>0` 不入 `JustPressed`**
- 玩法逻辑不关心 OS 重复；文本输入走既有 `KeyTypedEvent`（编辑器文本框专用），与快照无关。

**9.5 焦点/视口离开 —— ✅ 已定：`FlushAll()` 清 held，防粘键**
- 复用并补全 SceneLayer 既有"拖出视口释放"的处理经验；相机与脚本两侧一并覆盖。

**9.6 状态归属 —— ✅ 已定：`InputState` 归 `Scene`（每场景一份），非全局单例**
- 多视口/多场景解耦；编辑器与游戏场景各自独立输入状态，不被全局污染。平台 `Input::IsKeyPressed` 实时轮询**保留**但仅供编辑器/工具，脚本一律走快照（避免双真相）。

**9.7 帧序 —— ✅ 已定：`OnEvent`（轮询期）写 → `OnUpdate3D` 首行 `BeginFrameInput` 结算 → `UpdateScripts` 读**
- 事件在轮询期记录、帧首结算，同 App 循环迭代内先事件后更新，脚本本帧读到本帧之前那批事件，可预期。

**9.8 相机 —— ✅ 已定：保持事件驱动，不进快照**
- 相机是引擎侧即时消耗 + 需要 gizmo 短路（`m_ProcessCameraInput` 既有机制），不属玩法输入，迁移不改它。

## 10. 与既有链路的关系（改动面收敛）

输入改动只影响「事件摄入 → 脚本读输入」这一条边：

```
GLFW 回调 → Application::OnEvent → SceneLayer 门控（悬停/不是 gizmo）→ Scene::OnEvent
   ├─（不变）系统事件（窗口尺寸等）→ 各系统
   └─（改造）输入事件 → 只写 InputState 快照；删除 DispatchInputEventToScripts（原逐脚本分发）
UpdateScripts：脚本 OnUpdate 内查询 InputState（无回退回调）
   → 物理 / 动画 / 世界矩阵 / 蒙皮 / 渲染 全部零改动
```

**与动画事件/物理事件的关系（正交，勿混）**：
- 动画事件（动画系统增强计划书 §2.2）：`ClipInstance.events` 跨帧区间触发 → 事件回调（阶段 B 落地为 `eventCallback`）。物理事件（接触 enter/stay/exit）尚未开工。二者都是**边沿通知**，将来统一走事件总线（另议，与本文快照输入互不依赖）。
- 输入逮的是「**本帧按了/按住**」的连续状态，动画/物理事件逮的是「**某个瞬间命中**」的离散一次——两套并存，不共用数据结构。
