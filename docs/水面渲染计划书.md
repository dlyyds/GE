# 水面渲染计划书

> 状态：**计划 / 待评审**
>
> 目标：为 GE 引擎加入「可观测、可调、可序列化」的水面渲染能力，支持波浪位移、法线细节、Fresnel 反射/透射、岸边吸收与泡沫，并预留平面反射/SSR 等高级方案。
>
> 前置：
> - `透明物体渲染计划书.md`：Blend 透明段、远→近排序、深度写关已落地
> - `IBL实现方案.md` / 项目现状：PBR-IBL 环境贴图（`samplerPrefilter` 等）已可绑定
> - `MeshManager`：内置 `"plane"` / `"quad"` 几何体已存在
> - RenderGraph + HDR 链：已有 `Scene_HDR` 中间纹理（Tonemap 前），水面折射可采样
>
> 关联：`延迟渲染实现计划书.md`、`透明物体渲染计划书.md`、`级联阴影映射（CSM）实现计划书.md`

## 1. 目标与范围

### 1.1 本方案要达成的能力

| 能力 | v1（本计划主体） | v2（可选增强） |
|---|---|---|
| 水面几何 | CPU 细分水格 + 顶点位移 | GPU 细分 / Tessellation（未来） |
| 波形 | 叠加 2~4 个 Gerstner 波 + 方向波 | 频谱波 / FFT（未来） |
| 视觉 | 法线贴图细节 + GGX 高光 | 波导数逐像素微法线 |
| 反射 | IBL 环境镜面反射（现状复用） | 平面反射 / SSR |
| 折射 | 采样 `Scene_HDR` 的 UV 扰动 | 深度感知折射 + 吸收 |
| 透明 | 复用 Blend 透明段（深度写关、远→近） | OIT（未来预留） |
| 岸边 | 与场景深度比较 → 吸收色 + 泡沫 | 泡沫贴图、浪线 |
| 编辑 | `WaterComponent` + 序列化 + Inspector | 水面实时预览 |

### 1.2 明确不做

- **不追求 AAA 级流体模拟**：v1 是「游戏可用的渲染型水面」，用 Gerstner 波 + 贴图扰动，不做 Navier-Stokes / FFT 频谱。
- **不引入新渲染后端**：继续走 Vulkan RenderGraph + 现有 `Renderer3D` 管线家族，新增一个独立的水面管线集，不重构主渲染流程。
- **折射不包含透明物体**（边界说明见 §6.3）：v1 的折射只透视「已写入 `Scene_HDR` 的不透明场景 + 天空/IBL」，半透明物体折射留待 OIT 之后。

## 2. 现状盘点：为什么现在还没有像样的水面

| 层 | 现状 | 阻塞点 |
|---|---|---|
| **几何** | `MeshManager` 只有 1×1 的 `plane`（4 顶点单四边形，法线 +Z） | 单四边形做不了波浪形状，需要可配置分辨率的水格 |
| **材质** | `Material::AlphaMode::Blend` + PBR（含 IBL）已打通，透明段已可用 | 水需要自己的 UBO/着色器，而不是塞进 `mesh_pbr_*.frag` 的通用语义 |
| **着色器** | `mesh_pbr.frag` / `mesh_pbr_hdr.frag` / `mesh_pbr_ibl_*.frag` 已存在 | 无 `water.*` 变体；无水面专属输入（波参数、深度、折射 UV） |
| **渲染状态** | `Renderer3D::ConfigureMeshPipeline` 已能切透明管线（混合开、深度写关） | 水面若复用通用材质，无法绑定 WaterUBO、采样场景颜色/深度 |
| **场景深度** | 延迟链有 G-Buffer 深度；前向链目前没有「不透明场景深度 + 颜色」的可采样中间纹理 | 岸边吸收/泡沫、深度折射需要场景深度纹理 |
| **反射** | IBL 预滤波 cubemap 已能拿镜面环境光 | 水面以上的真实物体（人/树/建筑）没有平面反射或 SSR，只会反射天空/IBL |
| **序列化/编辑器** | `SceneSerializer`（YAML）+ `SceneHierarchyPanel` 组件面板 | 无 `WaterComponent`，无法在场景里保存水面参数 |

**结论**：水面不是「换个材质」就能解决的问题。它有独立的几何形状（细分网格）、独占输入（波参数/深肤色/泡沫）、特殊的光照项（Fresnel 反射+折射+岸边吸收），必须作为渲染器的一个**独立子特性**来设计。但它能大幅复用已落地的三块底座：Blend 透明段、PBR-IBL 环境反射、RenderGraph 中间资源。

## 3. 核心决策

### 3.1 决策一：独立 `WaterComponent` + 独立 water 管线，而不是伪装成通用材质

- 不把水写进 `Material::Type` 的 BlinnPhong/PBR 二选一里。水的渲染状态、绑定、UBO 它们共享 FrameUBO/LightBuffer，但有自己的 `WaterUBO` 和 `water.vert/water.frag`。
- 好处：通用材质语义不被污染；`water.frag` 可以自由加 Gerstner 微法线、Fresnel、泡沫，不担心破坏 glTF 材质。
- 接入方式：`Scene::RenderMeshes3D` 在 `meshView` 之后追加 `waterView` 遍历，分派到 `Renderer3D::DrawWater(...)`。
- 场景里既有 `MeshRendererComponent` 又想画水的用户，允许手动用 `plane` 网格 + 通用 PBR Blend 材质做个「简化水面」当降级路径（见 §4.1）。

### 3.2 决策二：v1 用「CPU 细分网格 + 顶点着色器 Gerstner 波」代替 GPU Tessellation

- 当前 RenderGraph 只有 Raster pass，未引入 tessellation/geometry shader；引入 Tessellation 需要管线状态、控制/求值着色器、动态细分，改动面大。
- 因此在 `MeshManager` 增加 `CreateWaterGrid(resolution)` 数据生成：`(N+1)×(N+1)` 顶点，uv 覆盖 `[0,1]`，附带切线/副切线/法线。N 典型取 `32~128`，由组件 `Resolution` 控制。
- 顶点着色器里按顶点世界坐标算 Gerstner 位移；片段着色器用解析偏导重建微法线 + 叠加法线贴图，避免顶点数不够导致水面太「平」。

### 3.3 决策三：v1 反射 = Fresnel 混合「IBL 环境反射 + 直接光高光」

- 新开 SSR/平面反射成本高（见 §8 风险），v1 先把环境反射接上：`Fresnel(F0≈0.02~0.04, NoV)` × IBL 预滤波采样 + GGX 阳光高光。
- 视觉预期：能看到天空、太阳高光、环境色在水上的柔和倒影；真实世界物体暂不反射（作为 v2 平面反射/SSR 的明确缺口记录）。

### 3.4 决策四：折射 = 采 `Scene_HDR` 的 UV 扰动，放在水面 pass 内

- HDR 链里 `Renderer3D` 已经把不透明场景写进 `Scene_HDR`，水面作为独立 raster pass **读**上一状态：`readImages = {Scene_HDR, SceneDepth}`，**写** `Scene_HDR`（或单独 `Water_Scene` 再由 Tonemap 合成）。
- UV 扰动方向：`N_view.xy * refractionStrength`（厚一点的水扰动大），比例尺可调。
- 前向非 HDR 路径退化：不采样 `Scene_HDR`，只靠 IBL 反射 + 吸收色，保证在低配/调试路径可跑。

### 3.5 决策五：透明归口统一走 Blend 透明段，不引入 OIT

- 水面仍是 `AlphaMode::Blend` 语义：混合 `SRC_ALPHA / ONE_MINUS_SRC_ALPHA`、深度写关、深度测试开。
- 波浪使水面自遮挡/岸边呈现混乱时，不靠 OIT 救，而是用**深度差吸收**淡化错误；OIT 留未来章节。
- RenderGraph 中水面 pass 排在「不透明 HDR 之后、其余透明物体之前或之后」依折射需求取舍，见 §6.3。

## 4. 数据层：`WaterComponent`

### 4.1 新增组件

放在 `GE/include/GE/Scene/Components.h`，与 `MeshRendererComponent` 同级：

```cpp
struct WaterComponent {
    glm::vec2 Size = {20.0f, 20.0f};   ///< 水面范围 XZ（世界坐标）
    float Height = 0.0f;               ///< 水面静止高度（世界 Y）
    uint32_t Resolution = 64;          ///< 细分分辨率（N，生成 (N+1)^2 顶点）

    // —— Gerstner 波 ——
    struct GerstnerWave {
        glm::vec2 Direction = {1.f, 0.f}; ///< 传播方向（归一化交给 CPU）
        float Amplitude = 0.6f;           ///< 振幅
        float Wavelength = 6.0f;          ///< 波长
        float Speed = 1.0f;               ///< 相速度
    };
    std::array<GerstnerWave, 4> Waves;    ///< 最多 4 层波叠加
    float TimeScale = 1.0f;               ///< 全局时间缩放

    // —— 视觉材质 ——
    glm::vec3 DeepColor   = {0.012f, 0.055f, 0.09f}; ///< 深水吸收色
    glm::vec3 ShallowColor = {0.05f, 0.35f, 0.42f}; ///< 浅水色
    Texture *NormalMap = nullptr;                   ///< 法线细节贴图（可选）
    float NormalTiling  = 4.0f;                     ///< 法线平铺
    float NormalStrength = 0.6f;                    ///< 法线强度
    float Roughness = 0.12f;                        ///< 粗糙度（影响高光/反射模糊）

    // —— 反射 / 折射 ——
    float ReflectionStrength = 0.8f;                ///< Fresnel 叠加强度
    float RefractionStrength = 0.35f;               ///< UV 扰动强度
    float AbsorptionDepth = 2.5f;                   ///< 深度吸收参考深度（米）

    // —— 岸线 ——
    float FoamDistance = 0.8f;                      ///< 离岸距离，在此距离内渐入泡沫
    float FoamIntensity = 0.9f;                     ///< 泡沫亮度
};
```

### 4.2 与现有 MeshRendererComponent 的关系

- **推荐使用方式**：实体挂 `TransformComponent + WaterComponent`，`Scene::RenderMeshes3D` 在其 `waterView` 循环里生成/缓存水格并调 `Renderer3D::DrawWater`。
- **兼容降级路径**：若实体只挂 `MeshRendererComponent`，用户可手动铺 `MeshManager` 的 `"plane"` 网格 + 通用 PBR Blend 材质，得到静态水面（v1 阶段 0，见 §7）。这不是 WaterComponent 的目标形态，只是短期热身器。

### 4.3 序列化

- `SceneSerializer::SerializeEntity` / `DeserializeEntity` 增补 `<Water>` 块：上述全部可持久化字段 + `waves` 数组。
- `Resolution` / `Size` / `Height` 在反序列化完成后通过 `Scene::RegisterWaterMesh` 重新生成水格，避免每次加载都重建。
- 兼容策略：缺失 `<Water>` 用默认值；`NormalMap` 以资源路径字符串保存，反序列化时走 `AssetManager`/`TextureManager` 查找。

## 5. 渲染层

### 5.1 新增水格几何（MeshManager）

```cpp
// MeshManager.h
std::shared_ptr<Mesh> CreateWaterGrid(uint32_t resolution, const glm::vec2 &size);
```

- 生成 `(resolution+1)^2` 顶点的 XZ 平面，圆心在原点，UV=世界 XZ 单位化。
- 顶点数据含 `position / normal / uv / tangent / bitangent`（沿用现有 Vertex 结构，先给平坦 +Y 法线，真实法线由顶点着色器 Gerstner 计算覆盖）。
- 分辨率缓存：`Scene` 按 `(Resolution, Size)` 键去重，避免每帧重建。

### 5.2 着色器

#### `assets/shaders/glsl/water.vert`

- 输入沿用现网格顶点流；世界坐标 `worldXZ` 由 `transform * position` 得出。
- Gerstner 位移函数：

```
P.xz += (k / w) * A * cos(dot(k, P.xz) - w*t)
P.y  -= A * sin(dot(k, P.xz) - w*t)
```

- 输出 `worldPos / worldNormal / tangent / bitangent` 到片元；局部法线由偏导重建（dx/dy 不在顶点自己身上算）。

#### `assets/shaders/glsl/water.frag`

伪代码结构：

```glsl
void main() {
    // 1. 由 Gerstner 偏导重建微法线，叠加 NormalMap
    vec3 N = normalize(gerstnerNormal + detailNormal * NormalStrength);

    // 2. Fresnel：NoV → R(反射率)，绝缘体 F0≈0.02
    float NoV = max(dot(N, V), 0.0);
    float fresnel = F0 + (1.f - F0) * pow(1.0 - NoV, 5.0);

    // 3. 反射：IBL prefilter 采样（可选）+ 直接光 GGX 高光
    vec3 reflFreq = textureLod(samplerPrefilter, reflect(-V, N), roughLod).rgb;
    vec3 reflColor = reflFreq * frame.iblParams.y * ReflectionStrength;

    // 4. 折射：采样 Scene_HDR，UV 加 N.xy * thickness * RefractionStrength；夹一层吸收
    vec2 refrUV = fragUV.xy + N.xy * 0.01 * RefractionStrength;
    vec3 refrColor = texture(SceneColor, refrUV).rgb;
    float depthDiff = readSceneDepth() - waterDepth;          // 没有深度纹理则回退常数
    vec3 waterColor = mix(ShallowColor, DeepColor,
                          exp(-depthDiff / AbsorptionDepth));

    // 5. 岸边：depthDiff < FoamDistance → 混入泡沫
    float foam = smoothstep(0.f, FoamDistance, FoamDistance - depthDiff) * FoamIntensity;

    // 6. 直接光 / 点光贡献（复用 FrameUBO/LightBuffer）
    vec3 spec = calcGGX(N, V, L);          // 沿用现有 PBR 光照函数
    vec3 result = mix(refrColor, reflColor, fresnel) + spec;

    // 7. 线性 HDR 输出；透明段混合由管线状态负责
    outFrag = vec4(result + foam, fresnel);
}
```

- **HDR 路径**：水写入 `Scene_HDR` 前不 ACES，交给 Tonemap 统一处理（同 `mesh_pbr_hdr.frag`）。
- **前向路径**：降级为 IBL + 直接光 + 常数吸收色，不采样 `Scene_HDR`。

### 5.3 Renderer3D 扩展点

新增（不是重写现有透明段）：

```cpp
// Renderer3D.h
void DrawWater(const glm::mat4 &transform,
               WaterComponent &water,
               const glm::vec4 &clearColor = {-1.f, -1.f, -1.f, 1.f});

// 内部
void ConfigureWaterPipeline(VulkanCommandBuffer &cmd, bool hdr);
void RecordWaterScene(VulkanCommandBuffer &cmd, VulkanRenderFrame &frame,
                      const std::vector<WaterBatch> &waterBatches);
```

- WaterBatch 存放：水格 mesh、transform、`WaterUBO`（组件序列化后每帧按时间填充）、`Scene_HDR/SceneDepth` 采样输入（仅 HDR 路径）。
- 管线 hash 需把 `Water` 作为一个独立 `pipelineId` 位段加入（例如高 3 位 `kWaterPipelineBit`），避免与 Blinn/PBR 的 `pipelineId` 冲突。

### 5.4 RenderGraph Pass 编排

沿用现有 `RenderGraphBuilder::AddPass`（`RenderPassDesc`），新增一个 `WaterPass`：

```cpp
builder.AddPass({
    .name = "Water",
    .colorAttachments = { { sceneHDRHandle, Load, Store } },
    .depthAttachment  = sceneDepthHandle,      // 用于岸线/吸收（可选）
    .readImages = { sceneHDRHandle, sceneDepthHandle },
    .execute = [&](PassExecuteContext &ctx) {
        Renderer::Get3DRenderer().FlushWater(ctx);
    },
});
```

依赖顺序：

```
Opaque / GBuffer → Lighting → […] → Water → 其余透明物体 → Tonemap / Bloom → UI
```

> 若水面不希望 «折射» 其他透明物体，也可把 Water 排在透明段最后；用组件参数区分「WaterOrder」或文档明确 v1 行为。

## 6. 排序与透明的完整性

### 6.1 排序语义

- Water 本质是 Blend（深度写关），由 Scene 在调用 DrawWater 时生成独立 `WaterBatch`，不混进 `MeshRendererComponent` 排序批。
- 如果水面与其他透明物体同屏：水面按 mesh/相机距离的惯例参与透明段远→近排序。水面是大面积平面，建议**固定排在整个透明段的最后**（不折射雾/玻璃时视觉最稳）。
- 波浪自遮挡不再是 alpha 排序问题，而是 §4 里深度吸收淡化的范围。

### 6.2 与现有透明物体的关系

| 场景 | 行为 |
|---|---|
| 水面上方有玻璃/烟雾 | v1 不折射这些透明物；顺序上它们先画、水后画，混合叠累 |
| 水面下方有半透明＋光影 | 混合顺序错误可接受，靠深度吸收减弱；OIT 留未来 |
| 岸边有不透明地形 | 深度差 → 吸收色 → 泡沫，视觉自洽 |

### 6.3 折射边界（明确说明）

v1 折射「只对 Scene_HDR 中已存在的内容生效」：
- ✔ 不透明物体、天空/IBL、直接光高光会被折射进来
- ✘ 其他半透明物体不参与折射
- 原因：它们写在 Water 之后的合成阶段才参与混合，恰好在 Water 读不到的时间点。若要全折射，需整段透明走 OIT/双层合成，属 §10 未来预留。

## 8. 风险与难点

| 风险 | 影响 | 缓解 |
|---|---|---|
| 细分不够导致波浪「锯齿 / 步进」 | 近看明显 | 提供 Resolution 到 128~256；顶点着色器叠加法线贴图掩盖 |
| 前向链没有可采样场景深度 | 吸收/泡沫做不了 | 阶段 2 在 RenderGraph 增加深度中间纹理；阶段 1 先用常数深度 |
| `Scene_HDR` 与 Water 同附件读写自依赖 | RenderGraph 布局循环/同步错误 | Water 必须使用**不同资源实例**读/写（读上一步 Scene_HDR，写新 Scene_HDR 或自身临时附件） |
| 水面 + 其他透明物体的排序 | 混合错误、视觉穿帮 | v1 固定 Water 排透明段后；吸收色淡化；未来 OIT |
| 反射真实物体 | v1 只能反射 IBL/天空，观感有限 | 明确列入 v2 平面反射/SSR；本方案接口预留 `ReflectionTexture` 槽位 |
| 性能：高位分辨率 + 全屏折射采样 | GPU 带宽上升 | Resolution 默认为 64；远离相机可用 LOD 半径；SSR/折射采样开半分辨率 |

## 9. 验收标准

1. 场景可添加 `WaterComponent`，无需写代码即能渲染一片持续波动、有高光和天空反射的水面。
2. 水面参数（尺寸、分辨率、波、颜色、粗糙度、反射/折射强度）在编辑器调整和 `.scene` 序列化往返后保持一致。
3. HDR 链下，水面输出在线性空间进入 Tonemap，不出现双重色调映射偏白。
4. 阶段 2 完成后，岸边深度渐变 + 泡沫正确；相机入水面带来的折射扰动方向合理且连续性无硬边。
5. 现有不透明物体、透明玻璃、PBR-IBL 材质渲染无回归：`MeshRendererComponent` 路径不变，新增仅发生在 `waterView`。
6. 性能基线：64×64 水面 + 4-Gerstner 波 + 全屏折射单 pass，在目标设备上帧时间增量 < 2 ms（阶段 2 给参考值）。

## 10. 未来预留（本方案 v1 不做）

- **OIT（顺序无关透明）**：水的折射若要包含其他半透明物体，需整体透明链路升级，独立立项。
- **FFT / 频谱波**：现在 Gerstner 波是解析近似，做开阔深海可换 `FFT ocean`（compute pass + bilinear 采样）。
- **平面反射 / SSR**：本方案在 WaterComponent 预留 `reflectionTexture` 槽位，后续可把平面反射结果喂进现有 `reflFreq` 采样点。
- **焦散 / 水下后处理**：需要水格法线聚焦计算与水下雾效，属后处理/着色器增强。
- **物理联动**：水面高度可被 `PhysicsWorld` 查询（Jolt 高度场可能需要插值），脚本系统可读 `WaterComponent` 得到波高。
- **编辑器视口预览**：Inspector 里小尺寸预渲染水面缩略图，避免频繁切换 Play 模式确认效果。

## 11. 锁定的衔接点

- `透明物体渲染计划书.md`：水面复用 Blend 透明段语义；`Material::AlphaMode::Blend` 不因水而改动。
- `IBL实现方案.md`：水面反射的预滤波/辐照度/BRDF 绑定直接复用现有 `samplerPrefilter` 等槽位。
- `延迟渲染实现计划书.md` / HDR 链：折射需要 `Scene_HDR` + `SceneDepth`，与现有 GBuffer/Lighting/Tonemap 的 pass 拓扑一致。
- `MeshManager`：`CreateWaterGrid` 与之并列，不破坏现有 `"plane"` / `"cube"` 语义。
- `SceneSerializer` / `SceneHierarchyPanel`：`WaterComponent` 作为新组件进序列化与 AddComponent 面板。
