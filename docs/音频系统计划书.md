# 音频系统接入计划书

> 状态：**计划中（未开工）**
> 目标：为引擎补齐可用的游戏音频层——音频后端初始化/统一 Device、声音资源加载与缓存（2D/3D 发声）、ECS 组件（AudioSource / AudioListener）、每场景音频世界（Listener/Source 管理、位置衰减）、Lua 脚本 API、.scene 序列化、编辑器属性面板与资源浏览接入。
> 前置：当前引擎尚无任何音频代码，`third_party` 中也没有音频库。音频是全新的子系统，只接入不改动渲染/物理/动画链路的既有行为。
> 关联：`Lua脚本系统计划书.md`（脚本 API 注入方式）、`物理系统增强计划书.md`（每 Scene 子系统 + 延迟创建 + Play/Stop 生命周期参考）、`实体包围盒剔除计划书.md`（编辑器面板 Add Component 模式参考）、`项目架构总览.md`

## 0. 一句话架构

```
主线程（ECS 编辑/序列化/脚本）            音频线程
──────────────────────────────            ─────────────────────────
AudioSourceComponent ──► AudioWorld ──►   AudioContext(Audio Engine)
AudioListenerComponent ──► (每帧同步      │  ── ma_engine / ma_device
世界位置/速度)             位置/发声指令)  │
                                          ▼
Lua 脚本 audio.* API ──► 延迟命令队列      设备输出（WASAPI/DSound）
```

- **AudioContext（全局，Application 持有）**：封装后端（miniaudio），负责 Device/Engine 初始化、Mixer/Master Volume、底层发声/停止/查询，是唯一碰音频线程的层。
- **SoundAssetManager（全局，挂 AssetManager）**：负责 `audio/` 资源解码、缓存、引用计数，与 `TextureManager / MeshManager` 同模式。
- **AudioWorld（每 Scene 一个实例）**：把 ECS 组件翻译成后端通道/发声句柄，每帧处理 Listener/Source 世界位置、启动/停止请求、音量/音调变化；不直接持有后端类型，头文件用前向声明隔离 miniaudio。
- **AudioSourceComponent / AudioListenerComponent（纯数据）**：只存作者配置，运行时 Voice/Handle 放 AudioWorld 映射，不污染 ECS 组件。

## 2. 技术选型

推荐 **miniaudio**（v0.11.25，单头文件 vendored）：

| 候选 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| miniaudio | 单头文件、零依赖、MIT/Public Domain 许可、WASAPI/DSound 后端、`ma_engine` 高层 API 自带 3D 衰减/Doppler/Listener/多声道 | 需要自己写少量封装；社区流行度高但要锁版本 | ✅ 推荐 |
| OpenAL / OpenAL-soft | 跨平台成熟、3D API 标准 | 依赖安装/system lib，Windows 下 API 较旧、初始化繁琐 | 备选 |
| XAudio2 | 系统自带、低延迟、适合 Windows | 仅 Windows、API 冗长、无跨平台 | 不选 |
| SoLoud | 高层游戏音效库 | 多一个对象模型、与现有 C++20/ECS 风格略重 | 备选 |

**选型理由**：
1. 引擎现在纯 Windows + Vulkan 开发，miniaudio 用 WASAPI 足够；
2. 单头文件形式与现有 `third_party`（stb、entt、glm 等 header-only/vendored）一致，CR 成本低；
3. 不用搭原生窗口/消息循环，`ma_engine_init` 即可；
4. 自带 WAV/FLAC/MP3 解码器（`MA_ENABLE_FLAC` + `stb_vorbis`/`dr_mp3`），首版不用接外部 decoder。

### 3.4 ECS 组件（Scene/AudioComponents.h）

**一个实体可以同时发出多个声音**，所以 `AudioSourceComponent` 设计成“多声音槽位”容器，而不是单一 SoundPath。
同一个实体上，每个槽位是一条独立的声音（独立文件/音量/音调/衰减/循环控制），运行时 `AudioWorld` 按 `(entity, slotIndex)`
分别维护 VoiceHandle。

```cpp
/// 一条声音槽：一个文件 + 该声音自己的播放参数（可序列化）
struct AudioSound {
    std::string         SoundPath;   ///< audio/ 下相对路径（含扩展名），空 = 未绑定
    std::string         Name;        ///< 槽位名，编辑器/脚本用；空 = 用索引（可序列化）
    bool                PlayOnAwake = false; ///< Play 进入后自动开始
    bool                Loop = false;
    float               Volume = 1.0f;
    float               Pitch = 1.0f;
    float               MinDistance = 1.0f;   ///< 衰减近距（仅 Spatial）
    float               MaxDistance = 100.0f; ///< 衰减远距/截断（仅 Spatial）
    float               Rolloff = 1.0f;
    AttenuationModel    Attenuation = AttenuationModel::Inverse;

    AudioSound() = default;
    AudioSound(std::string path) : SoundPath(std::move(path)) {}
};

struct AudioSourceComponent {
    // —— 作者配置（可序列化）——
    bool  Enabled = true;
    bool  Spatial = true;             ///< 整个源的空间性；false = 2D 全向（UI/背景音乐兜底）
    std::vector<AudioSound> Sounds;   ///< 声音槽列表（一条 = 一个可独立控制的发声）

    // —— 编辑器 UI 暂存（不序列化）——
    int  uiPreviewSlot = -1;          ///< 面板“试听”的槽位索引；-1 = 无请求

    AudioSourceComponent() = default;
};

struct AudioListenerComponent {
    bool Enabled = true;
    // 运行时：AudioWorld 记录该实体为 Listener。
    // 无 Listener 实体时退化到主相机实体（GetPrimaryCameraEntity）。
    AudioListenerComponent() = default;
};
```

运行时 Voice/播放状态**不写回组件**，由 `AudioWorld` 以 `unordered_map<entt::entity, unordered_map<int, VoiceHandle>>`
（或按 `(entity, slotIndex)` 的扁平 map）维护，保证组件继续是纯数据、可序列化不变。

**典型多声音用法**（一辆车）：

```
车辆实体 ─ AudioSourceComponent
           ├── slot 0 "engine"   engine_loop.wav   PlayOnAwake=true  Loop=true   Spatial=true
           ├── slot 1 "tire"     tire_squeal.wav   PlayOnAwake=false Loop=true   Spatial=true
           └── slot 2 "horn"     horn.wav          PlayOnAwake=false Loop=false  Spatial=true
           （三个槽共享同一个 Transform 位置，脚本可单独控制喇叭/轮胎声）
```

### 3.5 每 Scene AudioWorld

```cpp
class AudioWorld {
public:
    explicit AudioWorld(Scene *scene);
    ~AudioWorld();

    void OnComponentAdded(entt::entity e);
    void OnComponentDestroyed(entt::entity e);

    // 命令名都带 slot：int = 槽位索引；缺省给 -1 = 当前实体第一个/全部
    void RequestPlay(entt::entity e, int slot, bool restart);
    void RequestStop(entt::entity e, int slot);
    void StopAll(entt::entity e);
    void SetVolume(entt::entity e, int slot, float v);
    void SetPitch(entt::entity e, int slot, float p);
    void SetLoop(entt::entity e, int slot, bool loop);

    void Update(Timestep ts);           // Play 态每帧调用
    void OnPlay();                      // Scene::Play() 进入时：遍历 PlayOnAwake=true 的槽
    void OnStop();                      // Scene::Stop() 退出时：stop 本实体全部 voice
    void Shutdown();                    // Scene 析构/清空
private:
    void SyncListener();
    void SyncSource(entt::entity e, AudioSourceComponent &src);   // 同步该实体全部槽
    void ProcessCommandQueue();
    Scene *m_Scene;
    struct Impl;                        // Voice 表（key: entity+slot）、命令队列
    std::unique_ptr<Impl> m_Impl;
};
```

`Update(ts)` 内部顺序：

1. 处理主线程命令队列（Play/Stop/SetVolume/SetPitch），转 AudioContext；
2. `SyncListener()`：从 `AudioListenerComponent` 实体或主相机取位置/朝向/速度，写 `AudioContext::SetListener`；
3. 遍历 `AudioSourceComponent`：对每个槽写世界位置、音量、音调；空间声由 transform + 世界矩阵获得。

### 3.6 Scene 集成（关键接入点）

`Scene::OnUpdate3DSimulation` 的当前顺序（Scene.cpp:792）：

```
输入快照 → 脚本 → StepPhysics → UpdateFollowCamera → UpdateAnimations
→ UpdateRootMotion → UpdateWorldTransforms → UpdateSkins
```

音频子步骤插在 **`UpdateWorldTransforms()` 之后、`Render3D()` 之前**：

```cpp
void Scene::OnUpdate3DSimulation(Timestep ts) {
    ...
    UpdateWorldTransforms();
    UpdateSkins();

    // —— 音频：必须拿到本帧最新 world 后才同步 Listener/Source 位置 ——
    UpdateAudio(ts);
}
```

生命周期接入：

```cpp
// Scene 构造：m_AudioWorld = std::make_unique<Audio::AudioWorld>(this);
// Scene 析构：m_AudioWorld.reset();  // 先于 m_Registry 清空

void Scene::Play() {
    ...
    if (m_AudioWorld) m_AudioWorld->OnPlay();   // 触发 PlayOnAwake
}

void Scene::Stop() {
    ...
    if (m_AudioWorld) m_AudioWorld->OnStop();   // 全部停掉，回 Edit 静音
}

// OnComponentAdded<T>：
//   若 T == AudioSourceComponent / AudioListenerComponent → m_AudioWorld->OnComponentAdded(entity)

// OnAudioSourceDestroyed / OnAudioListenerDestroyed：
//   注册 on_destroy 销毁回调（参考 OnRigidBodyDestroyed 模式）
```

**决策点**：首版只在 `Playing` 态发声（`UpdateAudio` 内 `if (m_SimulationState != Playing) return;`），编辑态不发声。编辑器"试听"按钮由面板直接调 `AudioContext`/`AudioWorld::RequestPlay` 作为例外，Play/Stop 不影响试听通道。

## 4. 阶段计划

| 阶段 | 内容 | 依赖 | 优先级 |
|---|---|---|---|
| **A** | 后端 + 资源管理器（能加载 WAV 并在编辑器任意处播放一次） | 无 | P0 |
| **B** | ECS 组件 + AudioWorld + Scene 生命周期（场景内 3D/2D 发声、Play/Stop） | A | P0 |
| **C** | Lua `audio.*` API + 序列化 + 编辑器属性面板/Add Component | B | P1 |
| **D** | 高级能力：流式大文件、混音总线、泛音/滤波、事件/播放完成回调和周边 | B/C | 按需 |

**推荐开工顺序：A + B 一起落地（AudioContext 一次性搭，AudioWorld 紧随），随后 C**。

### 4.1 阶段 A：后端 + 声音资源管理

- vendored `miniaudio.h`，新建 `GE/src/Audio/AudioContext.cpp` 唯一含 `#define MINIAUDIO_IMPLEMENTATION`。

  - 去重缓存 `unordered_map<std::string, shared_ptr<SoundAsset>>`；
  - 提供 `PlayOneShot(path, volume)` 直接试听（编辑器菜单用）。
- 验证：`GE_CORE_INFO` 打印设备名/采样率；临时在编辑器 `StatsLayer` 或工具栏放一个"Play Test Tone"按钮。

  - `m_AudioWorld` 成员；
  - `UpdateAudio(ts)` 子步骤（OnUpdate3DSimulation 内）；
  - `Play()/Stop()` 调用；

### 4.3 阶段 C：脚本 API + 编辑器

**Lua API（注入 `audio` 表，参考现有 `log/input` 注入方式）**：

```lua
-- 当前实体（挂脚本的实体）上的 AudioSource 操作；无组件返回 false/0
-- slot 可用索引（0 起）或 Name（"engine" 等）；缺省 = 全部槽位
audio.play(slot)                  -- 播放某个槽（restart = true）
audio.stop(slot)
audio.is_playing(slot)            -- bool；缺省 = 是否任一槽在播
audio.set_volume(slot, v)
audio.set_pitch(slot, p)
audio.set_loop(slot, on)

-- 可通过实体参数控制其它实体（Entity 表由现有 get_entity 返回）
audio.play(entity, slot)
audio.stop(entity, slot)
audio.set_volume(entity, slot, v)
audio.set_pitch(entity, slot, p)
audio.set_loop(entity, slot, on)
```

命令在脚本 `OnUpdate` 中写入 `AudioWorld` 命令队列，`UpdateAudio` 统一应用——保证空间位置同步在 WorldTransforms 之后。

### 4.4 阶段 D：高级能力（可选，按需求开工）

- **流式播放大文件**：`ma_sound_init_from_file` 用 `MA_SOUND_FLAG_STREAM`，适合 BGM 长音频。
- **混音总线/Master Group**：`ma_engine` 支持 Group，做 UI / 声音 / 音乐分组音量。
- **Doppler/Inertia**：`ma_sound_set_doppler_factor`、`ma_sound_set_3d_processing_enabled`。
- **播放完成回调**：倒查 `VoiceHandle → entt::entity`，派发 `OnAudioEnd(entity)` 到 ScriptEngine。
- **编辑器 Mixer/Channel 面板**：展示当前活跃 Voice、音量、播放状态。
- **多 Listener**：miniaudio 原生多 listener，首版只接 listener 0，代码按数组设计。

## 5. 风险与决策记录

| 决策 | 结论 |
|---|---|
| 音频后端选型 | miniaudio（单头文件、WASAPI、3D 内置） |
| AudioContext 归属 | Application（全局一份，不是 Renderer 也不是 Scene） |
| AudioWorld 归属 | Scene（每场景一份，平行 PhysicsWorld） |
| 组件运行时状态放哪 | AudioWorld 内部映射，不写回组件（保证组件纯数据、可序列化） |
| 空间位置同步时机 | `UpdateWorldTransforms()` 之后，保证使用本帧最新世界矩阵 |
| Edit 态是否发声 | 默认不发声；编辑器试听走独立命令通道 |
| 格式首版 | WAV（miniaudio 原生）；FLAC/MP3 以 miniaudio 内置 decoder 逐步开 |
| 多线程 | AudioContext 是唯一碰音频线程/后端；ECS 与命令队列全部主线程访问，`UpdateAudio` 统一转发 |
| 序列化 | 路径写相对 `audio/`，与 mesh/texture 一致；运行时句柄不序列化 |

### 主要风险

1. **miniaudio API 较粗、3D 参数多**：首版收敛到 `ma_engine` 高层接口，把 `Attenuation/Position/Velocity` 封在 `AudioContext` 内，避免业务层散落后端细节。
2. **多 Scene / 编辑器与 Play 切换**：AudioWorld 以 `m_SimulationState` 门控；编辑器试听与 Play 声音需要不同通道，否则 Stop 会误停试听。
3. **资源加载失败**：`LoadSound` 失败返回 `nullptr`，组件显示警告并静默，不 block 场景加载（与现有 Mesh/Texture 失败策略一致）。
4. **PlayOnAwake 时序**：`Scene::Play()` 里创建 Voice 时源实体 Transform 已备份完成，`UpdateAudio` 首帧就会写位置，无需特殊处理。

## 7. 验收标准（每阶段自测）

- **A**：`AudioContext::Init` 成功；`LoadSound("sfx/test.wav")` 返回非空；工具栏 One-Shot 能出声；App 退出无崩溃（Device 正确 uninit）。
- **B**：场景中 Add Audio Source + Audio Listener，Play 后资源发声；移动 Listener（相机/角色）音量随距离变化；Stop 后全部停止；保存/重载场景不丢组件。
- **C**：Lua 脚本可用 udio.play/stop/set_volume/set_pitch（支持槽位索引/Name）；编辑器面板可增删/编辑多个声音槽、可 Add；资源拖入正确写各槽 SoundPath。
- **D**（若做）：长音频不卡主线程；事件回调不阻塞主循环；多源同时播放 CPU/内存可控。
