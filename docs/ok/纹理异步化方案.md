# 纹理异步化实现方案

> 状态：**已实施**（3a/3b/3c 全部落地）
> 日期：2026-08-16
> 前置：`docs/异步上传方案.md`（AsyncUploadManager 骨架已实施并入 Renderer / AssetManager）

## 1. 背景与动机

当前 `Texture::LoadFromFile / LoadFromMemory / LoadCubeMapFromFile` 都是**同步阻塞**的：在主线程完成
stb_image / KTX 解码 + staging 上传 + fence 等待，加载大纹理（尤其 IBL 环境图 KTX cubemap）时主线程
整个卡住。

异步上传基础设施（`AsyncUploadManager`）已就绪并接入 `Renderer`（`BeginFrame` 调 `Poll()`）。本方案把
**纹理的加载迁到异步路径**：后台线程解码 + 上传，主线程每帧 `Poll()` 回收，资源就绪后自动可见。

## 2. 已拍板的设计方向

| 维度 | 决策 |
|---|---|
| 异步粒度 | 解码（stb/KTX）+ GPU 上传 全异步 |
| 内部结构 | **方案 A：后台建独立 image**，主线程 `Poll()` 注入 |
| 未就绪策略 | `IsReady()` 为 false 时渲染降级/跳过，就绪后自动亮相 |
| 线程安全 | 后台线程**只产出局部对象**（local VulkanImage / staging），绝不写 Texture 成员 |

## 3. 核心结构：后台建独立 image（方案 A）

```
主线程 LoadAsync(...)                       后台上传线程
  ├─ 创建"空壳" Texture                     │
  │    （m_Image 为空，m_Ready=false）       │
  ├─ 组装 UploadTask 提交给 AsyncUploadManager
  └─ 立即返回空壳 Texture ────────────────►  decode：stb/KTX 解码 → CPU 像素容器
                                              upload：创建 local VulkanImage + staging
                                                      录 copy + 布局转换；staging 交 task.staging
                                                      提交，等 fence（后台等，不卡主线程）
主线程 BeginFrame → Poll()
  └─ fence 完成 → task.finalize（主线程）
       ├─ 把 local VulkanImage 注入 m_Image
       ├─ 创建 m_ImageView + 请求 m_Sampler
       └─ m_Ready = true   ← 下帧渲染自动可见
```

**为什么后台建独立 image**：
- 后台线程完全操作自己的 local 对象，不持 `Texture` 裸指针 → 无 use-after-free
- local image 所有权由 pending 槽位托管，主线程 `finalize` 注入 → 无 GPU 泄漏
- 完全符合 `AsyncUploadManager` 的线程模型（后台只产出局部对象）

## 4. Texture 类改造

### 4.1 新增状态与访问器

- `std::atomic<bool> m_Ready{false};` + `bool IsReady() const`
- 未就绪时 `m_Image` / `m_ImageView` 为**空**（`nullptr`）

### 4.2 新增异步工厂（纯增量，保留同步工厂）

```cpp
// 返回空壳 Texture 并提交 UploadTask；就绪后主线程 Poll 时注入
static std::unique_ptr<Texture> LoadFromFileAsync(
    VulkanDevice &device, VulkanResourceCache &cache, AsyncUploadManager &upload,
    const std::string &filepath,
    vk::Format format = eR8G8B8A8Unorm,
    vk::Filter mag = eLinear, vk::Filter min = eLinear, bool gen_mips = true);
// 同理 LoadFromMemoryAsync / LoadCubeMapFromFileAsync
```

### 4.3 新增安装方法（主线程 Poll 调用）

```cpp
// 主线程：接收后台 local image，建 view/sampler，置 ready
void InstallAsyncImage(std::unique_ptr<VulkanImage> image, VulkanResourceCache &cache,
                       vk::Filter mag_filter, vk::Filter min_filter);
```

### 4.4 保留同步路径（零回归）

- 同步工厂 `LoadFromFile / LoadFromMemory / LoadCubeMapFromFile` 不变
- **直接构造**（空白纹理，`RenderTarget` 用）不变——它立即建 `m_Image`，不受异步影响
- 默认 / 纯色 1x1 纹理（`GetSolidColor`）保持同步立即就绪

### 4.5 访问器防御

未就绪时 `GetImageView()` / `GetSampler()` / `GetDescriptorInfo()` 返回空句柄；渲染端必须先 `IsReady()` 检查。

## 5. UploadTask 组装（decode / upload / finalize）

```cpp
AsyncUploadManager::UploadTask task;
// 捕获 CPU 数据容器（值捕获，后台解码结果写入）
auto bucket = std::make_shared<AsyncLoadData>();
task.decode = [bucket]{ stbi_load / ktxTexture ...  → bucket->pixels等 };   // 后台
task.upload = [&device, bucket, &texture](VulkanCommandBuffer &cmd) {
    // 创建 local VulkanImage（后台局部对象）
    auto image = std::make_unique<VulkanImage>(device, builder);
    // staging + copy + 布局转换（录进 cmd）
    task.staging = ...;   // staging 交 task 托管
    bucket->image = std::move(image);   // local image 暂存于 bucket
};
task.finalize = [&texture, bucket, &cache, mag, min]{
    texture.InstallAsyncImage(std::move(bucket->image), cache, mag, min);  // 主线程注入
};
upload.Submit(std::move(task));
```

## 6. TextureManager 改造

- 新增 `LoadAsync(...)`：创建空壳 Texture → 缓存 → 提交异步任务 → 返回未就绪指针
- 保留 `Load(...)`（同步）与 `GetSolidColor`（同步 1x1）
- 缓存仍按路径去重；未就绪条目也参与缓存查找（同路径只异步加载一次）
- `unload` 时：若该纹理仍在异步加载中，`finalize` 用 `m_Textures.contains(key)` 门控跳过注入

## 7. 渲染端接入

### 7.1 Renderer3D

- **默认/纯色纹理**（`GetSolidColor`、`LoadFromMemory` 的 1x1）**保持同步立即就绪**，是安全兜底
- `EndScene` 各 `GetEffective*Texture`：绑定时若 `!tex->IsReady()` → 降级为对应默认纹理
- 天空盒 / IBL：环境图未就绪则本帧不显示天空盒与 IBL

### 7.2 EnvironmentMap

- `LoadFromFiles` 改为异步加载三张图，`IsReady()` 门控
- `Renderer3D::SetEnvironment` 异步化：加载完成前 `m_EnvironmentMap` 为空，就绪后自动切换

### 7.3 MaterialManager / MeshManager

- 模型加载时对材质贴图调 `LoadAsync`；渲染时经 `Renderer3D` 的 `IsReady()` 门控兜底
- 材质对象本身不感知异步（它只持有 `Texture*`）

## 8. 生命周期与线程安全

| 风险 | 对策 |
|---|---|
| 后台线程写 Texture 成员 | 后台只产出 local image + staging，写入全在主线程 `finalize` |
| staging 提前释放 | `task.staging` 由槽位托管，fence 完成才释放 |
| unload 时异步加载中 | `finalize` 用 `m_Textures.contains(key)` 门控，已卸载则跳过注入；local image 所有权在 pending，无泄漏 |
| 渲染引用未就绪纹理 | 渲染端 `IsReady()` 检查，未就绪降级默认纹理 |
| 队列并发提交 | 已由 `VulkanQueue::Submit` 内部 per-queue 锁保证 |

## 11. 验证方式

- 加载大环境图（IBL）/大纹理：主线程不再长时间卡顿（帧率 / Profiler）
- 加载期间资源未就绪：网格可见但用默认纹理 / 天空盒暂不显示；就绪后下帧自动切换
- 快速 unload/reload 同一资源：无崩溃、无 use-after-free、无 GPU 泄漏
- 验证层开启：无队列并发、无生命周期相关报错
