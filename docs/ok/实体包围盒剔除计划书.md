# 实体包围盒（手动摆放）剔除计划书

> 状态：**已实现（待构建验证）**
> 目标：给蒙皮/动画角色补一级「实体级粗剔除」——编辑器用 gizmo 手动摆一个罩住动画全程的盒，盒在视锥外即整棵子实体连带剔除，把「屏幕外仍在渲染的动画角色」救回来。
> 前置：视锥剔除基线（`Scene::RenderMeshes3D`）、glTF 蒙皮/动画管线（阶段3/4）、编辑器 `GizmoController` + ImGuizmo、包围盒线框调试开关（提交 161ef54）
> 关联：`骨骼动画实现计划书.md`、`glTF接入.gemesh计划书.md`

---

## 1. 现状盘点：为什么蒙皮实体一帧都不剔

| 类型 | 剔除现状 | 原因 |
|---|---|---|
| **静态网格** | mesh 级 AABB（模型空间 `Mesh::GetAABB`）+ SubMesh 级 AABB 两级剔除 | 绑定盒固定，可可靠判定 |
| **蒙皮实体** | **整段跳过**（Scene.cpp RenderMeshes3D，`isSkinned` 时两级判定均豁免） | 绑定姿势静态 AABB 追不上动画变形，误剔 > 漏剔，宁可不剔 |

**结论文档载体**：蒙皮实体受力=零剔除。屏幕外的动画角色（NPC、背景人群、远处怪物）整帧白画顶点着色器 + 片元着色器，是当前剔除链唯一的空窗。

## 2. 需求与取舍（多轮讨论结论）

| 决策项 | 结论 | 理由 |
|---|---|---|
| **给谁补盒** | 只给含蒙皮的模型 | 静态网格 mesh AABB 已够用且更紧，补盒反而重复 |
| **盒的来源** | 编辑器 gizmo **手动摆放**，序列化进 .scene | v1 从简。离线烘焙动画全程盒（joint-box）或每帧关节盒都更重，留作后续（§8） |
| **挂在哪个实体** | **角色根实体**，判外连带整棵子树 | 用户选 B 方案：贴合「被剔除实体的子实体一起剔除」，一次摆盒罩整角色 |
| **盒的空间** | 模型局部空间（Center+Size），运行时 `× 世界矩阵` | 与现有 `meshAabb.Transformed(world)`（Scene.cpp:660）同构，动画发生在局部空间内部 |
| **遍历方式** | 保留扁平 `meshView` 循环 + **预扫描**子树收割 | 绘制路径零改动、风险最低（扁平 vs 层次 DFS 的权衡见 §5.2） |

**正确性前提**：盒必须罩住动画**全程**的伸展范围，不是 bind pose。角色抬手/踢腿不得穿出盒外——否则视为「判断在屏外但从屏幕内伸出来」，裸奔不剔。

## 3. 核心决策

### 3.1 数据：`BoundingBoxComponent`

新组件（Components.h，SpriteRenderer 同构）：

```cpp
struct BoundingBoxComponent {
    glm::vec3 Center = {0.0f, 0.0f, 0.0f}; ///< 局部空间中心
    glm::vec3 Size   = {0.0f, 0.0f, 0.0f}; ///< 局部空间边长（任一轴 <= 0 视为未摆放）
    bool IsValid() const { return Size.x > 0.0f && Size.y > 0.0f && Size.z > 0.0f; }
    glm::vec3 minCorner() const { return Center - Size * 0.5f; }
    glm::vec3 maxCorner() const { return Center + Size * 0.5f; }
};
```

- **用 Center+Size 而非内嵌 `AABB`**：Components.h 是核心头，不引入 `Render/Mesh.h` 的完整类型（保持轻依赖、避免 include 膨胀）。运行处用 Mesh.h 的 `AABB::Transformed` 组装变换。
- **IsValid 语义**：默认 0 尺寸 = 未摆放 = 不参与剔除。新 Add 的组件默认无效，须手动给尺寸 → 向后兼容（旧场景无此组件零影响）。
- 无 `OnComponentRemoved` 清理诉求，纯数据组件；仅需补一个 `OnComponentAdded<BoundingBoxComponent>` 空特化（`Entity::AddComponent` 会无条件调用，缺了编译失败）。

### 3.2 挂载实体与剔除语义：子树级盒

盒子所在实体须是该角色子树的**公共根**（角色根或含蒙皮的 mesh 实体均有效——根更贴合）。剔除语义两段式：

1. **任何实体上的 `BoundingBoxComponent` 判外 → 该实体整棵子树连带剔除**（挂在根即整角色；挂在子组即子组）。
2. 判内/相交 → 下钻，叶子照旧逻辑：**静态 mesh 继续逐网格/子网格剔除**；**蒙皮叶子无盒仍不剔**（保守）。

这使「A 方案（挂蒙皮 mesh 实体各剔各的）」成为 B 方案的特例，一套代码覆盖两种挂法。

### 3.3 无盒场景零损耗

`m_Registry.view<BoundingBoxComponent>()` 判空后跳过整个预扫描，小型/纯静态场景成本为零。

## 4. 剔除层：RenderMeshes3D 改动

在视锥建立（`const Frustum frustum = ...`）之后、扁平 `meshView` 循环之前插入**预扫描**：

```
subtreeRejected = {}
若有任何 BoundingBoxComponent：
  以 m_ChildrenOf 为边、Transform.parent==null 的实体为根 DFS：
    节点盒（无效盒不算）经世界矩阵变换后视锥完全在外
      → 节点 + 全部后代收进 subtreeRejected，不再下钻
    否则下钻子节点
循环首行：if (subtreeRejected.count(entity)) continue;   // 整棵被盒剔除
```

要点：
- DFS 沿 `m_ChildrenOf`（与 `UpdateWorldTransformsRecursive` 同一棵子树结构和根集定义）。
- 盒子变换 = `AABB(盒 min/max).Transformed(实体 GetWorldMatrix())`，`frustum.IsVisible` 判定，全部复用既有 API。
- 递归用 Y-combinator 式泛型 lambda，`<functional>` 零依赖。
- 蒙皮/静态叶子的后续网格级、子网格级判定原样不动，盒只负责「整棵粗筛」。

### 5.2 为什么不做全面层次 DFS

讨论过「扁平 vs 层次遍历」：全面 DFS 会替换掉现有绘制循环（skin 上传、子网格剔除、材质覆写那段 50 行逻辑），命中树遍历的指针追逐与乱序。**预扫描 + 扁平循环**语义等价（父盒判外 = 子树在扁平循环首行被跳过），但与现有绘制路径解耦，风险最低。代价是每帧多 O(节点数) 的预扫描——与现有世界矩阵 DFS 同量级（§3.3 已兜底无盒零损耗）。将来若收益需要，可随时把预扫描并入世界矩阵 DFS 合成一趟（§8）。

## 5. 序列化层：.scene 存读

SceneSerializer.cpp 两方向各加一个块（仿 BoxCollider）：

- **Serialize**：`entityNode["BoundingBox"]`，写 `Center` / `Size`（`SerializeVec3`）。
- **Deserialize**：`if (entityNode["BoundingBox"])`，`AddComponent<BoundingBoxComponent>` + 读回（`DeserializeVec3`）。

旧场景文件无该节点 → 不加组件，向后兼容。盒随 .scene 持久化，重载不丢。

## 6. 编辑器层

### 6.1 组件登记与属性面板（SceneHierarchyPanel）
- `DrawComponents` 加 `DrawComponent<BoundingBoxComponent>("Bounding Box", ...)` 行；
- `DrawAddComponentPopup` 加 `TryAddComponent<BoundingBoxComponent>("Bounding Box")`；
- `DrawBoundingBoxComponent`：两个 `DrawVec3Control` 画 Center / Size；无效（未摆放）时提示。

### 6.2 gizmo 编辑（GizmoController）
- 工具条新增 **Box** 开关 + `B` 快捷键切换**包围盒编辑模式**（`m_EditingBounds`），选中实体无组件时置灰。
- 进入模式后隐藏变换 gizmo，改调 `EditBounds`：
  - 复用 **ImGuizmo 的 `localBounds` 模式**（`Manipulate` 第 8 参数，`HandleAndDrawLocalBounds` 原生画虚线盒 + 角点/边中点手柄），**无需自写盒拖拽**。
  - 手柄矩阵 = 平移(盒世界中心) × 实体世界朝向（列归一化剥离世界缩放）——拖拽沿**模型轴**进行，保证盒在模型局部保持轴对齐。
  - `localBounds` 传 ±Size/2；拖完从输出矩阵**列模长 = 每轴缩放系数**、**平移 = 新世界中心**还原局部 Center/Size 写回。
  - 尺寸下限钳制 0.05，防止缩成退化和反向盒（`IsValid()` 失效会使剔除静默失效）。
  - 未摆放盒进入编辑模式时自动给 1m 单位盒起步。

### 6.3 视口线框预览（SceneLayer）
`DrawWorldBounds` 抽出共用 `drawWorldAabb` lambda（世界 AABB → 投屏 12 条 `AddLine`，沿用 `ProjectWorldToScreen` + OpenGL 投影还原），除既有静态网格灰蓝盒外，**叠画所有有效 `BoundingBoxComponent` 的黄盒**，随「显示包围盒」开关一起显示。

为直接回答「一个方向看不出角色是否完全被盒罩住」，黄盒附加两层可视化：
- **半透明盒面**：6 面 `AddConvexPolyFilled`，面法线朝向相机（外表面）更亮、背向更暗，单视角也能分辨前后重叠与深度；
- **关节露点**：沿盒所在实体子树（`Scene::GetChildren` 递归）收集全部蒙皮关节（`SkinDef::joints` 的真实实体），取世界矩阵平移列即骨骼枢轴点，逐帧投影到盒判断：**盒内绿点 / 盒外红点**。角色动起来时哪些骨头伸出盒一眼可见。关节是点不是顶点面，故为即时轻量检查，非最终校验。

## 8. 边界与已知限制

| 项 | 说明 | 处理 |
|---|---|---|
| **动画幅度超盒** | 以后新加幅度更大的动画剪辑，手动盒可能盖不住 → 肢体穿出盒外裸奔"不剔" | 手动重摆盒；或后续换烘焙盒（见预留） |
| **盒摆错（过小）** | 父盒判外 → 整棵子树被连带跳过，极端摆错会把屏内角色剔掉 | 编辑期黄线框对照；v1 手动环节固有风险 |
| **静止角色** | 屏幕内静止角色其盒可能在屏外被剔——只要盒盖住动画全程就不会误判 | 依赖正确摆放 |
| **旋转/缩放父实体** | 盒 × 世界矩阵变换自带旋转/非均匀缩放处理（`AABB::Transformed` 的 |R| 法） | 无额外处理 |
| **视口无拾取** | 视口点击选择实体未实现（仅层级树可选中） | 不阻塞此特性；作为编辑器增强后续项 |
| **盒数量** | 每 `BoundingBoxComponent` 都做一次完整视锥测试，量大时预扫描粒度过细 | 数量级是「角色/组」数量，可接受；极端场景再按根聚合 |

## 10. 验收标准

- 编辑器给一个蒙皮角色加 `BoundingBoxComponent`，黄盒线框叠出；`B` / Box 进入编辑，拖角/边实时改盒尺寸与中心，盒保持模型轴对齐。
- 保存 .scene → 清场景重载 → 盒 Center/Size 不变，剔除行为一致。
- 运行时：把带盒角色整体移到视锥外 → 该角色全部蒙皮 mesh 一帧止绘；移回视锥内 → 恢复绘制。无盒角色（或盒无效）行为与改动前**逐帧等价**（回归判定）。
- 「显示包围盒」下黄盒与网格红/灰蓝盒同时可见，静态场景无任何盒组件时预扫描零开销（无回归）。

## 11. 与现有方案衔接

- **蒙皮动画管线**：不改 `SkinDef` / `UpdateSkins` / 蒙皮叶子判定，盒只在更上层粗筛，蒙皮跳过语义保持不变（无盒仍不剔）。
- **.gemesh / .geanim 烘焙**：不动烘焙格式；阶段 2 若上烘焙盒再扩展 .geanim（version 1→2）。
- **ImGuizmo**：仅新增 `localBounds` 参数用法（仓库此前从未使用该能力），不动第三方源码。
