# 编辑/运行时物理分离计划书（Edit · Play）

> 状态：**计划中（未开工）**。前置已完成：物理事件阶段 A/B（`动画物理事件脚本桥接计划书`）落地——`StepPhysics` 尾部已按实体派发碰撞事件到脚本；`PhysicsWorld`（固定 60Hz 步进 + 待创建列表 + Body↔实体映射 + 环形缓冲）与脚本钩子完备；编辑器碰撞体线框可视化（`显示碰撞体`）与包围盒线框已在 `SceneLayer`。
> 目标：把「编辑器与运行时物理」分离开——**Edit 态静止可摆、Play 态模拟、Stop 干净回位**。目前 `Scene::OnUpdate3D`（Scene.cpp:505）每帧无条件 `StepPhysics`，编辑态给实体加 `Dynamic` 刚体立刻下落，无法摆放场景；碰撞事件也在编辑态就触发（脚本在 Edit 态误收到 Enter/Stay/Exit）。
> 定位：纯场景层状态机 + 编辑器 UI；渲染 / 动画 / 输入 / `GE/Events` 零改动。本计划是 `物理系统增强计划书.md §5 阶段 C` 的独立落地细化，不新增能力面。

---

## 0. 一句话架构

```
Scene::SimulationState（Edit / Playing）
  ├─ StepPhysics 门控：仅 Playing 步进 → 编辑态静止、碰撞事件只在 Play 派发
  ├─ Play()  ：flush 全部"有 RigidBody+碰撞体 未初始化"实体 → 首帧建体 → 备份 Transform 快照
  └─ Stop()  ：销毁全部 body + 清 pending → 回滚 Transform 快照 → 回到编辑摆放姿态
编辑器工具条：▶ Play / ⏹ Stop 按钮（Play 时视口标题"▶ 运行中"）
```

**关键约束**：Edit 态不建 body、不步进；Play 态从实体当前 Transform 建体并激活。确保"编辑时实体可自由摆放、运行时由物理接管、Stop 后回到摆放姿态"三者闭环。

## 1. 现状盘点与差距定位

| 能力 | 现状 | 本次改动 |
|---|---|---|
| 运行态 | **无**（全仓 grep 无 `IsPlaying/SimulationState/Play`） | 新增 `SimulationState`（Edit/Playing） |
| 物理步进 | `OnUpdate3D` 每帧无条件 `StepPhysics`（Scene.cpp:517） | `StepPhysics` 门控到 Playing |
| 编辑态加 Dynamic | 立刻下落，无法摆放 | Edit 态无 body（pending 积压），静止悬停 |
| 碰撞事件 | 编辑态也派发（`StepPhysics` 尾部已接，仍每帧跑） | 门控后仅在 Play 派发（顺带修掉"编辑态误触发"） |
| body 生命周期 | 组件添加即 `RequestCreateRigidBody`，首帧建体 | Play 建 / Stop 销毁，编辑态挂起 |
| Play 后恢复摆放 | 无（动态体世界被模拟写乱） | Stop 回滚 Transform 快照 |

本次只做上表全部行；Play 中 gizmo 禁用、脚本查询 `IsPlaying()`、多场景各自运行态等放 §4 路线图。

## 2. 总体设计

### 2.1 状态机（Scene）

```cpp
/// 模拟运行态：Edit = 编辑器编辑，Playing = 运行时模拟
enum class SimulationState : uint8_t { Edit, Playing };

bool IsPlaying() const { return m_SimulationState == SimulationState::Playing; }

/// Edit → Playing：flush 未初始化刚体、记 Transform 快照。重复进入 -> 无操作（已 Playing）。
void Play();

/// Playing → Edit：销毁全部 body、清 pending、回滚快照。Edit 态调用 -> 无操作。
void Stop();
```

默认 `m_SimulationState = Edit`；**不序列化**（加载后恒为 Edit，见决策 5.5）。

### 2.2 步进门控

```cpp
void Scene::StepPhysics(Timestep ts) {
    if (m_SimulationState != SimulationState::Playing) return; // 编辑态物理整体停摆
    if (!m_PhysicsWorld) return;
    // …既有：SetStayEnabled → Step → TakeCollisionEvents → 双侧派发（原样，事件顺带仅在 Play 派发）
}
```

Edit 态不做的事：`Step`（含 `ProcessPendingBodies`/`SyncBodiesToTransforms`）**全部不执行** → 无步进、无碰撞事件、动态体不被 Jolt 写回、pending 列表积压不建体。

**动画事件不受门控**：`UpdateAnimations` 独立于 `StepPhysics`，编辑态播放/Scrubber 预览照旧触发 `OnAnimationEvent`（决策 5.6 说明取舍）。

### 2.3 body 生命周期（核心设计）

**Edit 态（不建）**：`RequestCreateRigidBody` 仍随组件添加被调用，但 `StepPhysics` 不跑 → `ProcessPendingBodies` 永不执行 → body 不建、实体自由编辑（Transform 无 body 冲突）。碰撞体线框 `DrawColliders` 直接读 `TransformComponent` + 碰撞体组件（SceneLayer.cpp:601），无需 body，编辑态仍可预览线框。

**Play()（建）**：
1. 备份 Transform 快照（见 2.4）；
2. flush：遍历 `view<TransformComponent, RigidBodyComponent>`，对 `!rbc.IsInitialized` 的实体补 `RequestCreateRigidBody`（防"组件已加但从未请求"的漏；pending 已有者去重后自然无操作）；
3. 首帧 `Step` 内 `ProcessPendingBodies` 建立全部 body；静态/运动学停置、动态激活开始模拟。
4. **首帧防抖**：Play 按下瞬间在 UI 线程立刻 `SyncBodiesToTransforms()` 一次——body 初始位与实体当前位对齐，避免"按 Play 画面抖一下"（物理计划 §5.2 已指出）。

**Stop()（毁 + 回滚）**：
1. 遍历 `view<RigidBodyComponent>`，对 `IsInitialized` 调用 `DestroyRigidBody`（既有：`RemoveBody`+`DestroyBody`+清组件标记）；
2. 清空 pending（新增 `PhysicsWorld::ClearPendingBodies()`，编辑态新加未建/Play 后又加的都清掉）；
3. 回滚 Transform 快照（2.4）→ 实体回到播放前摆放姿态。

**Play 期间**：工具条按钮变 ⏹ Stop；动态体位置由 Jolt 写回 `TransformComponent`，gizmo 拖拽不生效（阶段路线图 §4）。

### 2.4 Transform 快照与回滚

```cpp
struct PlayTransformSnapshot { entt::entity e; glm::vec3 translation; glm::quat rotation; };
std::vector<PlayTransformSnapshot> m_PlaySnapshot; // Play() 填、Stop() 用，仅内存不序列化
```

- **Play() 时**：遍历 `view<TransformComponent, RigidBodyComponent>`，把 (Translation, Rotation) 存入快照（静态体也在内——静态位置不随模拟变，存了无害）。
- **Stop() 时**：逐条写回实体 `TransformComponent`；随后下帧渲染自会 `UpdateWorldTransforms` 重建 world。
- 快照与 body 销毁次序：**先销毁 body、再写回 Transform**——避免写回时 Jolt 还在跑（Stop 时无步进，顺序不敏感，但保持"毁干净再摆回"语义）。

### 2.5 编辑器 UI（SceneLayer）

在 `SceneLayer.cpp:291` 起的 SceneLayer 窗口顶部加运行控制行：

- **Edit 态**：按钮 **▶ Play**；点击 → `m_Context->Scene->Play()`；下方提示"编辑中（物理静止）"。
- **Playing 态**：按钮 **⏹ Stop**；点击 → `Stop()`；视口标题叠显 **"▶ 运行中"**（复用窗口标题或叠加文本）。
- 与 `显示包围盒/显示碰撞体` 等调试开关并列（`SceneLayer.cpp:313-318` 附近）；键盘快捷键 F5（Play）/ F8（Stop）可选。

### 2.6 对既有链路的影响面

```
OnUpdate3D
  ├─ UpdateScripts       不动（脚本每帧照常，即使 Edit）
  ├─ StepPhysics         ★ 门控：Edit 不步进（顺带：碰撞事件只在 Play 派发）
  ├─ UpdateAnimations    不动（编辑态预览照旧；动画事件照旧触发，见决策 5.6）
  ├─ UpdateWorldTransforms 不动（Stop 回滚后下帧自动重建 world）
  └─ 渲染                不动
```

脚本输入快照、相机、`GE/Events` 不动。

## 3. 阶段实施

依赖极浅，整体可一次 PR 落地（阶段 A/B 顺序实现、同一提交或分两提交均可）。

### 阶段 A：状态机 + 门控 + 工具条（最小闭环）

**目标**：编辑态物理静止、事件不刷；Play/Stop 可切。

- **A1.** `Scene.h/.cpp`：`SimulationState` + `m_SimulationState` + `IsPlaying()` + `Play()`/`Stop()`（此阶段 Play/Stop 只切状态）；`StepPhysics` 顶部门控。
- **A2.** `SceneLayer`：▶ Play / ⏹ Stop 按钮 + Play 时标题"▶ 运行中"；Play 中禁用 gizmo 拖拽（`GizmoController` 或 `SceneLayer` 处按 `IsPlaying` 短路）。
- **A3.** 序列化：不写运行态字段；加载后恒 Edit（旧场景文件照常）。

**退出标准**：
- 编辑器给悬空实体加 Dynamic：Edit 态静止悬停，不下落。
- 勾"显示碰撞体"线框正常（body 未建也不依赖）。
- 编辑态**无**碰撞事件日志；挂 `collision_demo.lua` 后点 Play 才有 Enter/Stay/Exit。
- Play 中拖动 gizmo 无效（动态体被物理拉回）；Stop 后按钮复原。

### 阶段 B：body 生命周期 + 快照回滚

**目标**：Play 建体从当前位、Stop 销毁并回到摆放姿态。

- **B1.** `PhysicsWorld`：加 `ClearPendingBodies()`（停用后清空待建列表）。
- **B2.** `Scene::Play()`：快照（2.4）→ flush 未初始化刚体 → 立即 `SyncBodiesToTransforms()` 防抖。
- **B3.** `Scene::Stop()`：遍历销毁全部 body → `ClearPendingBodies()` → 逐条回滚快照。
- **B4.** Play 期间新增刚体组件/改碰撞体：不即时生效（下轮 Edit 再改，文档注明）。

**退出标准**：
- Edit 摆好悬空动态盒（静态地板 + 动态盒）：Play 开始下落；Stop 回到 Play 前位置、完全静止、事后可再编辑。
- 加载场景 → 直接 Stop（未 Play）无副作用；再 Play 正常。
- 连续 Play→Stop→Play 数次：位置一致、无残留 body（`view<RigidBodyComponent>` 全部 `!IsInitialized`）、pending 为空。
- 保存→加载后仍为 Edit 态；既有 2.scene 行为不回退。

## 4. 明确不做（本计划范围外）

- **运行时与编辑器相机分离**（进 Play 换成玩家相机）：玩法相机（第一/第三人称）是后续阶段 F/角色控制的独立目标，本计划沿用编辑器相机路径。
- **Play 中现场编辑刚体/Shape 并热生效**：属 `RebuildRigidBody` 运行时路径，物理计划阶段 E 再定。
- **物理插值（渲染 α 插值）**：物理系统增强计划书阶段 F，按需。
- **深拷贝场景作为 Play 沙盒**：Unity 式"Play 用副本、Stop 整个丢弃"，代价高；我们选轻量快照回滚（决策 5.1），不搬场景数据。

## 5. 决策记录（编码前拍板）

**5.1 回滚方式 —— ✅ 已定：Transform 快照回滚，不做场景深拷贝**
- 只存 (Translation, Rotation) 一组 `vector`，Stop 写回。Unity 的"Play 用副本"在 ECS + Vk 管线里代价高得不成比例；快照覆盖了"摆好→试→回位"的实际需求。

**5.2 body 生命周期 —— ✅ 已定：Edit 不建、Play 建、Stop 毁**
- Edit 态不建 body 才能让 Transform 自由编辑无冲突，也是门控的自然结果。线框预览读组件不读 body，不受影响。

**5.3 StepPhysics 整体门控，而非只门控内部某段 —— ✅ 已定**
- 整段（含 `ProcessPendingBodies`/事件派发/动态体写回）在 Edit 全停，行为才自洽；拆段容易出"建了体却不模拟"的中间态。

**5.4 Play 中禁用 gizmo —— ✅ 已定：按 `IsPlaying()` 短路**
- 动态体每帧被物理写回 Transform，拖了也白拖还制造困惑；显式禁用 + 文档注明。

**5.5 运行态不序列化 —— ✅ 已定：加载后恒 Edit**
- 运行态是瞬态，落盘无意义；保存时若正在 Play，落盘 Transform 是模拟后的混乱值——故**保存一律按 Edit 视角**（即保存前的摆放姿态语义，Stop 后再存场景是常规操作）。

**5.6 动画事件编辑态照常触发 —— ✅ 已定不等同物理门控**
- 动画是场景预览的一等公民（Scrubber/播放预览），编辑态触发 `OnAnimationEvent` 可接受；脚本如要"仅在 Play 生效"可等阶段 C 的 `IsPlaying()` 查询。物理事件却绝不能编辑态触发（碰撞是模拟产物）。两类语义不同，分开处理，不因物理门控误伤动画。

**5.7 快照只存带 RigidBody 的实体 —— ✅ 已定**
- 无刚体实体 Transform 编辑不受物理影响，无需回滚；带刚体实体存档（含静态，位置本不变、存了无害）。
