# 透明物体渲染计划书

> 状态：**阶段 1-3 已落地 2026-09-04 / 阶段 4（排序精度）待定**
> 目标：给渲染器增加画透明物体的能力 —— 支持 **alpha 混合（BLEND）** 与 **alpha 测试（MASK）** 两种半透明形态，并贯通 glTF 的 `alphaMode` 语义。
> 前置：`Mesh类拆分重构方案.md`（instancing 批处理已就位）、glTF 导入管线（阶段2 已可用）
> 关联：`IBL实现方案.md`（PBR-IBL 变体管线与本方案同一机制扩展）、`延迟渲染方案计划书.md`（Blend 与 Opaque/Mask 的前向/延迟分派以此语义为依据）

---

## 1. 现状盘点：为什么现在画不了透明物体

| 层 | 现状 | 阻塞点 |
|---|---|---|
| **材质** | `Material::alphaTest`（bool）、`doubleSided`（bool）已声明但引擎内**未接线**（grep 无引擎调用）；无透明/alphaMode 概念 | 没有"材质是否透明"的判定来源 |
| **着色器** | `mesh.frag` / `mesh_pbr.frag` / `mesh_pbr_ibl.frag` 全部硬编码 `outFragColor = vec4(result, 1.0)` | 采样了 `texColor.a` 但丢弃，alpha 恒为 1 |
| **渲染状态** | `ConfigureMeshPipeline` 一律设置不透明混合（全通道写入、blend 关、深度写开） | 无 alpha 混合路径 |
| **排序** | `SortKey` 升序 = 从近到远（early-z 优化） | 透明物体必须**从远到近**，方向相反 |
| **管线路由** | `pipelineId` 只区分 Blinn/PBR/PBR-IBL | 混合状态进管线 hash，透明需要独立管线变体 |
| **glTF** | tinygltf 已解析 `alphaMode`/`alphaCutoff`，`baseColorFactor` 只取了 RGB | 值未消费，导入即丢失 |

**结论**：透明支持不是加一个开关，而是「材质语义 + 着色器输出 + 管线状态 + 排序」四处联动的完整小特性。本方案逐层打通。

---

## 2. 核心决策：对齐 glTF 的 AlphaMode

直接采用 glTF 的 `alphaMode` 三态模型，不发明自定义枚举：

| AlphaMode | 渲染路径 | 深度写 | 混合 | 排序 |
|---|---|---|---|---|
| `Opaque`（默认） | 不透明 pass（= 现状） | 开 | 关 | 从近到远（early-z） |
| `Mask` | 不透明 pass | 开 | 关 | 从近到远 |
| `Blend` | **透明 pass**（新） | **关** | **开**（SRC_ALPHA / ONE_MINUS_SRC_ALPHA） | **从远到近** |

要点：
- **Mask ≠ Blend**。Mask 是"裁剪树叶/铁丝网"用的，片元被 `discard`，仍是**不透明**物体（深度写开、不混合、占 early-z 深缓冲）；只有 Blend 才是真正的半透明。
- **per-instance 透明度无需新 API**。`DrawMesh(transform, mesh, mat, {1,1,1,0.5})` 的 `color.a` 现有实例数据已携带，着色器把 `texColor.a × inColor.a` 输出为片元 alpha 即可。透明判定来自**材质**，实例只提供 alpha 值。
- **不引入 OIT**（order-independent transparency）。v1 采用标准 back-to-front 排序 + alpha 混合，OIT 作为未来章节预留（见 §7）。

## 3. 数据层：Material 扩展

> **阶段 1 已落地（2026-09-04）**：`Material::AlphaMode`（Opaque/Mask/Blend）+ `alphaMode` + `alphaCutoff` 已入 `Material.h`（渲染状态区），`alphaTest` 已删除；glTF `alphaMode/alphaCutoff/doubleSided` 与 `baseColorFactor[3]` 已在 `GLTFLoader::AppendGLTFMaterial` 消费并经 `MeshManager::ApplyMaterialData` 透传；OBJ 侧按 `dissolve<1` 推断 Blend。编辑器两面板的 Alpha 测试 checkbox 已换为 Alpha Mode 下拉 + Cutoff 滑条。

`Material.h` 改动（增删字段，已实现）：

```cpp
/// 透明模式（与 glTF alphaMode 对齐）
enum class AlphaMode {
    Opaque,   ///< 不透明（默认，忽略 alpha）
    Mask,     ///< alpha 测试：低于 alphaCutoff 的片元 discard
    Blend,    ///< alpha 混合：半透明，深度不写
};

AlphaMode alphaMode = AlphaMode::Opaque;   ///< 透明模式
float     alphaCutoff = 0.5f;              ///< MASK 裁剪阈值（glTF 默认 0.5）
```

- **删除** `alphaTest` bool（引擎内无任何调用点，直接迁移为 `alphaMode`；杜绝两个并存语义互相打架）—— 已完成。
- `alphaCutoff` 同步到使用处的 shader 由 MaterialUBO 承载（见 §4，**待阶段 2 实施**）。
- `doubleSided` 保留，**阶段 1 顺带接线**：GLTFLoader/OBJLoader 已透传到 `Material::doubleSided`；剔除状态作为动态状态接线放 §8 阶段2。

> 决策依据：glTF `Opaque/Blend` 的取舍里，半透明材质的 `baseColorFactor[3]` 就是材质级基础 alpha，叠加 per-instance tint alpha 二者相乘，语义自洽。

## 4. 着色器层：输出 alpha + MASK 裁剪

三份片元着色器（`mesh.frag` / `mesh_pbr.frag` / `mesh_pbr_ibl.frag`）做同一处收尾修改：

```glsl
void main()
{
    vec4 texColor = texture(samplerColor, inUV * material.params.w, 0.0);
    // ... 现有光照计算得到 result ...

    // —— 透明度 ——
    float alpha = texColor.a * inColor.a;                     // 纹理 alpha × 实例 tint alpha
    // MASK 裁剪：alphaCutoff 存于 material.params.z（原"预留"字段，Opaque/Blend 传 -1 禁用）
    if (material.params.z >= 0.0 && alpha < material.params.z) discard;
    outFragColor = vec4(result, alpha);
}
```

设计要点：
- **不需要 shader 变体**。是否混合由**管线混合状态**决定（属渲染状态、进管线 hash），不着色器；shader 只需恒输出真 alpha。`Opaque` 模式下混合关、alpha 值写的是画布无关紧要，无副作用。
- `material.params.z`（原 `MaterialUBO.params.z 预留`）复用为 `alphaCutoff`：Opaque/Blend 填 `-1` 关闭 discard，Mask 填实际阈值。**C++ 与 GLSL 布局零改动**（`MaterialUBO` 48 字节不变）。
- 需重编译 `mesh.frag.spv` / `mesh_pbr.frag.spv` / `mesh_pbr_ibl.frag.spv`（build 脚本产物，见 `assets/shaders/glsl/CMakeLists.txt`）。
- 已知取舍：MASK 的 `discard` 会**禁用 early-z**（深度测试已做但片元仍进 PS），是 glTF 标准行为的固有损耗，仅影响 MASK 物体的裁剪耗时。

## 5. 渲染层（核心工作量）

### 5.1 排序键：加 pass 分区 + 透明深度反向

`Renderer3D::SortKey`（Renderer3D.h:75）新增字段并调整比较序：

```cpp
struct SortKey {
    uint8_t  pipelineId = 0;   ///< 管线 id（Blinn=0 / PBR=1）
    uint8_t  passId     = 0;   ///< 渲染段：0=不透明，1=透明（分区：不透明全部先画）
    uint64_t materialId = 0;
    uint64_t meshId     = 0;
    uint64_t submeshId  = 0;
    uint32_t depthBits  = 0;   ///< view 距离位模式（透明段取反，见下）
    // operator< 顺序：pipelineId → passId → materialId → meshId → submeshId → depthBits
};
```

`ComputeSortKey`（Renderer3D.cpp:363）改动：

```cpp
const bool transparent = material && material->alphaMode == Material::AlphaMode::Blend;
key.passId = transparent ? 1 : 0;
uint32_t dist = std::bit_cast<uint32_t>(-viewPos.z);   // 距离，越大越远
// 不透明升序 = 近→远（early-z）；透明按位取反 → 分区内升序 = 远→近
key.depthBits = transparent ? ~dist : dist;
```

正确性：正浮点位模式随值单调递增，`~dist` 保持单调**递减**映射，透明分区内部升序排列即"远→近"；`passId` 保证 MASK/Opaque 全部先于 Blend，天空盒背景层的深度不被透明覆盖顺序影响。

### 5.2 批处理：透明逐实例，禁止 instancing 合批

`CollectBatches`（Renderer3D.cpp:489）现在把「同 material+同 mesh+同子网格」连续实例合并为一个 instanced batch——这对透明是**错的**：

> 同一个 batch 会被一次性绘制，其内部实例的深度排序被"压扁"成批次位置。当同材质同 mesh 的远、近两个实例之间穿插了**别的材质**的透明物体时，正确顺序需要跨 mesh 交错插值，instancing 做不到。

v1 决策：**透明实例一律单独成批**（`instanceCount = 1`）。改动极小：

- `CollectBatches` 扫描区间时，`material->alphaMode == Blend` 的实例**不合并相邻同键实例**，每个自身一批；
- 不透明实例合并逻辑保持不变（现库合批收益不回归）。
- 实例 SSBO **一次上传全部**（透明批次通过 `firstInstance` 指向同一缓冲的子区间），不透明 / 透明两段共享。

> 理由：半透明物体通常数量少、draw call 成本可忽略，换来的是正确性零妥协。后续若出现大量透明物体，再上"同深度桶合并"或 OIT（§7）。

### 5.3 双 pass：不透明段 + 透明段

`EndScene`（Renderer3D.cpp:396）在**同一个动态渲染 pass 内**（`BeginDynamicRendering` … `End` 不拆开），把网格绘制拆成两段：

```
BeginDynamicRendering（清屏一次）
  DrawSkybox                       // 背景 → 深度缓冲先被网格写
  ── 段 1：不透明 pass ──
  ConfigureMeshPipeline            // 混合关 + 深度写开（= 现状）
  BindSharedUniforms
  DrawMeshInstances(opaqueBatches)
  ── 段 2：透明 pass ──
  ConfigureTransparentPipeline     // 混合开(SRC_ALPHA/ONE_MINUS_SRC_ALPHA) + 深度测试开(Less) + 深度写关
  DrawMeshInstances(transparentBatches)
VulkanRenderingInfo::End
```

机制依据（已确认）：
- `VulkanCommandBuffer` 把状态累积在 `m_PipelineState`，`Draw` 时按**状态 hash** 请求管线（VulkanCommandBuffer.cpp:372）。混合状态参与 hash（VulkanPipelineState.cpp:638）。
- 段 2 只需在执行前改 `setColorBlendAttachments`（blend on + 因子）+ `setDepthWriteEnable(VK_FALSE)`，首次 `Draw` 即触发**新的透明管线变体**创建，同 layout 下由资源缓存去重。需要变体的管线：Blinn / PBR / PBR-IBL 各一透明实例，数量翻倍但可控。
- 深度测试仍为 `Less` 保持：透明片元正确被不透明深缓冲遮挡；透明之间退化为按绘制序混合（标准局限）。

混合因子（straight alpha）：

```cpp
blendState.blendEnable = VK_TRUE;
blendState.srcColorBlendFactor = vk::BlendFactor::eSrcAlpha;
blendState.dstColorBlendFactor = vk::BlendFactor::eOneMinusSrcAlpha;
blendState.srcAlphaBlendFactor = vk::BlendFactor::eOne;            // 直通 alpha 路径
blendState.dstAlphaBlendFactor = vk::BlendFactor::eOneMinusSrcAlpha;
```

`ConfigureMeshPipeline`（Renderer3D.cpp:700）拆出一个带参版本（`bool transparent`）或独立 `ConfigureTransparentPipeline`，避免大函数继续膨胀（延续近期 EndScene 拆子步骤的既有方向）。

### 5.4 其余外围

- `RecordStats`：统计两段批次数之和（draw call = 不透明批 + 透明批）。
- `EndScene` 早退语义（天空盒/网格各自判断）不受影响：透明段仅在 `transparentBatches` 非空时执行。
- `GetPipelineId` 不变——透明体现在 `passId`，不与既有管线路由耦合。

## 6. glTF 导入层：消费 alphaMode

`GLTFLoader.cpp::AppendGLTFMaterial`（GLTFLoader.cpp:149）补齐三处：

| 数据 | 来源 | 落到 |
|---|---|---|
| `baseColorFactor[3]`（alpha） | `pbr.baseColorFactor[3]`（double） | 材质基础 alpha × tint alpha 的因子（存浮点参数 `"baseAlpha"` 或经 shader 端 `inColor.a`） |
| `alphaMode` | `mat.alphaMode`（string，"OPAQUE"/"MASK"/"BLEND"） | `Material::alphaMode` |
| `alphaCutoff` | `mat.alphaCutoff`（double，默认 0.5） | `Material::alphaCutoff` → 写 `MaterialUBO.params.z` |
| `doubleSided` | `mat.doubleSided` | `Material::doubleSided`（阶段2 连同背面剔除动态状态一起接线） |

注意 `AppendGLTFMaterial` 目前产出的是 `MaterialData`（OBJ 语义，走 MeshManager 缓存）。需确认 MeshManager 在 `MaterialData → Material` 的转换点补上这三个字段的透传。tinygltf 已解析好这些值（tiny_gltf.h:757），只差搬运。

## 7. 边界与已知限制

| 项 | 说明 | 处理 |
|---|---|---|
| **透明↔透明自相交** | 排序只按物体平移距离（`viewPos.z`），大物体/相交时 artefact | v1 接受（glTF 查看器同款）。后续可改按 Mesh 包围球中心距离提升精度 |
| **同材质同 mesh 多实例透明** | 逐实例绘制，放弃合批 | 半透明物体少时 draw call 增量可忽略；见 §5.2 |
| **MASK 禁用 early-z** | `discard` 使片元必进 PS | 仅影响 MASK 物，可接受 |
| **共面半透明（贴纸/反光层）** | 深度 `Less` 下共面片元丢失 | 已知限制，属标准行为 |
| **颜色空间** | 混合在**线性空间**进行（PBR 数学前提），结果经 ACES + swapchain sRGB | 正确，无额外处理 |
| **OIT / 折射** | 玻璃折射、大量半透明排序 | **未来**（见 §10 预留） |
| **透明物体不在不透明之上叠二遍光照** | 透明材质仍跑完整光照（含 IBL），只是混合输出 | 符合预期；恒定 alpha 材质可接受 |

## 9. 验收标准

- `DrawMesh(transform, mesh, Blend材质, {r,g,b,a<1})` 渲染出半透明，透过可见背后的不透明物体与天空盒
- 多个 Blend 物体从远到近正确混合；同屏 Mix 不透明 + MASK + Blend 顺序无错乱
- Blend 物体**不写深度**，Opaque/Mask 物体**写深度**（以远处 Blend 玻璃不被近处不透明墙面"穿帮"为观感标准）
- glTF 导入的 `alphaMode=MASK`（`alphaCutoff` 生效裁剪）与 `BLEND`（半透明）材质行为符合 glTF 规范
- 不透明渲染路径与现状逐帧等价（无回归：批次、深度、早退逻辑不变，仅新增透明段）

---

## 10. 未来预留（本方案不做）

- **OIT**：如需大量半透明或自相交场景，v1 的 back-to-front 排序必然到极限。预留两条路：
  1. 加权混合 OIT（Filament 式，单 pass、兼容 MSAA 差，质量中）；
  2. per-pixel linked list（需要 atomic counter + 大 pool 缓冲，双 pass，质量高、改 renderer 深）。
  两者的缓冲与排序都不挤压 v1 的接口，可增量替换透明段。
- **折射**：半透明玻璃折射需额外渲染到纹理再扭曲采样，属 PostProcess 范畴，独立立项。
