# 动画物理事件脚本桥接计划书（约定命名钩子 · 不建中央事件总线）

> 状态：**计划中（未开工）**。前置已完成：Lua 脚本系统（阶段 A~C）落地，`ScriptEngine` 的 `CallHook` 约定钩子机制（实例表 metatable → 行为表 + 错误隔离 + 限频禁用）已就绪；`AnimationComponent`/`ClipInstance`（Components.h:409/402）、`PhysicsWorld`（固定 60Hz 步进 + 待创建列表）、`ScriptComponent` 收敛为纯数据（`{ScriptPath, Enabled, PublicFields}`）。
> 目标：把「动画事件（时间轴数据）与物理事件（接触发现）如何到达脚本」这一层定下来——**不新建、不挪用任何"事件系统"**，引擎触发各自内聚在 `UpdateAnimations`/`StepPhysics`，脚本侧统一用**约定命名函数**接收（写了即订阅，没写即跳过），与大厂共同做法（Unity `OnCollisionEnter`、UE `OnActorBeginOverlap`、Godot `body_entered` 信号）一致。
> 定位：纯场景层/脚本层衔接；**改动现有 `GE/Events` 那套窗口/输入事件系统、渲染层、着色器、`.geanim` 格式零改动**。阶段 A/B 各自独立可回退，可并行、可分两次 PR。

---

## 0. 一句话架构

```
UpdateAnimations（FireEvents 区间检测）──► 按实体 DispatchAnimationEvent ──► ScriptEngine 约定钩子 OnAnimationEvent
StepPhysics（接触缓冲消费）────────────► 按实体双侧 DispatchCollisionEvent ─► ScriptEngine 约定钩子 OnCollision/OnTrigger*
```

`ScriptEngine` 是唯一的脚本侧接收口：钩子**写了即注册、没写即跳过**，与 `OnUpdate` 同一套机制。不存在中央事件总线，不做跨实体广播、不做动态订阅。

## 1. 问题辨析：三种"事件"不是一回事

| | 现有 `GE/Events`（Events/Event.h） | 动画事件 | 物理事件 |
|---|---|---|---|
| 触发源 | GLFW 平台 | 时间推进跨过 `e.time` | Jolt ContactListener |
| 数据归属 | 瞬时对象，即分即弃 | `ClipInstance.events`（场景数据，序列化） | 物理步进内环形缓冲 |
| 消费方 | Application/Layer（引擎基础设施） | 该实体的脚本 | 接触两侧实体的脚本 |
| 签名 | 单事件对象按 EventType 分发 | `(entity, eventName)` | `(entity, otherTag, up, normal)` 双侧 |
| 语义 | 窗口/键鼠，全引擎一次 | 确定性边沿（每播一遍序列相同） | 无序边沿（模拟发现） |

**结论**：现有 `GE/Events` 是**窗口/输入基础设施**，与玩法事件不相干，**不碰**；动画事件与物理事件触发语义也不同，各自内聚在自己的更新链路。两者唯一的共同点是**最终都流向脚本**——所以只统一"接收端"，不统一"触发端"。

**为什么不建通用事件总线**：总线是给"玩法↔玩法"（脚本间通信）用的，不是给"引擎系统→脚本"送达用的；后者用固定命名钩子即可，免去总线带来的订阅管理/泄漏/乱序成本。脚本间消息需求在 Lua 计划 D-3，延续，不做。

## 2. 总体设计：脚本侧统一钩子契约

### 2.1 钩子约定（写了即订阅）

在所有现有 Lua 行为钩子（`OnCreate/OnUpdate/OnDestroy`）之外，新增如下**可选**钩子：

| 钩子 | 参数 | 说明 |
|---|---|---|
| `OnAnimationEvent(self, name)` | `name` = 事件名 | 动画事件（跨过时间轴事件点时调用） |
| `OnCollisionEnter(self, otherTag, impulse, nx, ny, nz)` | 对端 Tag、法向冲量、法线(向 self) | 普通碰撞进入 |
| `OnCollisionStay(self, otherTag)` | 对端 Tag | 高频；**写了才启用 Stay 通道**（见阶段 B4） |
| `OnCollisionExit(self, otherTag)` | 对端 Tag | 普通碰撞离开 |
| `OnTriggerEnter/Stay/Exit(self, otherTag)` | 对端 Tag | 传感器事件（`IsSensor` 体） |

规则与 `OnUpdate` 完全一致：**行为表里写了这个函数 = 订阅；没写 = 引擎直接跳过**。不需要任何 `set_callback()`/注册 API。钩子内报错走既有隔离（`sol::protected_function` + 日志 + `lastError`），但**不累计限频禁用计数**（限频只针对 `OnUpdate` 的运行循环——事件是边沿、无循环语义，见决策 7.4）。

示例 `footstep.lua`：

```lua
function M.OnAnimationEvent(self, name)
    if name == "footstep" then
        log.info("脚步落地")
    end
end

function M.OnCollisionEnter(self, otherTag, impulse, nx, ny, nz)
    log.info(string.format("撞到 %s，冲量 %.2f", otherTag, impulse))
end
```

### 2.2 ScriptEngine 扩展（唯一接收口）

`ScriptEngine` 新增两个公开方法（**头文件仍不引 sol**，参数全部是纯数据，解析在 `Impl` 内完成）：

```cpp
/// 动画事件派发：FireEvents 命中后调。实体无脚本/未启用 → 空操作。
void DispatchAnimationEvent(entt::entity entity, const std::string &eventName);

/// 物理事件派发：StepPhysics 消费缓冲后对**该侧**实体调一次（参数已按侧算好）。
void DispatchCollisionEvent(entt::entity entity,
                            const std::string &otherTag, bool isTrigger,
                            enum class CollisionPhase phase, /* Enter/Stay/Exit */
                            float impulse, float nx, float ny, float nz);
```

内部实现复用既有 `CallHook`：查 `m_Impl->instances[entity]` → 按类型数拼钩子名 → `CallHook` 逐参调用。**不留全局事件队列、不做缓存**——事件到达即派发即弃，天然免疫"漏处理"与"重复处理"。

派生关系：动画/物理的检测逻辑（见 §3/§4）调用这两个方法，**不直接**接触 `sol`、不感知 Lua。

### 2.3 时序：本帧事件"后到"

`Scene::OnUpdate3D` 现状（Scene.cpp:505）顺序：

```
BeginFrameInput → UpdateScripts → StepPhysics → UpdateAnimations → UpdateWorldTransforms
```

脚本 `OnUpdate` **先跑**，物理/动画事件在**同一帧的稍后**派发。语义：

- 脚本先读输入、改本地 TRS（`mover.lua` 等不受影响）；
- 第 N 帧碰到的碰撞、跨过的事件点 → 第 N 帧 `OnCollisionEnter`/`OnAnimationEvent` 即被调用；
- 钩子内改的状态（血量、位置等）经第 N 帧稍后的 `UpdateWorldTransforms` 与下一帧世界更新生效——**同帧可读新数据，无需等下一帧**。这与 Unity `FixedUpdate → OnCollisionEnter → Update` 的"碰撞在物理步后送达"语义一致。

**关键防线**：`Playing=false` 的动画不推进时间（`UpdateAnimations` 只在 `ac.playing` 时 `ac.time += …`），Scrubber 只改 `ac.time`，下次推进的 `prev` 读改后值 → 不产生跨越区间 → **不误触发**；物理 `Step` 只在运行时推进（编辑器 Edit 态不步进，见物理计划阶段 C）→ 编辑态无碰撞事件。天然免疫，无需额外状态。

### 2.4 无脚本 / 无钩子的回落

- 实体无 `ScriptComponent` 或未启用 → 事件**静默丢弃**（可 `GE_CORE_TRACE` 一条用于调试，计划阶段默认 TRACE 可关）。
- 一方实体有脚本、另一方没有 → 有脚本的一侧照常收到。
- 两侧都没有 → 事件无人消费，缓冲停在同一帧，零副作用。

## 3. 阶段 A：动画事件 → 脚本钩子

**目标**：`ClipInstance` 带事件表，播到 `e.time` 触发对应实体的 `OnAnimationEvent`；可编辑、可序列化、loop 回绕不重不漏。检测细节复用`动画系统增强计划书.md §2.2/阶段 B`，**仅把该计划的"`AnimationComponent.eventCallback` std::function 派发"替换为本计划的 `DispatchAnimationEvent`（§5 交代取代关系）**。

### A1. 数据结构（Components.h）

```cpp
struct AnimationEvent {
    float       time = 0.0f;  ///< 秒，相对 clip 起点
    std::string name;         ///< 事件名（脚本按名分派）
};

struct ClipInstance {
    std::shared_ptr<AnimationClip> clip;
    std::vector<entt::entity>      channelTargets;
    std::vector<uint32_t>          keyHints;     ///< 既有
    std::vector<AnimationEvent>    events;       ///< 场景级事件表（序列化）
};
```

事件表挂 `ClipInstance`（每实例，非共享 clip）——事件是玩法/场景数据，glTF 不携带；多实例各播各的事件轴。**组件内不加 `std::function`**。

### A2. 检测（Scene.cpp UpdateAnimations 扩展）

```cpp
const float prev = ac.time;                  // 推进前记录
ac.time += ts.GetSeconds() * ac.speed;
// …既有回绕/钳制（loop 回绕拆两段：先扫 (prev, dur] 再扫 [0, cur]）
if (ac.playing) {
    for (auto &e : events) if (prev < e.time && e.time <= cur)
        m_ScriptEngine.DispatchAnimationEvent(entity, e.name);
}
```

负速 `prev > cur` 且非回绕 → 不触发（v1 语义，与动画计划决策 9.9 一致）。

### A3. 派发 → ScriptEngine

直接调 `DispatchAnimationEvent`（§2.2）。无脚本实体 → 内部空操作。

### A4. 序列化（SceneSerializer.cpp）

`clipNode` 增 `Events: [{ Time, Name }, …]`；反序列化缺省空（旧场景文件照常）。`keyHints` 是运行时态，不序列化（既有）。

### A5. 编辑器（SceneHierarchyPanel DrawAnimationComponent）

事件表编辑：每行"时间输入 + 名字输入 + 删除按钮"，底部"添加事件"。时间浮点编辑 + 可选拖动，不派发（编辑器不触发事件，仅编辑数据）。

### 退出标准

- mint 动画若干时间点放事件，播一遍 `OnAnimationEvent` **次数与时间**精确；loop 回绕处不重不漏。
- Scrubber 拖动、`playing=false`、clip 硬切期间不触发；负速不触发。
- 无脚本实体不崩、事件静默丢弃；保存→加载事件表保留。

## 4. 阶段 B：物理事件 → 脚本钩子

**目标**：Jolt 接触/传感器事件在步进后按实体双侧派发 `OnCollision*`/`OnTrigger*`。检测与缓冲细节复用`物理系统增强计划书.md §3/阶段 A`，**把该计划 §3.3 "`ScriptComponent` 加四个 std::function" 替换为本计划的 `DispatchCollisionEvent`（§5 交代）**。

### B1. Body ↔ 实体映射（前置）

创建 body 写 userdata（`ProcessPendingBodies`）→ `GetEntityFromBody/GetBodyFromEntity` 反向查询。命中后分发一律 `reg.valid` 兜底（防缓冲存续期内实体销毁，物理计划风险 3）。

### B2. ContactListener → 环形缓冲

`EngineContactListener` 四回调（Added/Persisted/Removed）内**只写原始缓冲**（`std::array<RawContactEvent,N>` 环形），不碰 ECS、不回调脚本（同步步进约束，物理计划 §0）。

### B3. StepPhysics 尾部分发

`Scene::StepPhysics`（Scene.cpp:552）在 `m_PhysicsWorld->Step(ts)` 后消费缓冲，对事件里 **A、B 两侧分别**调（**双侧投递**，否则对端收不到自己视角）：

```cpp
void Scene::DispatchCollisionEvents();   // StepPhysics 尾部
// 每条: sideA 有脚本 → DispatchCollisionEvent(A, tagB, isTrigger, phase, impulse, normal)
//       sideB 有脚本 → DispatchCollisionEvent(B, tagA, isTrigger, phase, impulse, -normal)
```

`-normal`：法线依约定指向接收侧实体（物理计划 §3.3 已定义）。`IsTrigger` 区分走 `OnTrigger*` 还是 `OnCollision*`。

### B4. Stay 通道按需启用

`OnContactPersisted` 逐对**只更新"最近帧仍在接触"标记，不排队**；初版只派发 Enter/Exit 两态。**当某对实体的脚本写了 `OnCollisionStay`（或 `OnTriggerStay`）时**才对该对合入 Stay——"写了即订阅"恰好天然承载"Stay 高频按需"的开关，无需额外配置或注册。

（实现提示：ScriptEngine 可在派发前查询该实体实例行为表是否含 `OnCollisionStay`，为 true 才让 Scene/PhysicsWorld 开启该对的 Stay 聚合，避免每帧几十万事件。）

### B5. 派发参数成形

进入 Event→Lua 前把参数定格为纯数据：`otherTag` 取对端实体的 `TagComponent.Tag`（`entity` 句柄属 Lua 计划 D-3，届时签名升级为实体句柄，同一位置向后兼容）。`impulse/normal` 仅 Enter 提供（Exit 语义只有离开，冲量无意义；Trigger 无冲量）。

### 退出标准

- sandbox 脚本：注册 `OnCollisionEnter/OnTriggerEnter`，动态球砸传感器球，日志 Enter/Exit 序列正确、冲量非零；**双侧**都收到且法线各自朝向自己。
- 只一方有脚本 → 只一侧触发；无脚本实体不崩。
- 写 `OnCollisionStay` 后才收到 Stay 更新；没写则无 Stay 开销。
- 回归：2.scene 刚体摆放行为不变（无脚本时缓冲消耗为零）。

## 5. 与既有文档的关系（取代两处旧设计）

| 旧设计 | 出处 | 取代方案 |
|---|---|---|
| `AnimationComponent.eventCallback`（std::function，运行时句柄） | 动画系统增强计划书 §2.2/阶段 B | **删除该字段**，改 `DispatchAnimationEvent` 直连 ScriptEngine（脚本侧是约定钩子而非手搓闭包；组件保持纯数据） |
| `ScriptComponent` 上四个 `OnCollision*` 回调（std::function） | 物理系统增强计划书 §3.3 | **不往组件塞函数**，改 `DispatchCollisionEvent` 直连 ScriptEngine（`ScriptComponent` 已收敛为 `{ScriptPath, Enabled, PublicFields}`） |

原因同一：`ScriptComponent` 已被 Lua 化收敛为纯数据，运行态归 `ScriptEngine`；任何"组件持有可序列化无关的 std::function"都是旧架构残留。`ClipInstance.events` 是**数据**（时间+名字），留在组件合理；回调**逻辑**全收进 `ScriptEngine`。

其余既有链路（`GE/Events` 窗口/输入系统、输入快照、`.geanim` 烘焙、渲染）全部不动。

## 6. 明确不做（路由图外）

- **中央事件总线 / 跨实体广播 / 脚本间消息**：玩法↔玩法通信，属 Lua 计划 D-3（"角色死 → 队友 AI 收到通知"），等需求出现再设计，公共 `entity` 句柄是它的前置。本计划只解决"引擎系统 → 脚本"单向送达。
- **动画事件进 `GE/Events`**：不往 `EventType` 加 `AnimationEvent`/`CollisionEvent`，不碰 `EventDispatcher`。
- **物理事件查询式替代**：不把碰撞做成 `OverlapSphere` 轮询差分（粒子等用查询接口另做，见物理计划 §3.4）；接触事件走 Listener 事件化。
- **事件携带任意 payload**：v1 动画只有 `name`、物理只有 tag/冲量/法线。将来要"事件带参数表"（如音量、受击数值）再为 `AnimationEvent` 扩充字段，不为此造通用机制。

## 7. 决策记录（编码前拍板）

**7.1 接收方式 —— ✅ 已定：约定命名钩子（写了即订阅），不建总线**
- 与 `OnUpdate` 同一机制、与大厂一致；免订阅/退订/泄漏/乱序管理。边沿通知到达即派发即弃。

**7.2 触发内聚 —— ✅ 已定：动画检测呆 `UpdateAnimations`、物理检测呆 `StepPhysics`，互不可见**
- 各自的区间语义、缓冲约束不同（物理回调内禁碰 ECS），硬抽共用管道两头别扭。

**7.3 组件零函数 —— ✅ 已定：组件只放数据（`ClipInstance.events`），回调全收 `ScriptEngine`**
- 取代动画计划 `eventCallback` 与物理计划 `ScriptComponent` 回调字段（§5）。

**7.4 事件钩子错误 —— ✅ 已定：复用 protected 隔离 + lastError，但不累计限频禁用**
- 限频计数只对 `OnUpdate`（连续运行循环）；事件是边沿，一次性出错记录 lastError 即可，不触发自动禁用（避免"事件里踩一次坑脚本就永久灰掉"）。

**7.5 时序 —— ✅ 已定：脚本 `OnUpdate` 先跑，物理/动画事件同帧后到**
- 与 Unity `FixedUpdate→OnCollisionEnter→Update` 同构；钩子内可立即读同帧新数据。

**7.6 物理双侧 —— ✅ 已定：A、B 两侧都派发，法线各向自己**
- 否则对端实体收不到自己视角的事件（物理计划 §3.3 同）。

**7.7 Stay 默认关 —— ✅ 已定：无 `OnCollisionStay` 钩子则不聚合 Stay 更新**
- 用"活了就有订阅"承载高频通道开关，零配置。

**7.8 对端标识 v1 —— ✅ 已定：传 Tag 字符串；实体句柄待 Lua D-3 升级**
- v1 不求跨实体交互，够判断"撞的是谁"；签名升级时同一位置传句柄，向后兼容。

**7.9 负速/倒放 —— ✅ 已定：动画负速不触发事件（v1）**
- 从动画计划决策 9.9；避免倒放区间歧义。
